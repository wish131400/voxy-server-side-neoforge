# 2026-10-05：预测覆盖缓存局部失效修复

本次同步更新 Forge 1.20.1 和 NeoForge 1.21.1，针对实际客户端采样发现的秒级帧时间：45 秒 JFR 中，渲染线程 97.8% 的样本包含 `PredictionRenderer.resolveCoverage`；另一段 14 秒观察完成 6 帧，覆盖计算平均每帧 2.23 秒，每帧重算 1,286 个瓦片且覆盖缓存没有命中。修改前的原因是请求状态、网格任务和节点变化共用全局版本，任意局部变化都会使全部瓦片重算。

`StrictLodVisibility` 现在区分请求调度变化与实际接管变化。`workChanged()` 继续通知请求圈的调度检查；上传节点就绪状态、当前渲染服务的网格任务，以及带坐标的摄入任务，仅登记其影响的水平范围。不同渲染服务的任务不会污染当前场景。相同位置的几何更新、重复就绪节点，以及同一节点已处于待处理状态时的再次入队，不会重复改变接管可用性。

`StrictVoxyCoverageChanges` 保存最多 4,096 个去重区域，给渲染场景提供变化增量。`Scene.prepare` 通过现有空间索引找到相交的预测瓦片，仅移除它们的覆盖缓存；相交的父、子层级都会更新。世界、渲染窗口和桥接状态重置，或消费者错过已淘汰的历史时，采用完整失效，以保留撤回和重新显示预测地形的正确行为。

共享列缓存最多保存 65,536 个区块。列版本通过对应区块及五层节点祖先的区域版本计算，远处变化不会清空近处答案。已证明完整覆盖的竖向范围可供重叠瓦片复用；失败范围仅精确复用，不能推导另一个范围也有缺口。互不相邻的成功范围不合并跨越中间缺口。局部变更和历史淘汰都会让可能过期的答案重新检查。

`StrictVoxyNodeIndex.coversRange` 一次跨过整个已上传祖先的竖向跨度，减少对同一节点的重复查询。`StrictVoxyPipeline.idleRange` 只获取一次锁，并按各层独立祖先扫描；没有待处理网格时立即成功。旧上传结果仍不能确认更新序列的任务。

预测瓦片先决定自己的驻留所有权，再查询 Voxy 接管。已被精细子瓦片覆盖的父瓦片不再重复查询同一片真实远景；缺失子瓦片仍显示父级回退，Voxy 撤回后立即恢复相同回退掩码。

针对性回归测试验证了：1,286 个驻留瓦片中，单个区块变化只失效相交父、子瓦片；10,000 次请求调度变化不失效驻留覆盖；1,000 次远处更新保留近处列缓存；重叠瓦片复用完整范围；混合 LOD、负坐标和负高度的范围查询与原先逐 section 结果相同；节点撤回、重复摄入、旧上传序列、完整重置和历史淘汰均保持正确。完整构建还修正了现有 `PredictionScopedResidencyTest` 对缓存恢复私有方法的旧反射参数，使用已有的新建筑参数接口。

跳过项包括需要额外输入的兼容、性能和 GPU 测试。完整运行提供了安装实例中的 Voxy JAR，两个平台的真实 Voxy 字节码接口契约检查均通过。Forge 构建完成 `reobfJar`；JAR 的 Java class major version 分别为 61 和 65，新覆盖辅助类均已包含，未混入测试或 JUnit 类。

两个 JAR 的五份原生资源逐字节一致，每个平台 40 个 JNI 导出，架构、依赖、最低系统版本和 macOS 签名结构检查通过。Forge 原生编译目录的旧中间产物与发布资源不同，因此最终核查的是 JAR 内文件与 `src/main/resources/META-INF/vss-natives` 的一致性；本轮 Java 修复没有重新编译或改动原生库。

用各仓库所需 JDK 运行 `gradlew.bat -I tools/prediction/regression-tests.gradle build --offline --console=plain` 可重新构建。实际运行还以 `-PvssVoxyJar=<本平台已安装的 Voxy JAR>` 启用了接口契约检查。日志、测试汇总和打包校验存放在每个仓库的 `build/coverage-fix-20261005`。打包前的原 JAR 保存在该目录的 `backups` 子目录。

发布文件仍使用现有 0.3.5 版本及文件名。本次只构建仓库中的发布包；游戏内 FPS 尚未安装新包重新测量。运行中的旧客户端不会自动加载新的代码，替换对应平台 JAR 并重新启动后，应在原位置、5,120 方块预测距离和相同视角重新采样，比较覆盖重算计数、查询命中数和帧时间。
