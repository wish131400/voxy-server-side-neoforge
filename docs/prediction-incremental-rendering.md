# 预测渲染主线程增量更新与合并提交评估

日期：2026-09-21。同步目标：NeoForge 1.21.1、Forge 1.20.1，版本与 jar 文件名保持 0.3.1。

## 完成范围

| 原方案 | 本次结果 |
| --- | --- |
| 未变化接缝及外层边界结果一起复用 | 正式路径实现，保留 Patch、包围盒、Draw、覆盖结果及 GPU 资源 |
| 地块变化只更新附近接缝 | 正式路径实现，空间索引查询旧、新范围附近的拥有者 |
| 地块集合、覆盖关系、排序按变化更新 | 正式路径实现，增量场景、可见绘制计划及不可变分段 GPU 快照 |
| 评估跨地块合并提交 | GPU 原型、局部更新正确性验证与计时完成；正式渲染器未启用跨地块合批 |

本次不降低预测精度、不增加生成线程，也不以帧率熔断替代优化。下面的计时是组件测试，不能直接换算成玩家 FPS。

## 正式实现

### 变化记录与空间索引

`PredictionRenderResidency` 记录已上传地块及与其重叠的拥有者变化。四叉树 `PredictionSpatialIndex` 支持插入、删除、半开矩形相交查询与提前结束的存在性查询，支持负坐标及混合 LOD。上传一个地块不再通过遍历整个驻留集合更新覆盖版本。

渲染变化记录和快照发布变化记录独立，消费其中一份不会丢失另一份。维度切换仍交付旧地块删除记录；资源重载、布局变化按实际需要失效。

### 接缝及真实地形交接

`PredictionLodSeams.apply` 接收替换、删除列表，查询变化范围周围的拥有者。先更新全部受影响边界遮罩，再构建这些拥有者的接缝，保证查询邻居时使用同一批边界结果。远处未受影响的补片、包围盒和 Draw 不重新整理。

`PredictionRealBoundarySeams.apply` 按 64 方块单元索引真实边界。真实边界列表没有变化时，只查询地形变化附近的边；真实边界本身变化时重新分组。局部重建保持原边的顺序。

保留全量输入适配方法用于参考结果及测试；生产渲染调用增量接口。

### 持久场景与可见列表

`PredictionRenderer.Scene` 持有地块几何、覆盖结果、地形 Draw、接缝 Draw、统计值和高度范围。局部上传只处理变化地块与相关拥有者。望远镜目标变化只使相关 scoped families 和新旧目标范围失效。

`PredictionVisiblePlan` 维护可见成员及水平距离顺序：

- 场景、相机、矩阵均未变化时，返回同一不可变列表，不遍历场景或重排。
- 原地转动时重新做可见性检查，仍然可见的成员保留距离顺序；可见集合不变时复用输出列表。
- 相机移动时更新距离和可见性；移动会改变地形裁剪和面方向，仍需相应遍历，不能声称这一情况也零成本。
- 局部地块替换且视图不变时，只检查脏成员。

Draw 保存形变是否允许；提交阶段仍按 GPU 上传年龄计算实际形变量，避免复用 Draw 把过渡动画冻结。透明部分保持全局距离反序提交。

### 不可变分段 GPU 快照

`PredictionTileTable` 每个 LOD 使用 32 个哈希页。发布局部变化时复制页引用表和受影响页，不复制整个世界地块表；旧帧仍持有原来的不可变页。地块、覆盖版本、望远镜关联集合均使用分段表，查询直接使用原始坐标索引。

这个优化覆盖渲染驻留/GPU 快照。工作线程发布的 CPU 源快照仍采用已有全量快照路径；CPU 源集合实际变化时，驻留保留判断仍有集合扫描。没有把这些路径计作已消除。

## 验证与测量

`PredictionIncrementalRenderTest` 覆盖空间索引与独立矩形扫描的随机对照、接缝全量参考对照、混合 LOD 删除/替换、真实边界重新归属、可见列表移动/转动、维度退休、分段表不可变性、望远镜关联集合及点查询对照。

两个版本各通过 68 项针对性 CPU 回归，以及包含多场景断言的生产 GPU 集成测试；合并提交原型在两个版本均单独通过。最终 jar 校验了项目 class 集合及逐字节内容：NeoForge 588 个 class 与编译输出一致，Forge 598 个 class 与 reobf 输出一致。两仓库 `git diff --check` 通过。该结果不代表运行了全项目测试套件。

- 1,024 个同级地块中修改一个：更新 9 个附近接缝拥有者，网格与全量重建一致。混合层级或大范围变化影响数量会增加，9 不是固定上限。
- 4,900 个可见计划成员、120 个静止帧：没有新增遍历或顺序编辑。
- 实际 OpenGL 下生产 Scene 连续 120 个稳定帧复用列表；局部上传正确更新地块且保留无关 Draw，重置清理旧资源。测试使用分段驻留快照。
- GPU 回归同时覆盖地形交接、接缝、标准/反向深度、窄 FOV、材质、透明层和 Iris 状态恢复。测试环境并非完整玩家整合包。

8,192 地块、一次局部上传的快照发布微基准：20 次预热、30 次交替测量旧参考路径与分段路径；旧参考构造不可变地块表和完整 RenderSnapshot 索引，未计复制 epoch 表。

| 本机一次运行 | 旧路径中位耗时 | 分段路径中位耗时 | 旧路径分配/次 | 分段路径分配/次 |
| --- | ---: | ---: | ---: | ---: |
| NeoForge / Java 21 | 1.936 ms | 0.025 ms | 417.3 KiB | 19.1 KiB |
| Forge / Java 17 | 2.539 ms | 0.032 ms | 417.4 KiB | 19.2 KiB |

这只测快照发布，不包含完整帧、生成、驱动等待或上传；大范围变化会复制更多页，收益取决于变化分布。

## 跨地块合并提交评估

测试 `PredictionBatchSubmissionGpuTest` 使用独立 OpenGL 3.2 上下文。512 个地块从各自 payload/mask 绑定，改为共享 payload、四边形所属地块索引、地块参数表及 mask 数组，以一次 `glMultiDrawElements` 提交。初始画面及单地块 payload/颜色/mask 更新后逐像素相同。

在 RTX 4070 Ti SUPER、NVIDIA 572.70 上，30 次预热、60 次交替测量：

| 运行 | CPU 独立提交 | CPU 合并提交 | GPU 独立提交 | GPU 合并提交 |
| --- | ---: | ---: | ---: | ---: |
| NeoForge 测试环境 | 0.063 ms | 0.033 ms | 0.015 ms | 0.004 ms |
| Forge 测试环境 | 0.052 ms | 0.022 ms | 0.015 ms | 0.003 ms |

Java 提交次数 512 → 1，相关绑定 1,024 → 4。每个四边形额外需要 4 字节所属地块索引，相对目前 48 字节 payload 增加约 8.3%，尚未计参数表和分配碎片。

结论：技术路径可行，但简化原型 CPU 绝对收益约 0.03 ms/512 地块，不能据此证明改造正式管线的收益。原型只有简化几何及着色，不代表真实地形的材质、形变、Iris 输出、水体排序或完整帧率。因此本次完成评估，正式跨地块合批不启用；已有单地块范围合并提交继续使用。

如果后续实机采样证明 draw 提交成为主要瓶颈，生产实现应采用有上限的共享 payload 页和空闲段回收、所属地块索引、地块描述表、按页组织的 mask 数组。必须保持大坐标下相机原点减法精度、形变/接缝标志/材质/Iris 输出，以及透明层全局从远到近顺序（只合并兼容的连续段）。迁移与碎片整理必须遵守上传预算，避免同时驻留两份完整 GPU 世界。

## 产物与实机验证边界

两个仓库都输出原有文件名：`lib/vss-0.3.1-neoforge-1.21.1.jar`、`lib/vss-0.3.1-forge-1.20.1.jar`。本轮不热替换正在运行的游戏。需要退出游戏、使用新 jar 重启后，才能对比同一位置转动视角的 PREPARE、COVERAGE、SEAMS、提交耗时与帧时间。本轮未测新版游戏 FPS，不承诺固定帧率提升比例。
