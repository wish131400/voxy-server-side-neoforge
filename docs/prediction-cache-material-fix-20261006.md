# 预测 LOD 灰色植被与进档缓存 I/O 修复

日期：2026-10-06。代码同步至 NeoForge 1.21.1 与 Forge 1.20.1 项目。

## 现场结论与证据

本轮采样来自修复前客户端。用户观察到进档磁盘峰值超过 170 MB/s。120 秒 JFR 记录显示，预测缓存整理线程读取 1,114,455,863 字节、写入 1,109,813,799 字节；14:17:05 这一秒全部已记录 Java 文件读取约 121.6 MB、写入约 121.9 MB。JFR 统计的是 Java 逻辑文件 I/O，不能与任务管理器的物理磁盘吞吐直接等同。

整理原本在提交线程短暂空闲时就可启动，没有足够长的空闲窗口或复制限速。进档不断重建和写入缓存时，整理复制完的区域可能已变化，临时副本被放弃，再次尝试又会重新复制。记录里同一批区域出现多次大体积临时整理文件。这是可直接避免的 I/O 放大。

同一记录还包括预测工作线程读取约 490 MB、材质资源身份扫描读取约 224 MB、预测磁盘线程读取约 219 MB 和写入约 206 MB，以及成品网格写入约 197 MB。因此整理修复不等于消除所有进档 I/O。资源身份扫描在本次客户端中正常完成，并未因扫描上限而永久失效。

材质现场审计确认 GPU 材质表已满 254 个槽位；403 个顶面方块映射中有 349 个走回退，包括 Biomes O' Plenty 冷杉、红杉的树叶和树干，以及部分原版树木。旧路径在槽位不足时拿不到平均颜色，最终使用灰色默认值，解释了截图中已经生成却呈灰色的树林。

另一个独立问题是城市整平后的显示样本被当作原始地形样本复用。缓存瓦片 (-5312, -5376)、LOD 0 中，周围显示高度约 107～109，但交错的“精确”样本为 90 或 96。这会产生棋盘状高度差和异常立面，不应与所有灰色植被混为一谈。

## 实现

- `PredictionDiskCache`：至少连续空闲 15 秒且相关任务队列、活动任务满足空闲条件，才允许整理。前台缓存需求会重置空闲时间。
- `PredictionRegionStorage`：整理复制限速 8 MiB/s；读写合计约 16 MiB/s 的逻辑吞吐，不是整个客户端的 I/O 上限。复制分块检查前台活动，恢复加载时中止、清理临时文件并重新排队；保留原有原子发布、版本和引用检查。
- `PredictionTileManager`：仅缓存恢复任务在材质资源身份尚未就绪时，先延后重试，再进入磁盘读取，避免重复读取和解压地形。
- `VssLodSpriteTable`：CPU 保存纹理平均颜色，不再依赖 GPU 槽位分配成功；溢出材质保留平均颜色和叶片染色。读取成品网格遇到槽位不足时，使用已有烘焙颜色安全恢复，避免因此报错重建。资源重载会清理平均色缓存。
- `ClientColumnSample`、`PredictionCityGeometry`：标记城市显示地面样本，并禁止其作为原始地形复用。兼容识别旧版特征明确的污染样本。
- `PredictionDiskCache`：只拒绝、重建检测到上述污染的地形记录，并移除阻碍较小干净记录覆盖的旧精细度限制；禁止将城市显示样本重新写入原始地形缓存。
- `PredictionMeshCodec`：网格签名版本更新到 10，二进制记录格式仍为 9，并兼容读取旧记录格式。使旧错误颜色的成品网格失效一次；平面颜色回退正确转换为 GPU 材质行号。

## 尚未现场验证与剩余限制

- 新包的实景颜色、进档耗时和物理磁盘峰值尚未复测，不能把测试通过当作现场性能改善幅度。
- 首次使用新包会因网格签名更新重建旧成品网格；原始地形和装饰缓存一般保留，仅对识别出的地形污染记录选择性修复。
- GPU 材质容量仍为 254。超出部分保留正确平均色，但不具有完整纹理细节；扩展材质编号需要另行修改打包和着色器链路。
- 现场成品网格身份审计仍有城市签名不匹配，尚未完全解释。因此不能宣称所有重复重建和暖缓存加载缓慢均已解决。
- 采样期间旧客户端曾因 Lost Cities `TimedCache.cleanup` 并发修改异常退出。该异常与本轮 I/O、材质修复分别处理；本报告不将其他对话的兼容修改作为本轮已经验证的崩溃修复。
