# 2026-10-05：连续移动时的预测渲染性能修复

本次同步修改 Forge 1.20.1 和 NeoForge 1.21.1，处理上一轮修复后继续采样发现的四处开销。诊断来自 NeoForge 客户端 PID 37732，Voxy 0.2.15-beta，预测距离 5,120 方块、精细距离 1,536 方块；用户已从暂停菜单返回游戏并持续移动。

61.30 秒移动计数中，客户端完成 2,257 帧，平均 36.82 FPS，覆盖计算平均 15.64 ms/帧。最差 2.012 秒窗口只完成 5 帧，约 2.48 FPS，平均每帧重算 1,184 个瓦片，覆盖计算 333.49 ms/帧，列查询命中率 0.88%。移动 JFR 中 74.39% 的渲染线程样本经过 `resolveCoverage`，最差窗口为 96.12%。这是修复前的数据；暂停菜单限帧没有计入这组结论。

## 修复行为

相机跨区块移动时，`StrictLodVisibility.updateRenderWindow` 登记旧、新窗口的移动增量。`Scene.invalidateVoxyCoverage` 用空间索引和保守圆形边缘分类，只移除可能改变 Voxy 接管状态的瓦片掩码。窗口内部和外部的稳定掩码继续复用，上传节点的列查询不因移动而清空。渲染距离、维度、世界或桥接状态变化仍完整重置。移动历史被消费者错过时，场景采用保守完整失效。

局部节点版本使用六层有界、单调的哈希桶时间戳，不依赖 4,096 条区域历史的淘汰。时间戳桶碰撞只会使少量无关列额外检查，不能保留过期答案；场景仍通过历史淘汰检测漏读的区域变化。每层 65,536 个 `long`，总存储约 3 MiB。

`PredictionTileTable` 使用混合哈希的高 32 位选页，页内哈希表继续用低位选槽。两种选择不再共用同一组低位。`PredictionCoverageOwners` 按不可变渲染快照、区块坐标和目标 LOD 共享所有权查询，也缓存缺失答案。快照替换时清空旧答案，总量限制为 262,144 项。

`StrictVoxyCoverageCache` 从 65,536 列扩大到 262,144 列，改用原始类型数组和每组最多四槽的 clock 替换。替换复用固定槽位，避免逐列分配对象、全局 LRU 链移动和哈希删除搬移。成功竖向范围只在相邻或重叠时合并，失败范围仅精确复用；节点撤回、任务入队或本地摄入立即更新对应时间戳。

`PredictionDiskCache.drainInvalidations` 将键按区域交给 `PredictionRegionStorage.deleteAll`。每批只枚举已有目录，跳过不存在的设置变体和文件；同一区域的删除标记先集中写入并执行一次 force，再删除旧格式文件。已有删除标记继续遮蔽重新出现的旧文件。并发写入若创建新区域，批量删除取得该区域的锁后刷新目录清单；删除或 force 失败时保留内存中的失效标记。目录不存在的结论只用于当前批次。

## 验证和限制

两个平台各 68 项针对性测试通过，涵盖负坐标、边缘进入与离开、窗口传送、节点撤回、槽位复用、历史淘汰、目录重新出现、删除标记持久性和并发创建区域。新的所有权查询与快照直接查询逐项比对，快照替换后不会返回旧所有者。

JDK 17 和 JDK 21 下，预热后的 200,000 次连续列缓存替换均实测为 0 字节线程分配。一个 3,200 键的缺失变体批次最多枚举两次目录，不创建空区域；同一区域内 13 个记录的批量失效只执行一次 force。上述结果验证指定路径的行为，不代表整个渲染流程零分配。

已捕获的 1,945 个快照键原先平均成功查找探测 7.40 次，P95 为 16；使用高位分页离线重建后平均 2.27 次，P95 为 5。回归测试中另一个 1,599 键网格平均为 2.12 次。离线重建会改变页容量和插入顺序，这些数字不等于游戏内 FPS 提升。

原始采样、JFR 和表快照保存在 NeoForge 仓库的 `tmp/client-fps-20261005-37732-080816`。本轮两个仓库的构建日志、测试汇总、打包审计和修改前源码/JAR 备份保存在各自 `build/movement-fix-20261005`。

新 JAR 保持 0.3.5 版本和既有文件名。需要替换对应平台的 JAR 并重新启动客户端后，在相同位置、预测距离和移动条件下重新采样，才能确认新的 FPS 和帧时间。
