# 距离带、地形屏幕 LOD 与独立植物绘制范围（2026-10-12）

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

本轮按“先统计 → 地形显示 LOD → 内容保护 → 实际缩小 MDI 范围”推进。NeoForge 1.21.1 与 Forge 1.20.1 同步实现。更深 Cluster 和 Mesh Shader 留待这条路径在实际游戏中稳定后再评估。本轮没有提交、推送 GitHub，也没有启动 Minecraft 或替换客户端包。

## 实现

### 距离带统计能区分几何选择与归属过滤

`PredictionRenderer.PreparedPass` 按相机到瓦片的最近水平距离记录四个距离带：`0–256`、`256–512`、`512–1024`、`1024+` 方块。`distanceBands` 中四组数组依次表示：原始候选 → 仅选择地形表示 → 再选择陆地植物/水草 → Voxy 归属过滤后。每组数组均按以上四个距离带排列。

每次绘制范围改变立即刷新；范围缓存命中且相机移动时，最多每秒刷新一次。使用已有条目计数，不重新扫描四边形，不重建 MDI 计划。辅助字段包括 `sourceCandidates`、`terrainCandidates`、`displayCandidates`、`afterVoxyCandidates`、`vegetationExcludedQuads`。这些是本帧可见计划的候选面数，**不是 Hi-Z 之后最终通过的面数，也不是全部驻留几何数量**。最终 MDI 候选及 Hi-Z 统计仍使用原有 `mdiCandidateQuads`、`sampleAfterHizQuads` 等字段。

### 地形的显示误差跟随现有细节设置

原先所有 `predictionDetail` 档位对已上传地形都固定使用 1.5 像素误差。本轮把该预算与现有档位关联：

| predictionDetail | 最大投影位移误差 | 进入更粗表示的阈值 |
|---|---:|---:|
| low | 3 px | 2.4 px |
| normal | 2 px | 1.6 px |
| high | 1.5 px | 1.2 px |
| extreme | 1 px | 0.8 px |

退出使用上限、进入使用上限的 80%，继续使用原有滞回。配置改变、完整细节半径改变，即使相机静止也会重选；仅当范围实际改变时才更新对应提交条目。**默认 normal 是明确的画质/性能取舍：远处允许的误差由 1.5 px 放宽到 2 px。** high 保持旧显示预算，extreme 更严格。植物选择不修改地形的实测位移误差。

### 按内容保护，而不是对所有 feature 统一删面

| 内容 | 处理规则 |
|---|---|
| 地形主体 | 选择已经构建并测量过误差的表示；外圈、邻近水体/特殊模型的受保护区域仍精确；有效陡坡不能按零 XZ 面积删除。 |
| 草、蕨、花等简单植物 | 必须是确认的植被材质、FEATURE、UNSHADED，且不是 MODEL_UV、流体或 preview；按 X/Z 稳定选整柱，保留上下部分和两面。 |
| 树叶、树冠 | 不使用植物删柱；继续已有的几何合并，保留树冠形状及透明纹理语义。 |
| 水草 | 与陆地植物使用不同区段和选择档位；共享非植被材质保守保留。 |
| 水面 | 不受植物密度影响，维持原水体几何及透明排序。 |
| 建筑、自定义模型、未知装饰 | 不进入植物删减；已有精确共面合并可以继续，未知特征不做坐标近似。 |
| 接缝、混合父子归属、morph、近处、望远镜 | 接缝保持精确；新地形/陆地植物选择在这些条件下退回完整表示。水草沿用已有独立安全路径。 |

`VssLodSpriteTable` 扫描 block/state/face/model 的材质归属并缓存不可变植被分类。仅保存代表 block 会遗漏共享材质；当 row 同时被非植被使用时禁用植物优化。暖缓存恢复保留植被类别，注册新贴图或新增类别使分类快照失效。Forge 的 `Blocks.GRASS`、NeoForge 的 `Blocks.SHORT_GRASS` 及材质 API 差异分别保留。

### 低细节实际缩小提交范围

新 `PredictionVegetationRanges` 在工作线程内对各不透明面组建立连续的精确内容、陆地植物、水草区段。每个植物区段按稳定空间选择构成前缀，改变细节档位只取更短范围。canonical 与已有地形 variant 中所有原记录完整保留，**植物选择不追加几何副本**。地形、植物、水草分别选择；范围共同交给原 ownership、MDI、直绘路径。GPU pass-local 偏移仍由原 `gpuFirst` 统一换算。

因此，低 LOD 减少的是 MDI 命令中的索引数量/范围，不是在 fragment shader 执行以后把像素藏起来。命令条数由实际范围数量决定，**不保证与面数同比下降**。CPU/磁盘保留源数据，暖恢复重新建立范围；版本检查与现有局部提交缓存继续使用。

### 生产 shader / MDI 的独立 GPU 对照

RTX 4070 Ti SUPER，OpenGL 4.6，NVIDIA 572.70。256×256 隐藏测试窗口，24 轮预热、81 轮交替 A/B，重复同一网格 64 次；报告中位数。植物样本使用可恢复为草的非标准贴图 row，覆盖原来仅按原版贴图名称识别不到的情况。地形样本使用阶梯地表，误差位于旧/新进入阈值之间。

| 平台/样本 | 实际 MDI 面数 | MDI 命令条数 | GPU 顶点阶段 | GPU 完整光栅 |
|---|---:|---:|---:|---:|
| NeoForge 植物 | 2,097,152 → 524,288 | 64 → 128 | 约 0.361 → 0.093 ms | 约 4.948 → 1.320 ms |
| Forge 植物 | 2,097,152 → 524,288 | 64 → 128 | 0.361 → 0.093 ms | 4.965 → 1.321 ms |
| NeoForge 地形 | 1,048,576 → 68,608 | 64 → 64 | 0.193 → 0.018 ms | 1.275 → 0.151 ms |
| Forge 地形 | 1,048,576 → 68,608 | 64 → 64 | 0.193 → 0.017 ms | 1.277 → 0.151 ms |

植物面数减少 75%，地形样本减少 93.46%。植物由两个方向面组形成两个前缀，命令条数从 64 增至 128，仍有明确 GPU 正收益。CPU 提交差异很小，没有稳定、明显的 CPU 收益承诺。每个档位的直绘与 MDI 颜色逐像素一致；不同细节档位本来就允许几何/植物密度不同，不要求跨档位画面完全一致。

**这些数字证明范围确实进入生产命令、可以减少 GPU 工作，不能换算为实际存档 FPS，也不能将重复样本的减面比例推广到整个存档。** 本轮没有换包后的实时游戏 FPS 测量。

## 撤回的方案

曾给整块 display tier 叠加植物抽稀误差，并追加植物显示副本。历史语料在假设 2,048 / 4,096 方块深度多提交约 2.11% / 4.03% 面，原始几何存储增加约 12.7 MiB。该方案已从两个仓库生产代码撤回。实验快照与数据在 `tools/prediction/vegetation-lod-experiments/rejected-coupled-display/`；它们只用于复现和审查，不进入 JAR。

## 检查与产物

独立 Gradle 任务在 `tools/prediction/vegetation-lod-tests.gradle`：

- `vegetationLodRegressionTest`：归属撤销、暖缓存、接缝、网格编码、材料共享、植物整株、静止配置变化、距离带跨越及静态提交缓存。
- `vegetationLodGpuTest`：生产 MDI/直绘、compact 编码、水面/特征交接、当前帧 Hi-Z、实际 Voxy JAR 深度约定，以及植物/地形 A/B。

原始计数、A/B CSV、回归数量与 JAR SHA256 见同名 JSON 报告；测试输出位于 `build-vegetation-lod-20261012/`。两个平台的 GPU 测试顺序执行，未与 Minecraft 争用显卡。

交付：`lib/vegetation-lod-20261012/vss-0.3.5-neoforge-1.21.1.jar`、`lib/vegetation-lod-20261012/vss-0.3.5-forge-1.20.1.jar`。Forge 使用 Java 17 并 reobf，NeoForge 使用 Java 21。JAR 必须通过 ZIP、生产 class 版本、测试类排除、native 文件哈希检查。
