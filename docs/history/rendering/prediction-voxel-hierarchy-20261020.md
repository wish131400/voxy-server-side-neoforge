# VSS 体素显示层与合并重构验证（2026-10-20）

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

本轮将 Voxy 的“体素父层 → 邻面消隐 → 二维扫描合并 → 常驻表示选择”思路接到现有 VSS 渲染系统。两个平台保持 0.3.5。该实现已构建测试包，尚未替换玩家实例，也没有测量实际客户端 FPS。

## 实现边界

输入来自预测已经生成的不可变 packed 表面，不是实际 Minecraft 世界的完整 block-state 体积。后台将适合处理的树冠、树干、轴对齐建筑表面重建为稀疏的一方块表面体素，逐级构造 2/4/8 方块父格；不透明材料优先，材料选择取稳定来源，不平均材质编号。去掉被邻居挡住的面，再调用现有扫描线矩形合并器。

只把通过成本、误差与驻留预算的表示发布给现有 GPU 常驻场景。GPU 随相机/投影选择已经上传的表示；近景、望远镜、活动 morph 和混合归属继续保留精确源网格。纯转向不生成体素、不重新编码这些静态命令。

本轮没有把世界存储替换为 Voxy 八叉树，也没有放宽跨瓦片父节点对 feature、水和不完整子节点的安全限制。花草的交叉面、烘焙 UV 模型、水、接缝/边界、预览几何和不适合重建的形状不进入体素填充。此前用户要求暂缓的花草按范围加载方向没有在本轮实施。

## 必须保留的现有收益

初版把树冠误差和地形误差直接取最大，挤掉原有地形表示，曾出现源网格反而更多的负例。该版本未发布。最终实现保留每个不同地形层的误差阈值，只复用空或重复槽位；已有层只有误差容纳体素形状时才附加 feature 代理。每个面组分别检查减少的面数，拒绝增加该组面数的代理。回到更细层时采用完整的退出误差界，避免滞回导致跳过仍有效的地形层。

初版命令成员还会在每个例外表面间交错，造成大量碎片。最终在后台把可体素化表面和必须保持精确的表面排列成连续 cohort。这样完整 GPU 路径不必为每个树干/叶片/例外面创建一个小命令。

## 资源上限和缓存

- 源不超过 1,048,576 个不透明面，栅格访问不超过 2,097,152 次，底层稀疏占据不超过 262,144 格，超出回到原显示路径。
- 最多 128 段替换范围；新增体素几何合计不超过源面数的 50%，且最多 262,144 面。
- 每层至少节省 64 面，代理不超过被替换表面的 75%，各可见面组均不能增加面数。
- 透明裁剪表面的误差门槛使用额外两倍几何余量，减轻树冠变密的视觉问题。该余量是保守策略，不是所有资源包像素差的数学证明。
- 层级构建支持取消；临时占据表在 worker 返回后释放。显示计划只保留范围、误差、映射，坐标仍交给已有可压缩存储，避免恢复之前的重复坐标引用。
- 完成网格缓存 identity 14 → 15、派生元数据 1 → 2。旧完成网格需要重建一次；地形采样缓存和 Voxy 的真实 LOD 数据不由本次版本变更删除。重存已恢复网格不叠加新层级。

## 对照方法与限制

使用仓库历史客户端捕获的六个森林网格（mode 0），真实原版 1.21.1 图集 alpha、当前生产 packing、shader、GPU 选层、筛选、屏障与 MDI。显卡为 RTX 4070 Ti SUPER，驱动 572.70，OpenGL 4.6。当前玩家资源包、光影与实际整合包画面没有重新采样。

直接绘制对照：512×512，70 度 FOV，距离 1024/2048/4096，yaw 0/45/90/135，共 72 个视角。性能段距离 4096、yaw 45，预热 16 轮，交错 31 对样本，取中位数。性能基线包含原有地形 LOD；没有把本来已有的地形简化再次算成新收益。

常驻场景对照：把同一捕获样本复制到 4×4 个不同空间位置，构成 16 瓦片、单区域、单显存页的共同批次；每种模式都从生产场景创建命令，比较同样的选层、筛选、压缩命令、同步和真实纹理绘制。它验证规模化提交开销，不能代表当前游戏完整帧。多瓦片各自距离不同，部分仍使用更细层，不能把这里的面数与单瓦片表直接相乘。

单瓦片完整路径约 0.1 ms，固定调用开销占比高，正负数微秒变化不稳定；已保留对应原始结果，不能只挑直接绘制的好看数字。无收益样本 359 不发布体素代理，维持原路径。区域测试中这个完全相同控制组的小波动说明 GPU 时序仍存在噪声。
