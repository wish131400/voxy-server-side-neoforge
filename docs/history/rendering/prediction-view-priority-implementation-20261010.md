**VSS 视野优先细化实施记录（2026-10-10）**

后续更新：[可见远景与屏幕细节细化](prediction-screen-detail-implementation-20261010.md) 已将视野优先贯穿普通远景目标，并加入无光影通道的异步遮挡降优先级；纯画面外已有覆盖的区域在前台完成后仍停止新升级。当前行为以该后续记录为准。

已同步到 Forge 1.20.1 与 NeoForge 1.21.1。本轮落实可行性报告的第一阶段：使用实际 LOD 视锥决定细化准入、更新排队优先级，并将加载完成条件联动到当前视野的 CPU 和 GPU 状态。代码自动生效，没有新增需要开启的配置项。

**玩家能感受到的行为**

- 当前画面内的地形、植被与建筑优先达到正常目标细节；近处但位于身后的普通高精度升级也可以暂缓，不再因为落在 512 方块半径内就全部当成前台。
- 当前画面仍有待生成细节时，纯视野外且没有覆盖依赖的昂贵升级不占队列和 CPU 预约。画面边缘和最近看过的区域有有限缓冲。
- 转身后，新视野任务会重新获得优先级；尚未开始且失去意义的任务会移出队列并释放预约。正在执行的任务完成当前有效阶段，避免反复取消重算。
- 360° 最低粗覆盖、Voxy 归属撤销恢复、脏地块修复、望远镜目标、可见父子交接和接缝地形依赖继续放行。移开镜头不会主动撤掉已有网格。
- 当前视野普通细节完成后，可以推进该区域的可选额外精化，不再等待整圈屏幕外的普通细节全部完成。
- 普通预生成等待“最低全景覆盖 + 当前视野普通细节 + 对应 GPU 上传”，而非等待所有被延期的后台细化。原有稳定窗口、回退阈值、保活和资源预算继续工作。

**视锥与更新频率**

`PredictionWorkView` 是不可变相机快照，来源于渲染实际使用的投影与 modelView，包含屏幕宽高比、缩放、镜头晃动与倾斜。使用侧平面和 clip-W 判断，不采用原版有限远裁剪面；尚未生成的候选也会分类，避免只能生成已经绘制过的区域。

边界保留 8 方块容差，画面边缘使用约 20% 的扩展保护带。未知或尚未达到目标的瓦片使用整个维度高度加建筑余量；达到目标且表面完成后才允许收紧高度包围盒。启动阶段使用 tick 相机作为回退，1 秒内的新渲染快照不会被它覆盖。

移动约 8 方块、转向约 3° 或明显投影变化时，在下一次客户端 tick 更新分类和队列，复用已有空间计划。完整空间规划保持原节流：NeoForge 通常每 5 tick；Forge 保留其快速移动时每 10 tick 的既有规则，其他情况每 5 tick。轻量转向路径不重新探测整套磁盘缓存或执行完整裁退。超过 90° 的转向或 256 方块的跳变清除近期可见历史；其他最近可见记录保留 1 秒。

**调度、依赖与生命周期**

分类依次为实际可见、边缘缓冲、近期可见和纯后台。现有距离、阶段和望远镜排序继续参与；可见地形的父链与邻接地形作为依赖放行。前台繁忙时，后台升级在入队前暂缓，worker 启动时再次检查。

地形依赖与植被依赖分开处理：屏幕外接缝地形可以继续生成，但该区域的植被不会被算作前台欠账，否则前台可能等待自己延期的工作。新增 `surfacePending` 记录排队任务的种类；队列取消、正常结束、执行器拒绝和关闭路径均清理相应记录。

缓存命中仍使用独立恢复通道，并按视野分类排序，不需要等待昂贵世界生成的前台门槛。总 CPU、帧率、内存、上传和后台并发预算保持原规则；本轮调整的是有效工作容量分配。

可选精化仅推进可见或依赖区域，并清理不再适用的请求、保留必要父链，避免反复转身占满 128 个目标。已有 resident 网格不随请求清理而直接删除；原 2 秒稳定期、1 秒 promotion 周期和资源保护继续生效。

**完成状态与可观测性**

`PredictionLoadingProgress.ViewProgress` 分开记录当前视野目标数、地形完成数、表面目标及完成数、GPU 可绘制数和纯后台欠账。已有整圈近处进度仍可诊断；无视锥的旧调用保持原判断。

GPU 完成判断来自实际上传后的 render residency 快照，并校验普通目标对应的 revision、capture epoch、mesh revision 与目标精度。等待可选升级上传时，已完成的普通 GPU 目标仍然有效；真实内容或资源变化会撤销旧目标。空几何无需等待上传。目标记录只保存版本和标量，不额外持有旧 CPU 网格。

开启现有 `debugLogging` 后，渲染诊断的 `surface.viewScheduling` 提供：

| 指标 | 含义 |
| --- | --- |
| `refreshes` | 视野分类刷新次数 |
| `foregroundDebt` | 当前前台是否仍有可调度的普通欠账 |
| `deferredAdmissions` | 因纯后台规则暂缓的准入检查次数，可能多次对应同一瓦片 |
| `visibleCpuMs / backgroundCpuMs` | 已准入任务按启动时类别累计的线程 CPU 时间；前台包含缓冲与必要地形依赖 |
| `visibleQueue / backgroundQueue` | 队列等待样本数、平均值、最大值、P50/P95 桶上界 |
| `viewReadyMs / viewWaitingMs` | 当前相机调度窗口达到普通可绘制目标的时间或已等待时间 |
| `loading` | 当前视野的 CPU、表面、GPU 和延期计数 |

队列延迟使用固定 32 桶直方图，不保存逐任务样本对象；P50/P95 是桶上界，不是精确分位数。视野就绪时间随新的相机调度窗口重置，不能直接当作进档总耗时。`/vssclient stats details` 中的 `predictionLoading` 也包含新的视野进度。

**验证范围与性能限制**

新增回归覆盖真实任务准入与构建、未开始任务的 CPU 预约释放、最低粗覆盖、转向复用计划、Voxy 覆盖撤销、普通 GPU 上传就绪、可选升级与真实版本失效、屏幕外植被不阻塞前台，以及预生成恢复与再次让出容量。

本轮没有启动 Minecraft 客户端或运行游戏性能采样。测试能验证调度和交接行为，不能证明进档、跑图或转身已经加速多少，也不能承诺静态 FPS 提升。

山后或建筑背面的区域如果仍在视锥内，会继续按前台候选处理。本轮没有加入逐瓦片 GPU 遮挡历史；可行性报告把它列为第一阶段实测之后的后续工作。预期主要收益是缩短当前画面达到正常细节的等待时间，完整一圈完成时间应单独衡量。
