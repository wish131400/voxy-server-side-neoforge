# VSS 可见远景与屏幕细节细化（2026-10-10）

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

本轮针对“近处已细化，但画面中远处仍明显粗糙”的反馈，继续修正上一版视野调度。实现同步到 NeoForge 1.21.1 和 Forge 1.20.1，版本号仍为 0.3.5，无需新增开关。

## 为什么上一版只改善了近处

上一版按视锥调整任务准入，但普通空间规划仍优先分配整圈近处区域的细分名额；普通精度和表面细化仍部分依赖距离半径，远景的更深升级可能进入要求稳定期及健康帧率的空闲通道。因此，单独调整排队顺序并不能保证远处明显的粗网格成为普通目标。

本轮把同一视野和屏幕误差判断贯穿规划、目标精度、表面细化、任务排序及完成条件。

## 当前行为

- 实际可见区域优先获得空间细分名额，随后是画面边缘缓冲；纯画面外区域保留最低粗骨架，不继续普通细分。
- 可见地形按当前格子在屏幕上的大小选择普通目标，远处大格子也能要求 16、32 或 64 轴网格，不再被近处半径限制，也不需要先等空闲精化。
- 普通地形目标满足屏幕误差后停止新升级；很小的瓦片可以保持 8 轴粗网格，不再欠一次无用的 32 轴中程升级。
- 在可生成表面细节的区域，远处树木、建筑大小的特征仍明显时，可以生成对应地表网格，无需先使用望远镜。低于屏幕阈值时不强制植物级网格。
- 当前画面普通目标完成后，已有粗覆盖的纯画面外区域仍然停止新升级；转身后它们重新进入可见普通目标。
- 可见普通任务按现有网格的屏幕误差排序。远处非常粗的格子可以排在近处误差较小的格子之前。
- 山后或建筑背面但仍在视锥内的区域，若当前深度确认其包围盒被挡住，会让出规划名额和任务优先级；实际露出的区域优先。遮挡提示只降优先级，仍可在前面的工作完成后推进。
- 最低全方向覆盖、脏列恢复、Voxy 归属撤销、望远镜目标、必要父子交接与邻接地形依赖继续放行。既有网格保留到正常交接或驻留淘汰；移开镜头不会主动删除它们。
- 现有总 CPU、帧率、内存、上传及有界规划预算继续控制实际工作量；本轮让容量优先用于当前能改善画面的工作。

## 屏幕大小如何判断

渲染端发布不可变的真实视锥快照及屏幕投影比例。投影大小使用候选包围盒最近的 eye depth，包括实际镜头方向、倾斜和晃动，避免用单纯平面距离低估画面边缘的误差。启动时尚无渲染快照，继续使用原有半径和距离投影作为回退。

普通地形使用配置中的像素阈值选择 8/16/32/64 轴目标。空间规划优先细分仍超出阈值的可见节点，保留父级覆盖以及邻级平衡；达到预算时保留粗 owner，不产生规划空洞。

树木和建筑采用 8 方块特征的投影大小作为保守代理。判断阈值为配置每格阈值限制在 1.5–3 像素之间，只有植物可生成的叶节点才进入完整表面任务。它不是逐棵树、逐栋建筑的真实误差计算；无法保证每一个模型恰好在相同像素大小停止生成。

画面边界仍保留 8 方块容差及约 20% 扩展带，减少转向时的反复启动。未知区域使用维度完整高度加建筑余量。实际像素比例变化超过约 5% 也刷新视野调度，窗口尺寸变化不会一直沿用旧分类。

完整空间规划保持原节流：NeoForge 通常每 5 客户端 tick；Forge 快速移动时保留每 10 tick，其余每 5 tick。转向的轻量分类及队列更新保留原快速路径。

## 遮挡反馈如何保证可恢复

在无光影的普通不透明通道完成后，使用包含真实区块、Voxy 与预测不透明几何的当前 reversed-depth 深度，执行有界 HiZ 包围盒探测。每 250 毫秒最多提交 1024 个候选，使用三个轮转结果槽；只对已完成的 GPU fence 读取结果，轮询超时为零，不使用同步等待或生产环境 glFinish。

测试包围盒保留地形范围和 64 方块的未知表面余量，深度判定复用已有保守 HiZ 实现。天空、轮廓孔洞、近平面相交及相机进入包围盒不会建立遮挡证明。已有粗父瓦片的完全遮挡提示可以用于尚未生成的子节点；子节点自己的可见结果优先于父级旧提示。

结果最多保留 1 秒，并校验生成 revision、覆盖 epoch 和视角变化。约 8 方块位移、3° 转向、投影变化、瓦片更新、归属变化或 dirty 状态都会使不再适用的提示失效；过期与未知结果恢复普通视锥优先级。世界切换、资源重载和关闭清理提示及 GPU 资源。

普通粗覆盖、必要交接、脏列恢复和望远镜目标继续受到保护。遮挡历史不参与渲染剔除、归属掩码、网格删除或硬性停止生成，因此短暂误判不会造成缺失覆盖。

光影/Iris 通道的深度约定不同，当前主动清除这组提示，保留视锥和像素调度；不支持 OpenGL 4.5、显式禁用预测遮挡或探测不可用时也保留普通调度。探测需要已有地形或粗父级范围，不能在完全未知区域准确判断每座山后的内容。包围盒过于宽大或碰到天空时，仍会保守地当作未知/可见。

现有渲染诊断增加 visibilityHints 的提交、完成和记录数；viewScheduling 增加 visibilityRecords。记录数包含尚待视角、时间和版本校验的历史，不能直接等同于当前有效隐藏区域数。

## 中程、交接和缓存

中程就绪判断对叶节点使用当前普通屏幕目标，而非上一轮尚未发布的新旧混合目标或可选精化目标。这样，已经达到像素要求的 8 轴叶节点不会被中程欠账重新拉到 32 轴，也不会因为过期目标阻止本区域表面任务。

当前视野完成条件仍校验普通 CPU 目标、表面及对应 GPU 上传。延期的画面外升级不阻塞当前画面就绪或普通预生成恢复。独立成品缓存恢复通道继续工作；已经存在的高质量缓存可以恢复，无需重复进行昂贵世界生成。

回归还覆盖了 NeoForge 现有地形/植被交接对无网格覆盖记录的判断：没有网格就没有可保留的植被，避免测试覆盖记录进入复制路径时抛出空指针。

新增与扩展用例验证：

1. 在 32768 方块视距、1400 投影比例的固定样例中，约 1800 方块处正面 owner 为 LOD 1，背对时为 LOD 4；前向计划有 1381 个叶节点，各方向采样点均保留且只有一个 owner。这是测试场景，不是实际游戏的固定细化距离。
2. 40 FPS 且空闲精化未开启时，可见远景仍能实际构建到普通目标；画面完成后，纯后台升级仍不运行。
3. 远处大格子以更大的屏幕误差获得优先级；很小的表面停止完整植物级生成。
4. 已经达到屏幕目标的粗叶节点不会反复补中程精度，过期的组合目标也不会重新形成中程欠账。
5. 转身、Voxy 覆盖撤销、CPU 预约释放、粗覆盖、必要邻接地形、GPU 就绪、缓存恢复和预生成交接继续正确工作。
6. 相同距离下，已确认被遮住的区域让出有界规划名额；隐藏任务仍能实际生成，新版本使旧提示失效。父级继承、子级重新露出、时效、转身、移动与乱序读回均有回归。
7. 真实 GPU 深度先建立遮挡提示；清空当前深度后恢复普通优先级，同时保留 OpenGL 存储绑定和状态。生产提交立即返回，测试中独立等待 GPU 仅用于验证读回。

逻辑测试使用各仓库独立的 `build-screen-detail-20261010/test-results/test`，GPU 测试使用该目录下的 `screen-detail-gpu`，避免其他构建覆盖这轮编译输出与证据。

本轮没有启动 Minecraft、替换游戏实例 JAR 或进行游戏性能采样。自动测试能确认目标、准入和交接行为，不能证明固定场景下提升了多少 FPS 或缩短了多少秒。

纯视锥外区域停止普通新升级；视锥内的确认遮挡区域降低优先级。两者处理不同。不能把本轮反馈理解为已经精确识别所有山后内容，或把历史结果当成硬性剔除依据。
