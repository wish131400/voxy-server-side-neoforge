## 这次发现并修正的缺口

队列中的未开始任务已经能重新排序或取消，但正在执行的细化原先只检查关闭／暂停、数据修订、捕获版本和 `effectivelyDesired`。玩家转身或缩小后，旧目标会在移动保留期内继续被认为有效，因此可能继续完成列采样、颜色、植被、网格、编码与上传暂存，即使该升级不再符合当前视角目标。

现在在采样分批、颜色行、外露列、植被、网格和打包等安全检查点同时验证数据是否仍有效、细化需求是否仍存在。过时的可选升级用独立取消原因退出，保留旧地块，统一释放 CPU 预约、CPU 租约、内存预约、磁盘租约和暂存上传。`supersededBuilds` 单独记录这类退出，不加入失败列表或 30 秒失败退避；转回来时可由正常调度立即重试。

必要工作仍会完成：没有已有覆盖的初次生成、脏数据恢复、当前望远镜目标、粗回退与边界／接缝依赖。缓存成品恢复保持按内容版本处理，不因为视角变化被认定为内容失效。退出只发生在安全检查点，不强行中断正在执行的 JNI/native 批次。

目标读取采用不可变地图，避免重规划中临时清空 `terrainLeaves` 误取消不变任务。植被目标也由先构造下一集合、再一次发布替代清空／逐条填回，避免正常植被任务把临时空集合误判为玩家已转身。

## 统一验收与采样

添加默认关闭的 `-Dvss.detailProfileDirectory=<目录>`。每秒最多采一组纯计数与上下文，JSON 编码和磁盘写入在专用后台线程中完成；队列容量 16、最多 1,800 行。数据包含：

- 相机、投影／视图矩阵、窗口大小、质量、维度、望远镜、菜单和着色器状态。
- 生成版本、计划目标、待执行任务、完成与过时取消、完成任务 CPU 计数。
- 不透明／水面的源、地形、显示、选中范围以及四个距离带。
- GPU 源和变体驻留、live／committed 字节、回收／恢复。
- 各 CPU/GPU 阶段的累计时间、样本数与丢失查询计数。
- 逐帧计数、累计帧时间、1 ms 直方图、33.3／50 ms 长帧计数，以及最近 90 帧的即时窗口。

对照工具从相邻观察作区间差分，用累计帧直方图计算 P95／P99，避免重叠窗口重复计算同一长帧。GPU 区间按新增样本数加权，没有新样本的阶段不使用旧均值；互相包含的阶段不相加。

菜单出现过、采样丢失、会话／维度切换、计数变化和长时间断档的区间被排除。静态 FPS 对照需要至少 10 秒相机、投影、窗口和画质对齐；仍应核对世界内容与生成状态。移动／转身／进档必须重复同一路线，工具只输出工作量，不能自动认定因果收益。

完整用法和固定视角 → 放大 → 缩小 → 再放大 → 转身／跑图 → 重新进档的步骤见 [统一验收说明](C:/Users/Administrator/Desktop/voxyserverside-neoforge-1.21.1/tools/prediction/detail-demand-profile/README.md)。

## 本轮的实际架构边界

已经补齐的是可选生成任务的需求退出与统一验收，已有细缓存、实际显示选择、覆盖和 GPU 冷恢复仍各自维持正确版本。它解决了需求下降后继续浪费后台工作的一条路径。

同源细列汇总出粗列、树冠粗外壳、普通父子可逆交接及按显示档拆分 GPU payload 仍属于更大的几何与驻留改造，本轮没有把旧粗父级选择或粗档优先原型当成已经完成的架构。继续推进它们应使用这套统一的相机／阶段／范围／显存／帧尾证据，逐项保留正收益。

本轮生产改动仅 `PredictionTileManager`、`ClientPredictionState`、`PredictionRenderer`、`PredictionFramePace`、`PredictionRenderTimings`、`PredictionGpuResidency` 和新增 `PredictionDemandProfile`。完整机器证据见同名 JSON；原始运行日志、受控工作量 CSV、平台基线和被否决的全语料回放保存在 `C:/Users/Administrator/.codex/tmp/vss-detail-demand-20261012`。
