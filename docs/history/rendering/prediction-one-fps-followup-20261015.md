# 仍有秒级停顿：GPU 场景清空与同步构建修复（2026-10-15）

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

上一版 `one-fps-fix-20261015` 没有解决用户现场的全部停顿。上一版覆盖了超出 64 MiB 后的反复构建／拒绝，本轮确认容量以内的整套重建仍可阻塞渲染线程。本报告对应后续修复，不能用上一轮测试通过代替本轮现场结果。

## 现场证据

客户端为 Minecraft 1.21.1 / NeoForge 21.1.249，Java 25，PID 32772。实例 JAR 的 SHA256 为 `61f0a37114fcc7d62a44a3e4568516ac0b61ede87015b2ffd639d8aac1599abe`，与上一版修复产物一致。

本轮完成 35 秒 JFR、只读帧率和场景计数观测，以及 30 秒自动恢复的运行时开关对照。观测和对照均已结束，开关已确认恢复为原来的不存在状态。没有替换实例 JAR、写入游戏配置、启动或关闭游戏。

对照使用 `vss.disableGpuPredictionSelection`：6 秒原状、18 秒临时禁用、6 秒恢复。恢复后在前台、无菜单、位置和朝向相同的连续快照中，渲染完成帧计数在约 3 秒内保持 8590，之后 FPS 读数降至 7。对照前段存在移动和转向，后段还有失焦／暂停，不能据此计算严格的 FPS 提升比例。它支持重启 resident scene 路径会触发长停顿，而不是证明新包已在游戏中修复。

## 本轮修改

### 材质发现不再清空整套场景

原逻辑对任何 `VssLodSpriteTable.materialRevision()` 变化调用 `clear()`，会删除固定命令槽和节点缓冲，再同步创建所有记录。该版本还会在后台首次发现新的方块、面或模型映射时变化，并非只表示资源包重载。

GPU 场景现在依赖记录自己的 packed mesh、GPU 分配、绘制范围、palette、morph 等版本。无关材质发现不再导致清空或重写。真正的图集／世界重置仍通过已有的 `PredictionRenderer.resetOcclusion()` 释放整个场景。

### 首次创建和大更新分帧准备

生产 `PredictionGpuScene.update()` 共用一套有界准备逻辑，限制每次最多 32 项范围准备、编码／更新或移除工作，并采用约 2 ms 的软时间片和约 256 KiB 的软上传预算。时间和字节阈值在工作项之间检查，单个驱动调用不能中断，也不保证整个方法或整个渲染帧严格小于 2 ms。

完整输入的容量预检查仍在任何新增 GPU 记录之前执行。已完成的范围与记录跨帧复用；连续移动时也会清除不属于最新输入的范围计划，避免暂存缓存无限增长。

准备未完成时返回失败，由渲染器继续使用普通的精确 ownership 绘制路径。当前输入的记录全部就绪后才提交完整 LOD 图并启用 resident 绘制，半套图不会参与父子选择。构建期间的 GPU 节点编号也被记录和校验，避免输入变动后旧命令引用已复用的节点。

`PredictionIndirectBatch` 把未完成准备也视为最近使用，并记录其编码／上传计数，避免准备工作被误当作闲置而清理。安全回退仍关闭本帧 resident 专用 GPU selection。

### 等价输入沿用稳定顺序

输入列表重排或绘制范围被等价对象替换时，使用精确成员和范围比较确认等价，沿用已准入的分配顺序与 LOD 图输入。容量检查也只由实际输入或相关 GPU 驻留变化触发。哈希值不作为相等证明。

回归过程中补修了快速路径：完全无成员变化时直接复用；局部变化也沿用稳定图输入，避免下一帧又因等价列表身份不同上传整图。

### 节点批量上传

原实现每个节点单独执行一次 64 字节 `glNamedBufferSubData`。现在复用本地连续暂存缓冲，填充完整节点布局和已删除槽位的零值，一次上传当前图。没有图变化时不上传。

上传计数同时补齐三套安全命令及对应清零写入；计数仍不包含驱动内部复制或所有缓冲扩容成本。

## 回归范围

新增验证实际生产更新入口：

- 1536 个稀疏区域瓦片的冷场景会主动让出，单次重工作项不超过 32。
- 构建期间撤销一个区域、添加另一区域并更改局部范围，随后持续发布等价重排列表，最终仍能完成，且引用当前空间节点。
- 准备未完成时不提交图，完整冷图只需一次节点上传。
- 40 次无关材质发现保持原 slot、命令、编码数、上传字节和节点上传数。
- 真正清空资源后重新走有界准备。
- 实际 `submitScene` 未就绪时走精确回退；逐帧颜色和深度与原路径一致，包括局部覆盖、撤销、输入替换和重排。
- 保留超限前拒绝、父子互斥、显示档位、GL 状态恢复和其他架构回归。

构建时还修正了工作区 `PredictionTerrainDisplayRanges.selected` 声明多出一维的编译错误，保留现有地表植被范围逻辑。

本轮进行期间，工作区另有地表植被档位及 LOD 历史标识的并行改动。本轮保留了这些改动，重新验证当前完整生产源码，并将地表植被、植被 LOD、材质、空间排序及缓存恢复回归加入同一验证任务。扩展验证也修正了两个原测试假设：近处及放大视图的视锥不一定包含整个瓦片；纯小植物瓦片在最远档位可能完全没有绘制范围。源范围包含关系、近处恢复和画面对比仍需通过。

由于并行任务还在修改测试夹具和生产文件，本轮最终测试输入冻结至 `tools/prediction/one-fps-followup-20261015/regression-src/`，生产 Java 源码冻结至同目录下的 `production-src/`。最终构建入口显式使用这些源码。构建清单记录冻结生产源码、资源、冻结测试源码和构建入口的 SHA256，包审计验证这些输入没有在构建期间变化。原工作区中的后续编辑不会被误计为本轮已经验证的内容。最后的生产快照包含节点历史暂存数组复用，保留本轮分帧准备与批量上传。

测试入口为 `tools/prediction/one-fps-followup-tests.gradle`，输出隔离至 `build-one-fps-followup-20261015/` 和 `lib/one-fps-followup-20261015/`。

最终测试统计、冷构建观测和 JAR 校验值见后面的交付记录。隐藏 OpenGL 回归与游戏同时运行，其计时只用于观察孤立路径，不能换算游戏 FPS。新包的实际存档表现仍需用户替换后验证。
