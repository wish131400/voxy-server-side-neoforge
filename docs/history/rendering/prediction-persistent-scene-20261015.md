# VSS 与 Voxy 的帧率差异及固定 GPU 场景改造

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

## 结论

VSS 低于 Voxy 不是单一原因。当前证据同时指向两层差异：

1. **当前实现仍有 CPU 场景准备成本。** 最近一次有效游戏窗口中，26.018 秒内渲染线程占用 22.828 秒，约为一个逻辑核的 87.74%；绘制计划准备 2051 次、复用 0 次，而网格上传只有 4 次。JFR 中 `Scene.prepare`、`PreparedPass.prepare`、可见列表和批次添加都出现在渲染线程热点中。这说明场景已在 GPU 驻留时，视角变化仍会让 CPU 重做候选、范围、排序或提交准备。
2. **Voxy 的数据组织更适合远景。** Voxy 从同源体素数据构建 2x2x2 逐级 mip，GPU 遍历父子节点，按视锥、Hi-Z 和屏幕误差选择层级；缺少细层时使用父级回退。VSS 已有显示 LOD、父子回退、meshlet bounds、MDI 和有限 Hi-Z，但预测网格仍要处理混合归属、接缝、植被、透明排序和 morph，尚不是同源三维代理树。VSS 的候选四边形数量也不能当作最终可见面数；远处画面精细不代表 Voxy 实际提交了同样多的面。

因此，不能把“GPU 平均利用率约 50%”直接解释为显卡没有吃满，也不能把离线提交基准换算成整场游戏 FPS。当前最直接的优化方向是切断视角变化对静态提交记录的传播，再逐步减少远处实际选中的几何量。

## 已完成的限定改造

本轮在 Forge 1.20.1 和 NeoForge 1.21.1 同步接入了固定 GPU scene，仅用于满足现有资格策略的常驻不透明 GPU 选择路径：

- 每个空间区域使用固定 metadata 槽和 2 的幂次命令区间，记录身份与 `baseInstance` 稳定；可见性变化不会给邻居重新编号。
- 网格、GPU 驻留、材质或覆盖真正改变时才更新对应记录；有界变更日志只编码受影响网格，历史溢出或版本不明时退回完整验证。
- 相机只改变区域的近远排序和当前帧选择，不重建所有世界空间 payload。接缝、重复 payload、独立网格和不满足资格的场景继续走原有安全路径。
- 删除记录会清零命令槽并保留其他槽位；扩大命令区间时使用 DSA grow-copy，保留旧记录和偏移。
- 固定场景受约 64 MiB 保留上限约束；超限、显存分配失败或平台路径不适用时回退，不靠无限缓存换帧率。

这不是完整 Voxy 式 GPU 层级遍历，也没有放宽原有 GPU 选择门槛。生产条件仍包括足够大的常驻不透明场景、当前帧 Hi-Z、没有接缝、相机位置不变的转向，以及 OpenGL / Iris / 水面等路径限制。

## 离线验证

隐藏 GLFW 4.6 上下文中，使用与生产选择策略相同的 3072 个地形瓦片和当前帧 Hi-Z；每种模式 12 轮预热、21 轮测量，每轮 32 帧并等待 GPU 完成。该测试只覆盖选择、提交和 GPU 命令完成，不包含完整游戏帧、全部 `Scene.prepare`、区块生成或真实森林。

| 平台和场景 | 原有有序提交 | 固定 GPU scene | 下降 |
| --- | ---: | ---: | ---: |
| NeoForge，静态场景原地转向 | 0.611734 ms/pass | 0.359072 ms/pass | 41.3% |
| NeoForge，每帧更新一个网格元数据 | 1.539022 ms/pass | 1.150066 ms/pass | 25.3% |
| Forge，静态场景原地转向 | 0.465756 ms/pass | 0.281469 ms/pass | 39.6% |
| Forge，每帧更新一个网格元数据 | 1.551591 ms/pass | 1.184153 ms/pass | 23.7% |

CPU 回归：NeoForge 86、Forge 85；隐藏 GPU 回归两平台各 11；失败、错误和跳过均为 0。测试结果和逐平台产物审计保存在 `build-persistent-scene-20261015`、`lib/persistent-scene-20261015/validation.json` 和 `SHA256SUMS.txt`。

## 为什么仍可能低于 Voxy

- `PredictionFramePlan.getStable` 仍要求相机、视图矩阵和投影矩阵完全相同；转向会离开整帧复用途径。固定 scene 只减少提交 payload 重编码，不能让每帧视锥和当前帧遮挡判断消失。
- CPU 仍负责区域管理、覆盖资格、接缝安全、需求队列、版本交接和部分可见成员处理。Voxy 把更细的父子节点选择放进 GPU，并且其粗代理来自同源体素 mip。
- 预测几何需要保留特殊模型、植被、透明水面和真实地形交接。把所有远景都强行转换成 Voxy 的规则面会产生画面错误或接缝，因此当前只能在适用网格上使用紧凑编码和显示 LOD。
- 当前 GPU scene 只覆盖 qualified resident opaque whole ranges。移动、接缝、Iris、透明水面和不完整覆盖会回退到原路径；这保证正确性，但不会给这些路径带来固定 scene 的收益。
- 此次离线数字不能承诺游戏 FPS 提升。下一轮必须在相同位置、分辨率、视距和画质下对比静止、转向、跑图和森林场景，记录渲染线程准备时间、实际编码量、候选面数、通过剔除面数、批次数和分阶段 GPU 时间。

## 后续顺序

1. 继续把同源细数据汇总成真实父子粗层，先统计远景实际减少的面和显存读取量。
2. 把 CPU 的选择收缩到区域级，逐 meshlet 的视锥、方向、屏幕误差和当前帧 Hi-Z 交给 GPU；水面排序和接缝继续独立处理。
3. 将纯需求分类和优先级计算以不可变版本快照后台化，在客户端线程只做安全交接。
4. 以相同游戏画面对 VSS、Voxy 和 DH 做 A/B；只有实测净收益的路径保留。

本轮没有启动客户端、替换用户实例或推送 GitHub。交付 JAR 由用户自行替换测试。
