# 传送后粗模型条纹、断面与 Voxy 交接修复（2026-10-17）

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

用户补充：异常主要出现在粗模型区域，刚传送后尤其明显，加载完成后恢复。本轮围绕粗模型退出绘制的条件检查，确认并修复了着色器误删前景、CPU 将磁盘覆盖误当作 GPU 就绪，以及旧整块归属在 Voxy 重建后继续生效的问题。

这些错误已经通过生产代码回归复现和修正。尚未取得截图异常发生期间的连续现场抓帧，因此不能据此宣称截图中的全部异常已现场消失，也没有测量本轮修复后的游戏 FPS。

## 已确认的问题

**着色器提前剔除前景。** 原路径只要预测面在 Voxy 半径内、对应列存在索引、当前像素有任意真实深度，就直接删除预测地形。真实深度可能来自后方断壁，并不表示前景地表已就绪。粗模型采样较疏时，两者轮廓更容易错开，删除后会暴露后方断面或天空。

生产 GPU 夹具覆盖普通直绘、间接批次、Iris 普通深度、Iris 反向 0–1 深度；粗模间距为 8、16、32 方块，并测试两个朝向、索引开关、后方断壁、较低真实地面、前景峭壁、同面地面、天空和部分真实画面。共 288 组中心像素检查，原实现有 24 组误删，均为索引存在时被后方断壁错误接管；修复后两平台均为 0/288。

**磁盘覆盖被误当作可绘制覆盖。** 原 CPU 地形、水面过滤只检查已稳定的磁盘列。GPU 上传证明主要用于临时植被；纯地形整块快速路径甚至不建立可撤销的上传依赖。这样在传送后尚未上传、上传撤销或 Voxy renderer 重建时，粗模型可能仍被排除。

**规划阶段另有整块提前退出。** 后台规划会根据磁盘列和视距停止预测工作，客户端发布时直接删除已完成瓦片。驻留阶段又把快照中的旧归属位当成现成替代。只修着色器或绘制过滤不足以堵住这些更早的删除路径。

修改前另外保存了 5 项失败 CPU 用例，分别覆盖地形／水面未上传、无临时植被的混合网格撤销、整块证明在 renderer reset 后撤销、磁盘覆盖提前退休规划，以及旧快照提前删除 GPU 回退。修改后均通过，并扩展检查了后台结果交接前失效、立即恢复与资源保留。

## 修改后的交接规则

1. 删除 `VoxyOwnershipDistance` uniform、setter 和对应重复 fragment discard。索引与深度交接统一经过已有的局部真实地表、距离和深度判断。
2. 普通地形、水面和临时植被的 CPU 删除都要求稳定磁盘覆盖与实际 GPU 区域覆盖。完整植被继续经过当前画面的深度判断。
3. 整块快速证明也进入已有缓存，记录 GPU 依赖；本地上传撤销、窗口变化和 renderer reset 撤销证明，远方无关上传继续复用。morph 改变时重新校验其高度范围。
4. 客户端只核验已有候选区域，将不可变的已上传瓦片集合交给后台规划。后台线程不访问 Voxy 的可变节点索引；发布结果时再次核验上传和相机范围。
5. Voxy 接管时停止重复生成，保留已有成品作为回退，继续使用原有 CPU 缓存、内存压力、GPU 驻留和距离淘汰机制。上传撤销立即撤销已发布的规划归属；驻留不再仅凭旧归属位强行退出。
6. 客户端的证明采集使用局部 `hasSettledExactCoverageBox` 查询，避免复制整张已探索索引。完整规划和探索索引快照仍留在后台。GPU 区域查询使用包含上界的方块坐标，例如主世界检查到 Y=319，避免等待维度顶端之外的区域。

没有增加交接计时等待，也没有新建第二套世界边界索引。缺少 GPU 证明时会暂时保留更多预测几何，这是交接正确性所需；实际帧时间与内存变化仍需要现场验证。

## 产物与证据

两个仓库分别在 `lib/scene-handoff-20261017/` 输出对应平台 JAR 与 `SHA256SUMS.txt`。最终校验值见同目录文件，逐项包审计保存在各仓库的 `tools/prediction/scene-handoff-20261017/package-audit.json`。

相对于上一轮 `teleport-loading-20261017` 包，每端只改变此次 7 个生产类及其嵌套类，共 26 个 class 条目，另有 manifest 构建时间变化。没有增加或删除 JAR 条目，测试夹具未打入生产包。审计核验了 Java class 版本和已删除的旧 uniform，并确认上轮雾、Voxy 真实侧面、植被深度及传送调度修复没有被回退。

主要修改：`PredictionTerrainProgram`、`PredictionRenderer`、`PredictionOwnershipRuns`、`PredictionAuthoritativeCoverageView`、`PredictionPlanPreparation`、`PredictionTileManager`、`PredictionRenderResidency`。

NeoForge 证据目录含修改前的 GPU 日志、5 项 CPU 失败结果与源码备份；两端均保留最终 Gradle 日志和 JUnit XML。回归入口为 `tools/prediction/scene-handoff-tests.gradle`，在已有 `meridian-implementation-tests.gradle` 后应用。

## 现场验收

用户自行替换对应 JAR 后，重点观察传送到未完成加载的区域、8/16/32 方块粗模、真实断壁与粗地形重叠处，以及水面、竹林和树木轮廓。检查粗模是否被条状挖空、Voxy 网格逐步出现时是否保持连续、覆盖撤销后是否恢复；同时记录刚传送的长帧和内存占用。

本轮没有替换实例 JAR、启动或关闭游戏、修改游戏配置，也没有提交或推送 GitHub。当前客户端仍是上一轮传送调度包；新包需要用户自行替换后验收。
