**VSS 渲染架构调整与 A/B 验收 — 2026-10-11**

本轮按 Voxy/Sodium 对比报告的方向实施了两项有收益的生产改动：页组独立缓存、几何池满后的批量提交。另补齐提交与遮挡样本的计数口径。“优先存储最粗显示层级”的候选在真实网格重放中增加了按屏幕误差选出的面数，已撤回。

修改已同步 Forge 1.20.1、NeoForge 1.21.1，分别构建新 JAR。没有推送 GitHub，没有启动、替换玩家客户端。本轮没有游戏 FPS/最差帧的前后对照；以下数字是生产 Java 提交路径和真实 OpenGL 的组件 A/B，不能直接换算为帧率。

**保留的架构变化**

原间接命令缓存虽然有逐项校验，但遇到一个不匹配项后，会重编码后续整个提交序列。现在命令、局部 bounds 和 GPU 命令槽归属于“页、遮挡距离桶、分段”的独立组。当前组变化时只重编码当前组，下一个组重新尝试复用。网格、范围、分配、材质、形变时钟等原有精确校验保留，完整通道重放仍检查全局版本。水面继续按原透明顺序提交，没有按页重排透明物体。

主几何 arena 的上限仍为 2 GiB。以前主 arena 满后，小网格进入独立缓冲，导致大量逐 tile 直绘。现在先尝试 8 MiB 的小页溢出池，仍使用同一 MDI、颜色表、覆盖掩码和 fence 生命周期；不能装入或溢出池达到上限时，继续走独立缓冲回退。溢出池按需分配，最大 64 页/512 MiB，计入现有 GPU 驻留软预算。它替代原独立缓冲的数据，页面未用满时会有额外容量；不是预分配 512 MiB，也不是显存压缩方案。没有修改现有可见、近处、接缝和粗级回退保护。

每个 slice 记录所属 arena，退休会回到正确的池。主池清理与关闭同时处理水面池、溢出池。池满测试验证了所有溢出页在 GPU 完成后释放，主池不会因溢出而扩容。

NeoForge 的水面 MDI 资格检查同时修正为查询水面实际 slice，与 Forge 保持一致。两仓库保留了原有加载器 API、Java 版本和其余原有差异，没有用整体文件覆盖抹掉已有改动。

**组件测试的收益**

GPU：NVIDIA GeForce RTX 4070 Ti SUPER，驱动 572.70。每种布局预热 24 轮、记录 41 轮，交替 A/B。CPU 使用 System.nanoTime；GPU 使用 GL_TIME_ELAPSED。glFinish 在 CPU 计时之外。性能重放关闭光栅化，用于隔离命令准备、提交和顶点处理；另有真实颜色/深度读回验证。

基线是本轮修改前工作树的间接命令实现，不是 Git HEAD。测试类 ArchitectureLegacyIndirectBatch 仅改类名、增加编码项计数。静态/局部变化布局包含 3,072 条真实 GPU fixture 绘制记录；混合布局每 256 条插入一个独立缓冲直绘。此测试是合成布局，不是该存档每帧实际地块分布。

| 平台与场景 | CPU 中位耗时：修改前 → 修改后 | CPU 降幅 | GPU 中位耗时：修改前 → 修改后 |
|---|---:|---:|---:|
| NeoForge：局部变化 | 0.3838 → 0.3201 ms | 16.6% | 0.9206 → 0.9206 ms |
| NeoForge：混合缓冲局部变化 | 0.4483 → 0.1820 ms | 59.4% | 0.9247 → 0.9257 ms |
| Forge：局部变化 | 0.4330 → 0.2986 ms | 31.0% | 0.9206 → 0.9206 ms |
| Forge：混合缓冲局部变化 | 0.4472 → 0.1776 ms | 60.3% | 0.9247 → 0.9247 ms |
| NeoForge：主池满后 384 个地块 | 0.0658 → 0.0233 ms | 64.6% | 0.1905 → 0.1178 ms |
| Forge：主池满后 384 个地块 | 0.0647 → 0.0286 ms | 55.8% | 0.1956 → 0.1188 ms |

局部变化时，编码项从每帧 3,072 降至 2,048；混合布局从 3,072 降至 256。上传字节分别保持 172,032 和 21,504 字节：旧实现也会比较数据并跳过未变组的上传，因此收益主要来自少编码、少比较，不能把“减少重复编码”误写成“同比减少上传”。

静态布局，NeoForge CPU 0.1502 → 0.1398 ms，Forge 0.1469 → 0.1545 ms，GPU 基本一致。这个量级的变化不作为稳定提升结论。保留的依据是两平台局部变化与混合缓冲都有明显收益，静态路径没有显著成本变化。

池满场景调用数从 384 降至 2，GPU 顶点阶段中位耗时下降约 38%–39%。测试用 JVM 属性将主 arena 限到 128 MiB 并实际填满，走的是生产分配与提交路径；交付 JAR 的默认主池上限仍为 2 GiB。两组包含相同的真实网格和覆盖掩码，候选面数不变。额外不透明缓冲容量从 10,242,048 增至 16,777,216 字节，约多 6.23 MiB；因此这项减少提交成本，不能宣传为减少显存。两个实现都使用本轮页组缓存，以隔离池外分配/提交路径的影响。

**统一计数口径**

- PreparedPass 记录原始面向候选、显示层级后的候选、Voxy 归属过滤后的候选。稳定帧复用这些计数。
- 间接提交记录 submissionFrame、mdiCandidateQuads、directCandidateQuads、directTiles、mdiCommands、passCulling。submissionFrame 是本 batch 实例的通道提交序号，diagnostics 中保存最近一次不透明通道的数据，不是 Minecraft FPS 计数。
- 异步 Hi-Z 样本带 sampleSubmissionFrame，保存该样本所属帧的 MDI 和 direct 候选量。sampleAfterHizQuads 从同一采样帧的候选量减 hiddenQuads，包含未经过 Hi-Z 的直绘候选；不会拿旧遮挡结果去减当前帧候选。
- sampleAfterHizQuads 是命令筛选后的几何量，仍在像素深度/透明混合之前。sampleAge 使用 culler 调用序号，不能当作实际显示帧差。
- 驻留 census 区分 residentSourceQuads 与 residentDisplayVariantQuads，并列出源地形、完整 features、preview 和水体。features 包含植被和建筑，不能把它全部称作树叶。这是驻留统计，不是当前画面像素或提交量。

新增计数复用已有准备循环与工作线程网格 census，没有给渲染循环增加逐面扫描；异步读回仍只在零超时 fence 成功后执行。

**撤回的显示层级候选**

测试将显示变体的构建/存储优先级从 1→3 改为 3→1，保持原来最多追加源不透明面 50% 的存储上限，并保留相同的屏幕误差选择。对之前捕获的 2,019 份真实源网格重放，源面共 21,344,411 个。原始坐标/属性数组合计减少约 47.4 MiB，但在相同误差阈值下，可用中间层级减少：

| 隔离测试的视深 | 原分配选择的面数 | 最粗优先选择的面数 | 结果 |
|---:|---:|---:|---:|
| 2,048 方块 | 18,962,827 | 21,344,411 | 增加约 12.6% |
| 4,096 方块 | 14,592,782 | 16,334,572 | 增加约 11.9% |
| 8,192 方块 | 12,497,475 | 13,461,465 | 增加约 7.7% |

这些是把捕获网格放到统一视深、完整归属条件下的隔离测试，pixel scale 固定为 1475；有 morph 的网格仍用原图。材质类别使用捕获的 leafClass 和雪材质适配，不代表当前资源包所有注册表标签；不是捕获帧实际相机/归属重放，也不是精确显存收益。规范源数组、面组顺序和 50% 上限检查通过，但显示选择负收益，已恢复本轮开始时的 PredictionDisplayGeometry。拒绝候选和结果仅保存在 tools，未进入生产包。

没有改变普通父子地形/植被归属来强制提交粗父级，也没有新增 cluster 树或再叠加一套遮挡算法。这些尚缺少同存档、同视角的收益证据，本轮只交付上述已验证改动。
