# 已采集真实地表的预测回退与粗层同步

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

日期：2026-10-16。平台：NeoForge 1.21.1 / Java 21、Forge 1.20.1 / Java 17。发布版本均为 0.3.5。

本轮实现了自然地表与流体范围内的真实数据回退：客户端收到、观察到或即将卸载的完整真实区块，可以在后台提取为 256 根地表柱，并逐层汇入有界的区域摘要。离开 Voxy 的有效渲染范围后，预测网格使用这些真实地表数据。脏通知期间保留最后有效的真实捕获，等待新版本替换。

这是对 [2026-10-15 TNT 交接审查](prediction-tnt-handoff-audit-20261015.md) 中已确认数据源缺口的修复。没有进入玩家存档、引爆 TNT 或测量当前客户端帧率；下文数字来自生产路径回归与合成成本对照。

## 数据流与更新范围

1. 服务端完整 `VoxelColumnData` 和本地真实区块快照共用一个有容量上限的捕获入口。连续方块修改只排入区块坐标，100 ms 安静窗口合并编辑；持续变化最多等待 500 ms，再尝试采集。
2. 普通 tick 最多复制一个区块的方块与生物群系调色板。后台只读取脱离可变世界状态的副本，不任意访问正在修改的 Minecraft 区块。
3. 卸载前尝试采集该坐标；即使区块到达早于预测系统初始化，没有收到当时的到达通知，也能在卸载前补入。卸载突发可以复制多于一个区块，仍受快照入口容量限制，不能把普通 tick 限额解释成绝对逐帧上限。
4. 提取、区域归约、压缩与写盘使用已有预测执行器。每个管理器最多一条捕获任务通道，每次处理至多四份快照，并申请共享 CPU 配额和 2 MiB 临时工作预算。配额不足会保留已接受的任务，后续 tick 重试。
5. 版本检查拒绝提取期间已被后续脏通知或新快照取代的工作；串行提交避免旧捕获覆盖已经提交的更新捕获。旧网格保留到替代网格就绪。区域记录逐条落盘，不是整棵层级的原子事务。
6. 真实区域变化会使相交的活动网格与磁盘网格依赖失效。祖先更新按区域交集判断，不能再只检查粗网格的稀疏采样点。相邻接缝也包含在刷新范围内。

Voxy 覆盖仍由实际有效范围和原有交接规则决定。历史真实地形记录负责选择回退数据源，不会凭“以前有过真实区块”永久隐藏范围外的预测几何。

## 粗层表示

新增 `PredictionCapturedTerrain`：

- 第 0 层按区块保存 256 根完整捕获柱，保留现有地表柱格式的材质、流体及有限外露空腔证据。
- 第 1～12 层保存四个子区域的整数统计和材质摘要，覆盖边长 32～65536 方块的单元。边长 16 的摘要由第 0 层生成；2、4、8 方块单元在相应叶节点内归约。
- 已捕获面积参与平均，未知面积使用当前预测样本。原本位于采样点之间的编辑也参与粗表示。
- 各层保留整数总和，最后一次查询才舍入，避免每层向下取整把一个小坑扩散成极远处整片一格的下降。
- 归约结果带独立来源标记，不作为更细网格的精确地形输入，也不能把同一个部分覆盖的修改反复应用到自身。
- 地面材质代表与液体类型独立选择；低处干地不能让占多数的水面／岩浆在摘要中丢失流体类型。

合成例子：区块 `(1,1)` 中间 10×10 区域从 Y=64 降至 Y=56。细查询仍得到 Y=56；32 方块单元得到 Y=63，证明修改参与了粗层。到 256 方块单元时，这个小坑可以被正常的平均与整数精度量化掉。修复不承诺任意距离都保留小坑的逐方块轮廓。

## 内存、落盘与成本限制

| 新增状态 | 限制与行为 |
| --- | --- |
| 等待本地采集的坐标 | 最多 2048 个；编辑优先于普通到达；不保存可变区块引用 |
| 等待后台处理的原始快照 | 最多 32 个，估算占用不超过 16 MiB；同坐标合并为更新快照 |
| 正在处理的快照 | 单独有一份，已从等待队列取出；不包含在队列的 16 MiB 数字中 |
| 捕获解码缓存 | 估算内容预算 16 MiB、最多 4096 个节点；实际 Java 对象、映射与共享存储还有管理开销 |
| 区域存在性缓存 | 最多 256 个区域 |
| 落盘 | 复用现有压缩 region 文件，新增记录类型 3；捕获持久化后才允许解码副本被淘汰 |

无文件的区域不会按每个网格点缓存一条空结果，避免 66×66 查询填满负缓存并挤走真实记录。相同捕获不重写叶节点与未变化的祖先；仍检查祖先是否需要修复。新捕获迁出旧的全量堆内样本存储，避免一份数据重复保留。

`rememberTerrain` 默认 true。开启时，真实捕获可以在解码缓存淘汰及退出后从磁盘恢复。关闭时只能保留受缓存容量限制的会话数据，不能保证远处旧捕获在淘汰或重启后仍然存在。磁盘缓存随探索增长，本轮没有给历史数据设置自动删除额度。

入口满载时不会无限积压：本地仍在加载的坐标可以等待后续 tick；卸载后已经拿不到真实数据的坐标、以及被拒绝的远端完整捕获，不保证最终保存。IO 失败会记录日志并保留已有回退，本轮没有新增自动 IO 重试队列。

## 合成成本对照

使用同一份真实地形截面输入、原生后端未代替 Java 采样的对照环境。旧提取器留在测试目录中作为参考，结果逐柱比较一致。不是实际游戏帧时间或 FPS 对照。

| 工作，墙钟中位数 | NeoForge / Java 21 | Forge / Java 17 |
| --- | ---: | ---: |
| 旧提取器：完整区块仍逐柱请求种子地形 | 8.0868 ms | 7.4094 ms |
| 新提取器：一次预览元数据 + 真实截面扫描 | 1.8041 ms | 2.1679 ms |
| 客户端复制 12 个非空截面，包含 mock getter 开销 | 0.5911 ms | 1.0488 ms |
| 第一次捕获 + 12 层摘要持久化 | 28.1731 ms | 26.8119 ms |
| 内容相同的重复捕获，跳过写盘 | 0.0066 ms | 0.0068 ms |
| 已缓存的 66×66 粗网格查询 | 0.1196 ms | 0.1590 ms |

复制 12 个截面的 P95 分别为 0.9130 ms、1.5485 ms；实际模组、区块高度和调色板复杂度会改变成本。普通 tick 限额控制频率，并不保证单次工作恒定耗时。

提取器每次分配中位数：NeoForge 从 436760 降至 104848 字节；Forge 从 383000 降至 108952 字节。新的首次持久化每次约分配 0.72 MiB 调用线程对象，包含层级构造与压缩；另有共享提交线程的成本。这部分在后台，不能与客户端快照复制时间相加后当作渲染线程耗时。

20 个合成区块落盘后，捕获解码缓存估算为 603392 字节，测试临时磁盘文件总计 875815 字节。区域索引有固定开销，不能把这个小样本直接外推为任意世界的每区块磁盘占用。

Windows 线程 CPU 计数器有量化，测试同时记录 CPU 均值与分配数据；单次 0 ms CPU 读数不代表没有执行。完整 JSON 位于各仓库 `build-edited-terrain-20261016/results/edited-terrain-benchmark.json`，发布验证也复制了这些结果。

## 使用与功能边界

用户自行替换对应版本 JAR 并重新启动；本轮没有替换实例、启动或停止游戏，也没有推送 GitHub。

测试时保持 `rememberTerrain=true`。旧包期间修改过的区域需要再靠近加载一次，才能采到修改后的真实内容。推荐在一处易辨认的地面炸坑，等近处画面更新后离开到 Voxy 范围外，再返回、重进世界检查。小坑在极粗远景中的自然量化应与完整旧地形回退区分。

本轮没有从 Voxy 历史数据库全量反查任意已探索区域，也不能估算玩家从未收到的服务器改动。自然地表和流体以外的任意建筑拆改、植被编辑持久层、完整地下体素更新，仍需要各自的数据表示。本轮保留了原有地表柱的有限外露空腔证据，不以地表高度替代地下维度的完整体积采样。
