# VSS 0.3.6

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

构建标识：`dirty-handoff-20261029`。

修复收到真实地形修改通知后，先使用旧采样重建预测、再在新数据到达后重复重建的问题。完整列更新分为两个阶段：通知到达时撤销旧任务的发布资格并保留当前画面；满足最新版本的真实列完成捕获、地形缓存和面积父层提交后，再刷新依赖它的预测地形与植被。相邻列的共同依赖由同一个等待状态管理，复用已有刷新合并机制。

等待期间保留已显示的地形和植被；没有等待依赖的区域继续加载。等待规则统一应用到构建入口、任务执行检查和最终发布，覆盖通知前已经排队但尚未启动的任务，以及等待期间才出现的新细化目标。

修复捕获队列满时无法向请求方反馈的问题。需要刷新的真实列未进入有界捕获队列时，请求保持可重试；提取或写入临时失败时，队列保留已接收的快照并延后重试，其他列继续处理。捕获写入期间再次收到修改通知时，旧捕获不能解除新版等待，也不能提交旧采样。地形高度相同但植被、建筑变化的更新同样会触发刷新。

统一脏通知、请求发送和请求保留范围：已有视距缓冲区中的脏列也能请求更新。移出请求保留范围或会话重置时，同步结束对应等待，避免遗留无法完成的阻塞。尚无本地旧列的可用性通知遇到暂时缓存缺失时，保留更新版本并重试。过滤列继续使用原有刷新路径，不等待无法提供的完整列。

修正 Forge 覆盖状态在通知、捕获提交和植被发布之间的坐标编码不一致，确保已修改的真实列能被正确识别，并避免植被补全时重新加入该列的预测植物。

保留主项目已有的末地群系上下文与植被缓存修复。Rust / Java 地形计算、完整树形缓存和 Voxy 统一渲染继续使用现有流程。

同时提供 NeoForge 1.21.1 与 Forge 1.20.1。离线验证覆盖本次调度回归及既有模块、传送、植被接续和 Voxy 兼容测试；未替换运行整合包，实际画面与卡顿改善仍需安装后确认。

## 开发回归

在对应平台项目根目录使用 Java 21（NeoForge）或 Java 17（Forge）执行：

```text
./gradlew -I tools/verification/dirty-handoff.gradle dirtyHandoffTest
```

覆盖更新通知、捕获提交、失败重试、旧任务拒绝、父级与植被交接、请求范围和列版本检查。末地修复可单独运行[末地回归入口](../worldgen/end-decoration-20261029.md)。
