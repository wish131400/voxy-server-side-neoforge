## 帮助与汉化

- 直接输入 `/vss` 或 `/vssclient` 显示帮助总览。
- `/vss help <子命令>`、`/vss 帮助 <中文子命令>` 显示用法、参数单位、示例和权限。
- 点击总览条目会填入详细帮助指令；Tab 补全包含英文与中文主题。
- 现有英文指令和中文别名均可使用，例如 `/vss 带宽 设置Mbps 20`。
- `/vssclient stats` 显示可翻译状态摘要，`/vssclient stats details` 显示技术计数。
- 中英文植被密度简介已删去城市模板绿化句子，不假定整合包安装失落的城市。

## /vss chunky

VSS 自带区域预生成，无需安装 Chunky 模组。任务生成真实 Minecraft FULL 区块，并保存供 Voxy 使用的真实远景列缓存。

坐标和半径全部使用方块单位，范围包含边界并向外取整到完整区块。

| 指令 | 行为 |
| --- | --- |
| `/vss chunky <x> <z> <radius>` | 指定中心和半径，生成正方形区域 |
| `/vss chunky start <x> <z> <radius>` | 同上 |
| `/vss chunky here <radius>` | 使用执行位置作为中心 |
| `/vss chunky rect <x1> <z1> <x2> <z2>` | 指定矩形角点，顺序不限 |
| `/vss chunky status` | 查看进度、可用/复用/失败/在途数量和耗时 |
| `/vss chunky pause` | 停止扫描新位置和提交新生成，已在途工作可完成 |
| `/vss chunky resume` | 继续任务 |
| `/vss chunky cancel` | 取消并释放生成回调、票据和工作记录，已有数据保留 |
| `/vss chunky limit [get]` | 查看预生成队列上限，无需存在活动任务 |
| `/vss chunky limit [set] <数量>` | 在线调整未完成列数上限并保存；0 为不限 |
| `/vss chunky limit unlimited` | 恢复不限队列并保存 |
| `/vss help chunky` | 查看完整说明 |

中文根命令为 `/vss 预生成`，支持 `开始`、`当前位置`、`矩形`、`状态`、`查看`、`暂停`、`继续`、`取消`。队列设置支持 `限速` 或 `队列上限`，例如 `/vss 预生成 限速 查看`、`/vss 预生成 限速 设置 32`、`/vss 预生成 限速 32`、`/vss 预生成 限速 不限`；英文和中文可以混合使用。

示例：

```text
/vss chunky 0 0 512
/vss 预生成 当前位置 256
/vss chunky rect -256 -256 255 255
/vss 预生成 状态
/vss chunky pause
/vss chunky resume
/execute in minecraft:the_nether run vss chunky 0 0 128
```

`0 0 512` 覆盖区块 -32 到 32，共 4,225 列；矩形 `-256 -256 255 255` 覆盖 32 × 32，共 1,024 列。负坐标向下取整，-1 方块属于 -1 区块。

## 队列上限与调度

可用 `/vss chunky limit 32` 或 `/vss 预生成 限速 32` 在线设置 `chunkyQueueLimit`，立即生效并保存到服务端 `config/vss-server-config.json`，不需要暂停任务或重启。默认 `0` 表示不限队列，正数表示扫描、生成、打包、写盘或本地导入中尚未完成的区块列总数上限。降低上限不取消已有工作，在途数降到新上限以下后自动补位；提高上限或设为 `0` 后后续调度继续领取位置。没有活动任务时也可以设置，供后续任务使用。直接编辑配置文件仍需关闭服务器或单人游戏后修改并重新启动，文件本身没有热重载。

领取位置与检查容量使用同一同步锁，多个扫描线程不会突破上限。满队列的扫描任务会退出，服务器后续 tick 在已有工作最终完成或失败释放名额后自动补位，不占用磁盘线程等待。重试和阶段切换继续占原名额，只有保存或导入确认后才计入成功并释放；不会跳过尚未领取的位置。`/vss chunky status` 显示在途数量和配置上限，0 表示不限。

该配置只作用于显式 chunky 任务，按列数控制积压，数值不代表线程数、CPU 百分比或每秒速度。老配置缺少字段时保持 0，升级不改变原默认行为。

chunky 只在用户配置正数 `chunkyQueueLimit` 时施加上述在途队列上限，仍豁免普通自动生成的并发配额、每 tick 启动/提交/完成数量上限和完成处理时间预算，不根据 FPS、TPS、CPU 使用率主动减速。预生成绕过日常单玩家和全服生成配额、打包快照内存预算、打包队列上限及磁盘读写队列限额。

缓存扫描在后台有容量时领取位置。游标按需创建工作记录，启动命令不会先在服务器主线程展开整个区域。多个扫描线程共享同步游标，每个位置只领取一次；取消时关闭游标，阻止旧线程继续领取。服务器线程只处理已就绪工作，不逐帧复制或遍历所有在途位置。

扫描、打包和磁盘线程在任务期间使用 JVM 可用的全部逻辑处理器，不再采用“核数 ×4、64–1024 并发、两倍流水线窗口”或半数核心策略。生成实际并行执行由 Minecraft 和整合包的世界生成实现负责。任务结束或取消后，共享执行器恢复日常设置。

`concurrency` 指令、中文并发别名、自动并发策略类、并发/容量状态文案和对应旧测试已删除。没有改为隐藏配置，也没有使用一个更大的数字替代原上限。

真实世界区块依旧通过 FULL 票据生成，服务端线程取得可变世界的安全快照，后台线程完成列打包。生成/写盘失败处理、版本校验和超时检测负责正确性；已有有效缓存先复用，新列等待写盘确认后才计入成功。

## 权限与生命周期

- 服务端 `/vss` 需要管理员权限 2；`/vssclient` 本机指令不需要管理员权限。
- 在命令源维度生成，控制台可使用 `execute in <维度> run vss ...`。
- 全服同时一个活动任务；半径 0–8,192 方块，矩形最多 4,194,304 列，完整范围必须在世界边界内。
- 要求开启 VSS、区块生成和持久远景缓存。
- 玩家移动、切换维度或离线不会取消任务；服务器停止时终止任务。
- 每 60 秒向发起者报告进度，任务结束时立即报告结果；状态指令可随时查看。
- 重启后可重新执行相同范围，复用已保存的有效缓存。
- 已保存数据按现有缓存保留/清理策略维护，客户端通过正常远景同步范围接收。

## 验证

以下为 2026-10-06 初版验证；2026-10-10 队列上限的实现与验证见 [chunky 可选队列上限](chunky-queue-limit-20261010.md)。

NeoForge 通过 70 项定向回归；Forge 通过 67 项，均为 0 失败、0 跳过。测试覆盖：

- 中英文指令解析、权限、帮助、格式占位符和删除并发设置后的命令树。
- 负坐标、矩形取整、区域遍历、范围与世界坐标校验。
- 5,000 个未完成位置仍可继续入队；多个扫描线程各位置仅领取一次。
- 取消关闭游标、重复/迟到回调不改变计数、成功/复用/失败分别统计。
- 显式任务绕过单玩家和全服在途/排队配额；取消归属后恢复日常规则。
- 磁盘读取和写入队列各接收 2,050 项任务，不受普通队列容量拒绝。
- NeoForge 显式打包超出日常快照内存预算仍可提交，并保持内存用量统计。
- 服务器停止拒绝新磁盘任务，拒绝时正确回滚计数，写盘确认校验正常。

两仓库构建及 `git diff --check` 通过，Forge 完成 `reobfJar`。JAR 已核对移除的策略类和文案不存在，60 秒报告说明正确。
