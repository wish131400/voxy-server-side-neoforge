## 配置和用法

服务端配置文件 `config/vss-server-config.json` 新增 `chunkyQueueLimit`，默认 `0` 不限制队列。旧配置没有该字段时也保持 0，加载时自动补齐字段和中文帮助。

```json
"chunkyQueueLimit": 32
```

正数表示 chunky 整条流水线中尚未完成的区块列总数上限，包含缓存扫描、等待生成、实际生成、后台打包、写盘和单人游戏的本地导入。一列最终保存或导入成功，或者达到重试上限判定失败后，才释放名额。

2026-10-14 增加在线设置：`/vss chunky limit [get]` 查看，`/vss chunky limit [set] <数量>` 设置，`/vss chunky limit unlimited` 恢复不限。中文为 `/vss 预生成 限速 [查看]`、`限速 [设置] <数量>`、`限速 不限`，也支持 `队列上限`。命令修改立即生效并保存，无需重启；没有活动任务时也可设置。直接修改配置文件仍需关闭服务器或单人游戏后修改对应实例配置，再重新启动，配置文件没有热重载。生成命令保持一致，例如 `/vss chunky 0 0 512`。`/vss chunky status` 显示队列上限，0 为不限，`/vss help chunky` 的中英文说明也已更新。在线设置的验证与产物见 [chunky 中英文队列指令](chunky-limit-commands-20261014.md)。

该参数控制未完成列数，不是线程数、CPU 占用目标或每秒生成速度。仅作用于显式 chunky，不影响日常自动生成；chunky 继续豁免普通自动生成的 MSPT 暂停、快照预算和并发配额。

## 调度行为

- 在 `ChunkyWorkQueue.reserve()` 内用同一同步锁检查上限并领取位置；满队列时不会推进区域游标，多扫描线程不会超过上限。
- 满队列时扫描任务返回，不占用磁盘线程等待；后续服务器 tick 处理完成回调并释放名额后，自动重启扫描补位。
- 不为阶段切换或重试重新预约名额；重复、迟到回调不会错误释放其他工作的名额。
- 队列通过轻量配置供应器读取 `volatile` 设置。如果内存中的配置被更新，降低上限时让已有工作继续完成、暂停新领取；提高上限或改回 0 后重新开放容量。
- 取消仍关闭游标并丢弃在途工作引用，旧回调不能恢复领取。
