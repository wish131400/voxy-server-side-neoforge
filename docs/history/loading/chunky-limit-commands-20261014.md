# chunky 中英文队列指令（2026-10-14）

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

Forge 1.20.1 与 NeoForge 1.21.1 同步增加在线设置 `chunkyQueueLimit` 的指令。默认仍为 0，不限制队列。

## 用法

| 操作 | 英文命令 | 中文命令 |
| --- | --- | --- |
| 查看队列上限 | `/vss chunky limit` 或 `/vss chunky limit get` | `/vss 预生成 限速` 或 `/vss 预生成 限速 查看` |
| 设置为 32 列 | `/vss chunky limit 32` 或 `/vss chunky limit set 32` | `/vss 预生成 限速 32` 或 `/vss 预生成 限速 设置 32` |
| 恢复不限 | `/vss chunky limit 0` 或 `/vss chunky limit unlimited` | `/vss 预生成 限速 0` 或 `/vss 预生成 限速 不限` |
| 查看完整帮助 | `/vss help chunky` | `/vss 帮助 预生成` |

中文 `限速` 也可以写成 `队列上限`。中英文根命令、设置名和动作可以混用，例如 `/vss chunky 限速 设置 32`。Tab 补全包含中英文别名，查看与修改反馈随客户端语言切换。

需要管理员权限 2，单人游戏需要开启作弊。命令不要求已有预生成任务；任务开始前、运行中、暂停时和结束后均可查看或调整。

## 生效与保存

命令修改内存中的服务端配置，并通过现有配置保存路径写入 `config/vss-server-config.json`。无需暂停任务或重启；既有任务继续读取同一个配置，后续任务也使用保存的值。

正数表示整个 chunky 流水线中尚未完成的区块列总数上限，覆盖扫描、等待生成、生成、打包、写盘或本地导入。这个数值不是线程数、CPU 百分比或每秒区块数。例如 32 表示允许最多 32 列未完成工作，不保证每秒生成 32 个区块。

降低上限不会取消或丢弃已有在途工作。如果当前在途数高于新上限，暂缓领取新位置，等已有工作完成、在途数低于上限后继续补位。提高上限或恢复 0 后，后续调度继续领取位置。原队列同步领取、游标、失败重试和完成确认规则继续生效。

输入范围为 0 至 2147483647；负数、小数或溢出整数会被命令解析器拒绝。没有管理员权限的命令源无法查看或修改这些服务端设置。普通自动生成的并发和性能预算不受该指令影响。

直接编辑配置文件仍没有热重载，需关闭服务端或单人游戏后修改并重新启动；在线调整请使用新增命令。

## 实现

- `VSSChunkyCommands` 增加 `limit` 的查看、直接数量、`get`、`set` 和 `unlimited` 分支。
- `VSSCommandHelp` 复用原别名机制，加入 `限速`、`队列上限`、`查看`、`设置` 和 `不限`，继承原管理员权限。
- 更新两种语言的反馈、帮助用法与示例，以及配置文件中 `chunkyQueueLimit` 的中文说明。
- 复用既有 `volatile` 配置和队列容量供应器，配置命令不依赖活动任务或服务初始化。
- 新增命令执行、JSON 保存、非法参数、权限和 Tab 补全回归，配合原 chunky 队列及普通生成预算测试验证。
