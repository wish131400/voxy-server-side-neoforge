# VSS 0.3.6

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

构建标识：`teleport-scheduling-20261028`。

传送到新区域后，优先补齐玩家周围 2048 格内的首份地形，再继续已有地形的细化和植被。保留距离排序、视角优先与每四次一次的公平轮转，远处地形仍会持续推进。

增加有界的中间区域粗覆盖需求，避免完全依赖 Voxy 节点的后续请求才开始补图。该需求与原有地平线覆盖共用生成、缓存和渲染路径。

首次地形最多为异步缓存探测预留 250 毫秒等待；探测拥堵时，工作线程仍先尝试恢复并校验实际缓存数据，再决定是否生成。传送时清理旧位置尚未开始的探测；已经执行的探测和缓存写入正常完成。

统一 Voxy 渲染下，完全离开当前视距的旧区域可直接回收，不再为了回收而生成其父层。仍在视距内的地形继续保留。

本构建同时包含跑图卡顿修复：将原先可能阻塞客户端线程的原生需求维护交给后台准备，并减少局部缓存失效及通知签名计算的重复工作。

提供 NeoForge 1.21.1、Forge 1.20.1 两个版本。离线回归覆盖任务调度、冷暖缓存、父层接续、内存回收和 Voxy 兼容性；实际传送后的显示时间仍需在游戏中确认。

两个平台使用相同的规划、距离优先级、粗覆盖和细化队列规则。任务排序不保证画面严格按距离依次出现：粗层计算量、缓存命中、真实列覆盖以及 Voxy 父子节点的构网与发布时机都会影响先显示的区域。旧流程仅主动请求地平线粗覆盖，中间区域依赖后续原生细分需求；本次为附近空白区域提供独立初始需求，减少该依赖造成的等待。
