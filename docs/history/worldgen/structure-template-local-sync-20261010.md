# 客户端模板读取、服务器校验与按需补发（2026-10-10）

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

已同步实现 NeoForge 1.21.1 和 Forge 1.20.1。新包包含前一轮 issue #9 的可选 Codec 故障隔离，以及本轮模板获取、补发、缓存和 NBT 树木桥接。交付产物以独立构建目录生成，生产源码保存在两个工作区；没有提交或推送 GitHub，也没有替换、启动用户的客户端。

## 玩家能看到的变化

客户端安装了相同的原版或模组资源时，可以直接读取建筑和树木模板。VSS 先核对服务器提供的哈希，内容一致才使用；服务器数据包、KubeJS 或模组版本改动了模板时，以服务器内容为准，只补发需要的模板。已有本地模板不再跟着世界生成档案重复传输。

取消旧的单模板 512 KiB、全部模板 5 MiB 截断。因此，模板数量多的整合包和大型建筑不会再单纯因为排在目录后面或文件较大而被丢掉。

等待补发的预测任务会延后重试，保留已有远景。等待状态不会被当作无效建筑起点，也不会保存成空植被或半成品建筑。表面和成品网格缓存加入模板目录身份，旧版缺少模板时写出的空结果会重新生成；已有地形采样缓存可继续复用。

## 纳入的适配范围

按 `ResourceLocation` 读取全部命名空间，没有针对模组名称的白名单。凡是通过既有结构预测入口访问标准 NBT 模板的模组，都使用同一套校验和补发流程，包括原版村庄、末地城及前面核对的 Moog 系列、ChoiceTheorem's Overhauled Village、Repurposed Structures、YUNG 系列、When Dungeons Arise、Valhelsia Structures 等。

BWG / Oh The Trees You'll Grow 的 `TreeFromStructureNBTFeature` 和 V2 增加可选桥接。虚拟预测世界取得共享模板管理器，不再要求真实 `ServerLevel`；正常世界的调用继续转发原接口。核对的实际版本为 NeoForge 1.21.1 的 OTTYG 5.3.2、Forge 1.20.1 的 OTTYG 1.7.3。Forge 的 MC 调用目标进入 refmap，发行包已完成重混淆。

Lost Cities 使用自己的城市资产和计划同步格式，继续使用既有适配。TerraBlender、Tectonic、FreeTerraForged、Epic Terrain 等现有地形后端的 Java 装饰上下文可通过本轮共同入口取得 NBT 模板；它们的地形算法没有因本轮改动而重写。

本轮解决的是模板资源获取。之前审计发现的自定义维度生成器、暮色地标放置、部分结构生成阶段、虚拟查询范围及后处理接口，仍需要各自适配。目录中存在模板不等于对应建筑已经在游戏内逐坐标验证；不能把完整模板目录解释为 ATM 全整包预测兼容。

## 实现要点

- 服务器在一个资源生命周期内流式计算有效资源的 SHA-256 和长度，跨维度复用目录；保存资源句柄和身份，不保留整套 NBT 文件字节。
- NeoForge 使用 `data/<namespace>/structure/`；Forge 使用 `data/<namespace>/structures/`。
- 客户端从原版 SERVER_DATA、已安装模组 JAR 和开发环境类路径找候选资源。每个候选均须匹配服务器指定的完整文件哈希和长度，客户端资源顺序不承担权威作用。
- 本地读取、文件哈希、大模板分片组装与校验放在独立 I/O 线程。预测工作线程遇到未就绪模板时抛出既有 `PredictionWorkDeferred`；建筑和植被路径传播该信号并回滚事务。
- 缺失模板以 128 KiB 分片发送。客户端每次请求一个资源，服务器每玩家保留一个传输，遵守现有 Netty / Bandwidth Optimizer 背压；前一个分片编码完成才继续发送。每 tick 全局最多 8 个分片。
- 重复相同分片不增加完成数量，内容冲突、长度错误或完整文件哈希不匹配不会发布。暂时不可用回复退避 2 秒再试；传输超时可以重试。
- 原始文件内存缓存目标 32 MiB，内容寻址磁盘缓存目标 512 MiB；下载按哈希原子写入，读取时重新校验。单压缩模板最多 16 MiB。NBT 解码最多 512 MiB 的 accounting 用量，普通解码缓存目标 64 MiB，允许一条超过普通目标的大模板；这是解析计量，并非客户端总内存上限。
- 断线、预测能力关闭、服务器退出和资源重载会清理对应状态，迟到的旧目录传输不能重新发布。服务器清理不会让旧 I/O 任务重新插入传输。
- 新网络协议为 **51**，世界生成档案格式为 **4**，服务器和客户端需要使用同一轮新包。

## 实际验证

使用此前 ATM 10 8.2 审计中校验过发行哈希的 57 个 JAR：12,508 个唯一模板全部进入目录，原始 JSON 为 1,777,733 字节，DEFLATE 后为 654,581 字节。原文件累计约 137.911 MiB，按需读取和补发；这个资源级验证不是完整 ATM 运行实例的生成计数。

实际大型资源解码通过：

| 模板 | 压缩文件字节 | NBT accounting 字节 |
| --- | ---: | ---: |
| WDA `dungeons_arise:kisegi_sanctuary/kisegi_sanctuary_main_0` | 3,939,141 | 334,765,724 |
| YUNG `betteroceanmonuments:start` | 1,749,146 | 150,635,970 |

测试覆盖本地零补发、版本不一致补发、乱序/重复/冲突分片、损坏磁盘缓存、退避/超时、服务器背压/编码交接/注销、旧目录清理、村庄起点延后恢复、植被事务回滚、表面/成品网格目录身份、普通缓存及 issue #9 的实际 Mo Structures Codec 回归。OTTYG 两个 Feature 的发行字节码调用链与桥接处理经过检查；没有启动完整 Minecraft 实例进行 Mixin 转换及 BWG 森林的实景对照。

构建与测试结果、文件 SHA-256 见同目录 `structure-template-validation-20261010.json`。JAR 放在各仓库 `lib/templates-20261010/`。
