# 当前预测生成耗时分布（2026-11-02 复算）

当前生成路径最大的已测成本是装饰触发的精确地表查询，占总生成耗时的 **47.12%**。Java 群系查询占 **10.38%**，装饰显示地表查询占 **5.39%**。三项合计 **62.89%**；这些时间原本都计在装饰阶段内，不能据“装饰占九成”推断九成时间都在构造树木或写方块。

## 数据边界与校验

本次重新汇总 2026-11-01 最近正式库的已保存记录，没有重新运行游戏。构建为 `20261101-density-dependencies`，VSS 0.3.7，Windows x86_64、Java 21.0.6、NeoForge 1.21.1 实际运行时、原版主世界种子 42。

每次处理 16×16 个目标区块（256×256 方块），装饰包含一圈来源边界，共 18×18=324 个来源区块；显示间距 4。五个不同区域各重复两次，共十条正式记录，每组另有两次预热。这里的两个重复组不是十个独立区域。单生成线程，排除世界上下文准备和摘要计算，没有渲染、调度排队或磁盘缓存读取。

复算前逐一核对：472 个生产 Java 源文件、18 个资源文件、7 个实现覆盖文件、477 个带计时的快照 Java 文件、46 个 Rust 文件及两个输入文件，全部与保存的校验值一致。七个实现覆盖文件属于前述生产文件的子集。当前及测试 DLL 的 SHA256 均为 `2ad535c6ff24b469ca9cb127a6bab73882bb32a1e49fedac3a9e6d89897527d1`。

两个旧正式库对照的同区域输出摘要，与这十条记录逐一一致。候选组没有同进程 baseline，所以其 `matchesBaseline:false` 表示该进程没有建立 baseline 字典；跨目录比较地形列/群系、装饰方块位置/状态和体素包围盒摘要全部一致。

实验副本固定了原来用于原生 shuffle 的外部随机熵以便复测，另有查询归因计时；没有减少采样或跳过无写入尝试。保留当前预测实现的兼容边界；这不是全部群系模组、所有结构或 Forge 的独立性能验收。

## 互不重叠的总生成分布

以十条正式记录的总时间为分母，平均 **3646.79 ms/区域**，区域实测范围 **3381.24–3911.02 ms**。下面各行相加为总时间，各行独立计算后显示的小数存在舍入误差。

| 环节 | 平均 ms/区域 | 占总生成时间 |
| --- | ---: | ---: |
| 初始显示地形采样 | 254.83 | 6.99% |
| 装饰/结构触发的精确地表查询 | 1718.38 | 47.12% |
| 装饰中的 Java 群系查询 | 378.37 | 10.38% |
| 装饰/提取触发的显示地表查询 | 196.68 | 5.39% |
| 原生 Feature 调用，含其内部查询 | 451.50 | 12.38% |
| 其余 Feature 工作，扣除以上已计查询及原生调用 | 390.06 | 10.70% |
| 结构工作，扣除以上已计查询 | 145.87 | 4.00% |
| 结果提取与竹子整理，扣除以上已计查询 | 21.90 | 0.60% |
| 树叶状态整理 | 24.28 | 0.67% |
| 装饰阶段未单独覆盖的工作 | 58.60 | 1.61% |
| 构造 Voxy 输入数据（列和包围盒） | 6.31 | 0.17% |
| **合计** | **3646.79** | **100.00%** |

按原始三阶段分组：显示地形 254.83 ms（6.99%），装饰总计 3385.66 ms（92.84%），Voxy 输入构造 6.31 ms（0.17%）。上表装饰各细项已包含在装饰总计内，不能再与总计相加。

“精确地表查询”计时包围 `surfacePoints` 调用，包括 Rust 内部实际工作，而非仅 Java/Rust 边界成本。它包含按需计算精确列时发生的密度、邻列几何、地表规则、原生群系和材质整理。初始显示地形很快，不能据此推断装饰随后补算的精确地形也很快。

“显示地表查询”是装饰读取的简化地表记录，不含初始显示地形采样；其内部仍可能走精确回退。原生 Feature 的 451.50 ms 包含其自己的地表/群系查询，尚未拆成纯放置与内部查询，不能称为纯植被构造。其余 Feature 390.06 ms 包括 Java 放置逻辑、缓存访问、序列化、编辑应用以及失败回退等，不是纯方块写入时间。

原生 Feature 使用现有成功调用累计毫秒计数，取相邻记录之差；毫秒截断误差留在余项。代理创建、上传、读取编辑结果等子计时不重复加入总表。未覆盖的 58.60 ms 包括初始化、来源/缓存合并、复制和计时归因开销，不能全部归咎于调度器。

## 查询、无写入尝试与传输

- 每区域 Java 精确请求 **85916.8** 个坐标点，已记录的重复坐标为 **0**。这不能排除 Rust 内部节点、插值输入或邻域计算重复，也不能证明 4×4 页内每一点都被实际需要。
- 被计时的 Java 群系调用平均 **132486** 次，其中实际 `BiomeSource` 计算 **125262.6** 次；后者耗时 **345.56 ms**，已包含在群系查询 **378.37 ms** 内。两者之差约 **32.80 ms**，含缓存/封装及计时开销，不能称为纯锁开销。
- 每区域 Feature 尝试 **35316** 次，其中 **34464.6** 次（**97.59%**）没有 journal 写入。这些尝试累计 **2299.55 ms**，包括 **1279.93 ms** 精确地表查询。这些是前表成本的子集；无写入并不意味着可安全删掉，仍须保留随机流、过滤语义及首次查询依赖。
- 原生阶段累计计数取差：代理创建 **14.6 ms**，编辑上传 **16.2 ms**，读取编辑结果 **11.8 ms**。这些与 Feature 耗时重叠，不能再相加；读取计时未覆盖随后在 Java 校验并应用编辑的全部时间。这里没有证据把主要瓶颈归为数据跨边界传输。
- 生成线程平均 CPU 时间 **3614.06 ms/区域**，约为墙钟时间的 **99.10%**；全进程 CPU 时间 **4029.69 ms/区域** 包含 JIT/GC 等其他线程。单线程基准呈现计算瓶颈，不能据此判断实机游戏是否有多线程争用。Java 线程分配平均 **519.31 MiB/区域**，GC 计数增量平均 **4 ms/区域**；分配量不是常驻堆或原生内存大小。

## 目前能够支持的优化判断

第一优先级仍是通用精确地表查询路径及其按需范围，然后是装饰群系查询。沙盘/冰刺/森林岩石的完整时间主要来自它们触发的精确地表查询；洞穴藤蔓主要触发群系查询。只优化方块集合整理或树叶收尾，覆盖的总时间较少。

仅作固定其他成本的估算：把精确地表阶段减半，总时间约从 3.65 秒降到 2.79 秒（减少 23.56%，吞吐约 1.31 倍）；把其余 Feature 的 390 ms 减半，总时间仅减少约 5.35%。这说明优化应以实际大头为准，不保证任何方案必然达到减半。

目前不能从这批记录可靠分出最新版的“纯噪声 / 密度图分派 / 邻域几何 / 地表规则 / 含水层”的互斥百分比。已有深层 Rust 计时来自更早诊断构建，且带嵌套计时和原子计数开销，因此本报告不将其绝对毫秒或比例套到最新版。Voxy 网格生成、GPU 上传/绘制、磁盘读取、网络、实际游玩帧时间也不在这批记录中。
