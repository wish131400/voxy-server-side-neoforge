**预测持续加载的主线程成本：实现、收益筛选与双平台交付（2026-10-14，0.3.5）**

本轮接续 main-reduction-20261014，针对“关闭预测加载提高约 20 FPS”检查到的剩余加载路径完成优化。没有运行中的 Minecraft 客户端，因此没有做真实游戏 FPS 对照。本轮用生产辅助类与保存的旧实现／旧算法回放对照来筛选 CPU 改动；测试数量不代表现场场景或收益比例。

**保留的实现**

1. PredictionRenderResidency 在至少 512 瓦片的源集合中使用分页快照差异，仅更新被替换／删除的 key；pendingSlots 配合交换删除维护待上传列表。GPU 淘汰会在相同源快照中立刻重新入队。保留父级、植被和缩视距安全回退；两处消费完差异后释放上一版快照引用。小集合仍用旧扫描。
2. PredictionUploadSelection 对大于 512 项 backlog 选取排序最靠前的 20 项，足够覆盖原每帧最多 16 上传与最多 4 冷恢复尝试。优先级和同一输入中的并列顺序与完整稳定排序一致；资格在筛选时和实际上传前检查。小集合保留旧过滤／复制／排序。没有改变 4 MiB / 2 ms 的原上传窗口，oversized 首项继续推进。
3. Scene 接缝输入改为不可变分页 Surface 表，由 stagedKeys 更新。Builder 按页差异应用输入，worker 计算 masks、LOD 接缝和真实边缘接缝的发布差异；差异以最后被渲染线程接受的结果为基准。被丢弃的 job 不会让下一帧漏更新。主线程只处理变化 mask／patch，旧 GPU 和整套覆盖保留到交接就绪。
4. PredictionLoadingPreparation 把加载进度、foreground debt、preview／surface preview 和遮挡优先级扫描放到已有低优先级控制线程，复用调度输入。仅在显示目标变化时复制目标表，稳态复用不可变表。没有增加独立计算线程、读取 Minecraft 可变区块或执行 GL。发布检查计划、内容版本、驻留快照、GPU 可绘制快照、视角和布局；捕获／城市脏状态另带版本，拒绝旧完成状态。mesh limit 重试语义保留。
5. desiredSnapshot 按需求版本复用，不在需求和调度入口重复 Set.copyOf；归属规划已拥有不可变驻留快照，驻留 key 加入候选的工作移到 worker。普通接纳持有 manager 锁时批量清理 pending 子集一次，单独接纳继续清理；完成和取消仍逐 key 移除。
6. 回归发现样本缓存溢出会随机淘汰唯一的真实捕获样本，在 rememberTerrain=false 时可能用预测地形替换真实空列。缓存现在优先删可重算的预测样本，条件删除避免把并发替换的新捕获删掉；只有捕获占满缓存时才淘汰捕获，容量上限仍保持。此项是正确性修复，未当作 FPS 收益。

**撤回／保留原路径的尝试**

- 小集合增量 pending 索引没有收益，512 瓦片以下恢复原扫描及重建。
- 小 backlog 的新简单筛选在 256 项对照中变慢，512 项以内恢复原过滤、复制、完整排序，只增加返回前缀的轻量视图。
- 把准备耗时加入上传限流无法证明改善整帧，可能延长加载，已撤回；保留 uploadPreparationUs 诊断。
- 初版分页差异遍历产生逐项临时对象，改用 fastIterator，并让两处差异消费共用结果缓存；未保留该高分配版本。

**收益基准方法与限制**

每项先 16 轮预热，再 21 轮交错旧／新顺序计时。驻留回放每轮 160 帧、每帧 8 变化；其他路径每个计时批次 32 次调用，减少 Windows 时钟噪声。两平台最终基准串行独占执行，没有另一份构建／回归争 CPU。记录中位数、批次平均的 p95、当前测试线程分配量以及粗粒度线程 CPU 时间。CPU 计时出现 0 是分辨率限制，不表示没有 CPU 工作。

旧驻留类从本轮原始源码保留并改名；上传使用生产优先级比较；接缝输入比较旧全量 Surface 和 Map.copyOf 与新 8 项分页更新。加载统计旧算法保持可变 goals，不使用增加了额外复制的测试适配器；旧 ready 查询使用 manager 的实际 ConcurrentHashMap。加载 fixture 设置每 16 瓦片一个捕获 epoch。所有比较保持结果语义校验。

这些是固定 fixture 的方法耗时，不是完整一帧、不是实际加载吞吐，也不是当前客户端的瓦片数量。稳态输入构建复用已经存在的 scheduling 快照，只计新增 loading 快照成本；原有调度输入复制仍存在。后台遍历成本单独报告，不能把迁出主线程当成总 CPU 成本消失。各行触发时机不同，不应相加或换算成 FPS。

**剩余主线程成本和现场验证**

主线程仍需取得不可变调度输入、接收规划集合、核验当前资源限制、维护 Minecraft 可变覆盖、准备可见提交、上传几何和原子接缝交接。需求结果接受仍做集合校验，捕获 epoch／失败信息等快照仍有复制。实际世界线程和地形工作线程竞争、渲染线程等待 GPU、Iris 逐瓦片提交及 GPU 几何量仍要现场测量。本轮没有改变视觉质量、植被密度或 LOD 距离来制造收益。

用户自行替换和启动；未修改整合包、未推送 GitHub。对照同档同视角：稳定静止、持续加载、跑图／转向、真实接管与撤销、传送／重生、望远镜和资源重载。观察 CLIENT_SCHEDULE、PREPARE_TOTAL、UPLOAD、loadingJobs / loadingCommits / loadingDiscards / loadingPrepareNanos 和 uploadPreparationUs。需同时看任务完成率及 GPU 时间，不能仅凭关闭加载后的约 20 FPS 推断全是主线程开销。
