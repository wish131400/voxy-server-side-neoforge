# 高度扫描的精确空气证明与含水层邻域复用（2026-11-02）

高度扫描仍有可以少算且保持现有精确结果的部分。本轮从冻结副本实现两项原型：放宽过强的含水层等水位条件，以及在下降扫描时复用候选含水层中心。两轮交替完整路径测试中，前者使完整耗时减少 **7.04%**；组合减少 **9.30%**，其中精确地表查询减少 **15.45%**。

本轮仅新增实验工具、隔离副本和历史记录，没有修改生产源码或发布 JAR。另一对话独立完成气候共享的多版本发布，本原型不混入该发布。这里的基准是上一轮气候共享实验方案，本轮没有开启前一轮按规则需求准备地表数据或矿脉高度提前排除，收益不能相加。

## 原判断为什么可以放宽

`Job::surface_top` 查找最高非空气块，原流程已经通过 `proven_air_bottom` 尝试跳过确定为空气的插值单元。密度必须有严格负上界，结构调整、未知范围及顺序敏感查询仍沿用原回退。

含水层还可能把负密度区域变成水、熔岩或压力形成的实心块。原证明要求覆盖全部可能最近三点的含水层候选：每个候选在区间底部都是空气，且其水位完全相同。相同水位可使压力为零，但不是唯一能证明空气的条件。

本原型保留原来的等水位证明，并增加一个条件：**全部候选在区间底部均为空气，而且底部至少高出所有候选水位五格**。满足时允许水位不同；不满足时按原样逐格检查。

这一条件来自现有 `pressure` 公式。对于任意两个候选水位 `a,b`，令 `H=max(a,b)`，在 `y>=H+5` 时：

```text
offset = y + 0.5 - (a+b)/2 > 0
edge   = abs(a-b)/2 - offset = H-y-0.5 <= -5.5
pressure 的几何项 = edge/2.5 <= -2.2
```

几何项已在 `[-2,2]` 外，原函数不会读取 barrier noise，最终压力非正。候选在底部为空气意味着在更高 Y 也为空气；严格负的密度加上非负相似度权重乘以非正压力，不能触发实心块分支。这是对整个区间和完整候选集合的证明，没有取样猜测，也没有高度单调性假设。

原有全局熔岩检查、密度证明、结构/状态回退都保留。五格是该分支可直接证明的边界，不是容许五格误差。靠近水位、无法证明的洞穴和未知表达式继续原逻辑。双精度和原表达式求值顺序没有改变。

## 含水层候选复用

同一个 X/Z、同一 `(y+1).div_euclid(12)` 网格内，原循环的 12 个含水层中心不变，中心到该列的水平距离平方也不变。逐格下降时无需反复向位置缓存查询这些中心或重算水平距离。

原型在每个 Job 中保留一份固定数组，键为实际 X/Z 与该 Y 网格。换列或跨网格时重建；每个 Y 仍重新计算垂直距离、排序最近三点，并保留原来的候选枚举顺序及 `>=` 平局处理。后续流体状态、压力和方块答案继续原实现。

该复用也作用于保留表层等流程中的含水层调用，因此组合收益不能全归因于找顶高本身。数组不跨世界、不形成无界坐标缓存；挂起/恢复 Job 时重新初始化这份可重建数据。

## 条件和实际完整路径

- AMD Ryzen 7 7700，8 核 16 线程；Windows x86_64、Java 21.0.6、Minecraft 1.21.1 / NeoForge 21.1.234。
- 原版主世界，种子 42，单生成线程，显示采样间距四格。
- 五片固定正式区域，每片 16×16 个目标区块；装饰包含一圈来源边界，共 18×18 个来源区块。
- 实际 NeoForge 运行时执行显示地形 → 原有结构与装饰 → 植被整理、提取 → `PredictionVoxySource.build` 地形列和包围盒。
- 包含缓存查询、缺失后计算、跨语言调用及 CPU 结果整理；上下文初始化和输出哈希不计入计时。
- 不减少候选、采样精度或装饰密度，不修改群系答案或 Feature 随机顺序。不是渲染、GPU、磁盘缓存读取或调度队列测试。

两轮各有两片预热、五片正式区域；每个模式保留独立上下文，按区域交替执行。第二轮反转两项候选的模式列表，奇数区域还反转上下文执行顺序。同一已验证 DLL 和源码跨两轮复用，正式计时与另一对话的编译/计时错开。

## 性能结果

以 `cross`（上一轮水平气候复用）为本轮直接对照，以下为两轮各五片的合计均值。

| 方案 | 完整耗时 ms/区域 | 精确地表 ms/区域 | 完整耗时减少 | 精确地表耗时减少 |
| --- | ---: | ---: | ---: | ---: |
| 气候复用对照 | 3536.427 | 1770.868 | — | — |
| 增加精确空气证明 | 3287.362 | 1591.943 | **7.04%** | **10.10%** |
| 再加含水层候选复用 | 3207.476 | 1497.231 | **9.30%** | **15.45%** |

空气证明每区域完整路径平均减少 249.065 ms；组合减少 328.951 ms。组合相对空气证明组进一步减少完整耗时约 **2.43%**，不是单独开启候选复用的结果。组合生成线程 CPU 时间由 3443.750 ms 降至 3156.250 ms，减少 **8.35%**。

第一轮空气证明/组合完整耗时分别减少 6.81% / 9.62%，第二轮为 7.27% / 9.00%。十个同坐标配对区域中，两种候选均更快；组合单片减少 0.94%–16.60%。区域差异较大，不能据此保证任意地图或整合包都有相同比例收益。完整吞吐约提高 10.26%，不代表游戏 FPS 同比增加。

Java 当前线程分配仍约 517.4 MiB/区域，没有通过此算法减少大量临时对象。组合精确地表仍占总耗时约 46.68%，后续还有计算，但本轮没有测出更多改造的收益。

## 正确性核验

- 两轮各 20 次正式完整生成，共 **40 次性能组生成**，以及独立计数副本的 **20 次诊断生成**，最终摘要全部匹配同进程基线及上一轮五个固定 oracle。预热输出也全部匹配。
- 各正式区域的精确请求点数、请求次数、Java 群系请求数、装饰方块数、Voxy feature box 数均与对照一致。
- 输出摘要覆盖装饰方块位置/BlockState、地形列群系/区间/BlockState、Voxy 包围盒。这里证明相对现有预测路径的一致性，不声称与完整真实存档所有方块逐一相同，也不是像素比较。
- 四项空气证明测试通过：真实 `pressure` 函数边界对照；水位附近应拒绝的条件；逐格 `block` 高度 oracle；单格浮空层和抬高水面。逐格高度共对照 200 列，包含两种种子及远坐标。
- 最近三点测试通过：两种种子、七组 X/Z、384 个 Y，共 **5376 次**候选坐标和整数距离完全一致，保留原平局语义。
- 四项广泛地表测试通过：合计 **21964 组十字段列记录**，包括主世界、下界、末地、放大世界、两种种子、区块边界、反向访问、显示/精确混用与重访、合成自定义命名空间规则和状态节点回退。该矩阵同时开启空气证明与候选复用。
- 共九项唯一原生测试在 B 副本执行通过。C 复用同源码、同 DLL，携带 B 的测试日志作为对应实现证据，并未声称在 C 独立重跑了九项测试。

未独立测 Forge、多线程竞争、全部群系模组的完整运行时，以及 FP32 新版原生实现。五格阈值和证明仅针对这里核对的含水层压力公式，移植到不同算法版本时需要重新核对。

## 产物与复现

工具位于 `tools/performance/height-air/`：

- `dry.rs`：空气证明及四项测试。
- `nearby.rs`：固定候选数组及原循环差分测试。
- `prepare.py`：只为冻结实验副本增加可选开关，另生成四项广泛地表测试。
- `run.py`：构建、正确性测试及真实 NeoForge 完整路径；支持 `--reverse` 和独立计数副本的 `--diagnostic`。
- `trace.py`：向单独副本添加十项入口计数，不使用其耗时判断收益。
- `summarize.py`：核对成功标记、无失败标记、固定 oracle、计数及两个性能副本源码/DLL/输入一致性。
- `results-20261102.json`：完整原始正式计时、配对变化、计数、测试日志、源码/DLL/输入及 Feature 明细哈希。
