# Cluster 层级与 Mesh Shader 实验（2026-10-12）

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

本轮落实六步计划的第 5、6 步为可执行实验，未将缺少明确正收益的候选加入生产。前四步的 LOD、植被选择、真实 MDI 范围缩减继续保留。

## 方法与范围

- 两个仓库分别编译运行，NeoForge 使用 Java 21，Forge 使用 Java 17；GPU 测试顺序执行，Minecraft 未运行。
- RTX 4070 Ti SUPER / OpenGL 4.6 / NVIDIA 572.70。确认 `GL_NV_mesh_shader` 与间接命令计数可用；输出上限 256 顶点 / 512 图元。
- 隐藏 256×256 目标，24 轮暖机、81 轮轮换顺序的测量。采用 GPU 时间查询；测试中的同步结果读取只用于实验。
- 剔除实验有 2,048 / 8,192 条命令，每条 256 面，包含全遮挡、半遮挡、无遮挡、遮挡中有孔洞四种情况。命令空间顺序被打散，包围盒按生产逻辑扩张 2 方块。
- GPU 时间包含当前帧 Hi-Z 构建、剔除、压缩（适用时）和绘制。Mesh Shader 使用实际几何解码、批次记录、归属和材质代码，对比顶点阶段及完整光栅。
- 比较各路径的颜色与深度，检查压缩结果数量。全部最终候选在两个加载器的实验均通过画面一致性检查。
- 这些是合成工作负载，不是存档 FPS。没有证明所有 Cluster / Mesh Shader 实现均无收益；结论仅适用于本轮方案及显卡。

## 第 5 步：空间分组、层级与命令组织

实验包括 Morton 空间父节点、每 16 个父节点再加一级、空间顺序/原顺序命令压缩、隐藏命令仅写零数量、以及整批为空时 GPU 原生计数跳过。

空间分组通过独立索引表映射回原命令，不更改 baseInstance；固定槽路径保持命令顺序。原顺序压缩保留序列，空间压缩只作为不透明实验。透明水面未被重排。

下表为 8,192 命令的 NeoForge 完整 GPU 时间，单位 ms；数值不能作为实际游戏帧时间：

| 场景 | 旧路径 | 空间父节点 | 再加一级 | 原顺序压缩 |
|---|---:|---:|---:|---:|
| 全遮挡 | 0.056320 | 0.054272 | 0.056320 | 0.081920 |
| 半遮挡 | 0.440320 | 0.432128 | 0.438272 | 0.494592 |
| 无遮挡 | 0.671744 | 0.673792 | 0.678912 | 0.724992 |
| 孔洞 | 0.662528 | 0.661504 | 0.668672 | 0.715776 |

早期单轮全遮挡对照曾节省约 0.03 ms；完整变体复测后，该收益未稳定重现，原路径本身的全遮挡时间也明显变化，因此不能用早期数字认定可靠收益。半遮挡、开阔和孔洞场景的压缩回退则反复出现。空间压缩还会改变索引访问局部性，回退更大。当前没有验证过能避免这些回退的自动启用规则，因此没有默认启用。

空间分组和新增层级只有小幅差异；隐藏命令少写几个字段也未取得足够明显收益。项目现有择路使用完整不透明阶段，以 0.08 ms 与 4% 中较大者为差异门槛，这些小差异不足以支持增加生产复杂度。

整批跳过额外需要计数缓冲清零、原子更新和间接计数读取，本轮同样比旧路径慢。两个加载器的这一项与 Mesh Shader 最终变体结果一致。

## 第 6 步：Mesh Shader

验证了两个 NV 原型：16 面一组的顶点解码迁移；32 面一组、每线程处理完整四边形，并把平坦属性改为逐图元输出。后者保留两组三角形各自的末顶点属性，避免改变原来的平坦插值。

完整光栅对比使用相同批次记录和归属处理。第一版曾用单瓦片 uniform 绕过批次访问，看到约 18–20% 的改善；该条件不等价，已从后端收益结论排除。修正为 BatchEnabled=true 后，该改善消失。

| 平台 / 32 面变体 | 现有 MDI 完整光栅 ms | Mesh Shader ms |
|---|---:|---:|
| neoforge / 植被 | 4.952064 | 5.400576 |
| neoforge / 地形 | 1.429504 | 1.907712 |
| forge / 植被 | 4.961280 | 5.417984 |
| forge / 地形 | 1.428480 | 1.908736 |

植被测试实际提交 2,097,152 面，地形 1,048,576 面。顶点阶段也出现明显回退。CPU 提交数字仅用于诊断：MDI 测试逐条重放输入，NV 使用预生成测试输入；它不能证明游戏主线程收益。

这些原型没有接入游戏、Iris、透明水面或生产后端选择。未完成的兼容项不被计为通过；由于公平的 GPU 对照没有正收益，本轮停止集成。

## 保留、同步与复现

- 本轮没有新增生产优化。三个生产核心文件与实验前逐字节一致；没有撤销此前已验证的四步 LOD 改动。
- 不成功的候选仅放在 `tools/prediction/cluster-render-experiments/src/`，独立 source set 编译，不进入主 source set 或发布 JAR。
- 两仓库同步实验工具、原始 CSV、报告。Forge 材料测试保留 `Blocks.GRASS`，NeoForge 使用 `Blocks.SHORT_GRASS`。
- `round1/` 保留较紧的初始包围盒数据；`round2/` 加入生产扩张；`mesh-fair/` 保存等价的 16 面后端；`final-csv/` 保存最终每平台数据。
- 各路径时间和判定见同名 JSON。候选不存在保留的生产行为，因此本轮不重复发布相同 JAR。

NeoForge 重现完整实验：

```powershell
$env:JAVA_HOME = "C:/Program Files/Java/jdk-21"
.\gradlew.bat --offline --no-daemon --max-workers=2 --project-cache-dir .gradle-vss-cluster-render-20261012 -I tools/prediction/cluster-render-tests.gradle -PclusterAllModes=true clusterRenderGpuTest --tests "*PredictionClusterArchitectureGpuTest" --tests "*PredictionMeshShaderExperimentGpuTest"
```

Forge 使用同一命令，但 `JAVA_HOME` 设为 JDK 17，增加 `"-Dorg.gradle.java.home=C:/Program Files/Java/jdk-17"`。
