# 4096 格外的模板散布与简化环境：完整 CPU 生成实验（2026-11-03）

在隔离的实际 NeoForge 运行时中，远区原型使“Rust 显示地形 → 装饰与结构 → 整理 → Voxy CPU 输入”的耗时减少 **60.82%–63.68%**，对应 **2.55–2.75 倍**的生成速度。仅替换树木/草花散布、保留原环境查询时，收益只有约 6%–8%。主要收益来自远区使用简化环境，以及重复查询共享固定的粗网格地表。

这是允许改变远区装饰的实验结果。它没有保持同种子逐方块一致，也没有证明游戏帧率或整圈远景加载提高同样倍数。本轮只添加实验工具和记录，未改生产 Java/Rust、配置默认值、原生库或发布 JAR。

## 距离策略与实验范围

用户确定的策略是：以玩家为中心，4096 格内保留现有计算，4096 格外使用群系规则、种子和稳定坐标散布模板。4096 是内区半径，不能代替总预测距离。

生产 `VSSClientConfig.predictionDistanceBlocks` 当前默认也是 4096；总距离仍为 4096 时没有外区，因而不会获得本方案的外区收益。本实验预先选定远区样本，**没有接入移动距离判定、调度队列、区域晋升、磁盘质量标识或真实区块接管**，也没有偷偷扩大总预测视距。

- Windows x86_64、Ryzen 7 7700、Java 21.0.6、Minecraft 1.21.1 / NeoForge 21.1.234，单条生成调用链。
- 从本项目当前生产源码和随包原生库冻结实验副本；没有使用旧实验中缺少气候绑定的基线。
- 原版主世界、种子 42；每片 16×16 个目标区块，现有回退装饰仍包含 18×18、324 个来源区块。
- 两轮各五片正式区域、各模式两片预热，地形步长 4、8。各步长使用不同坐标；第二轮反转模式顺序，单轮奇数区域也反转顺序。
- 共 112 行完整调用，含 80 行正式计时。每个步长是五片独立地形的两次重复，不是十片独立地形。
- 包含初始化后未命中的实际地形计算、剩余 Feature、结构、模板散布、整理和 CPU 侧 Voxy Tile/盒子/索引构造。没有磁盘装饰缓存命中。
- 模板解析/捕获单独计费；输出哈希、画质统计和代表区段映射校验在计时外。
- 不含客户端排队、磁盘读写、网络、Voxy 网格构建、GPU 上传与渲染。没有测多线程实际吞吐或各种模组整合包。

实际使用的 Windows 原生 DLL SHA-256 为 `de7a75ae179a067b80306d8ca493909e5ca4dffe289b3ea2c346e129e647ab6e`。处理后运行资源与冻结输入一致，所有诊断均确认水平气候共享实际进入。移除已声明的实验钩子后，503 个生产源码/资源文件与主项目一致。

## 四个对照模式

| 模式 | 装饰散布 | 剩余装饰的环境 | 输出 |
| --- | --- | --- | --- |
| `baseline` | 当前 VSS | 当前环境查询 | 当前输出 |
| `scatter_lod` | 群系统计规则、坐标哈希、模板 | 保留原有环境精度 | 直接目标 LOD |
| `proxy_lod` | 同上 | 使用显示地表代理；建筑仍保留现有查询 | 直接目标 LOD |
| `proxy_coarse` | 同上 | 显示代理再共享固定 8 格网格；建筑仍保留现有查询 | 直接目标 LOD |

模板规则从实际群系 `VEGETAL_DECORATION` 的 PlacedFeature/ConfiguredFeature 编译，递归处理随机选择器、数量和稀有度。噪声数量按 2048 个固定位置估计均值。模板捕获使用实际 Feature 和现有 `FeatureStampLevel`，每种配置尝试三个固定种子；不依赖 SeedGen 类，也没有复制其实现。

53 个原版群系共审查 93 个植被阶段 PlacedFeature，其中 53 个进入替换集合，剩余保留现有回退；189 次捕获尝试产生 151 个模板，38 次捕获失败。失败可能来自环境要求或捕获边界，不代表 38 个独立 Feature。没有宣称适配全部模组。

散布使用固定 5 格世界网格，独立的种子/维度/坐标/Feature 盐决定出现、树种、变体和旋转。锚点高度在固定世界坐标通过 Rust 显示地形查询，独立于目标 LOD、观察者和执行顺序。模板按柱区间直接归并到目标体素；粗格内按占用量选材质，避免最后一根竹子覆盖同格树冠。步长至少 4 时省略高度不超过两格、非木本的模板细节。

原型仅替换植被阶段中成功编译的 Feature；没有用树木概率散布村庄等建筑。远区环境组还复用地形已有雪/冰信息，跳过逐格重跑 `FREEZE_TOP_LAYER`。地形形状、群系身份和原地表材质的 CPU 输出与基线逐片哈希一致；远区的装饰环境和装饰结果允许改变。

## 正式性能结果

单位为每片 256 个目标区块；每格为两轮相同区域的平均值，速度比使用平均总耗时之比。

| 方案 | 步长 4 总耗时 ms | 相对基线速度 | 步长 8 总耗时 ms | 相对基线速度 |
| --- | ---: | ---: | ---: | ---: |
| 当前 VSS | 2929.032 | 1.00× | 2885.568 | 1.00× |
| 模板散布，保留原环境 | 2743.791 | 1.07× | 2666.900 | 1.08× |
| 模板散布 + 显示环境 | 1524.010 | 1.92× | 1438.073 | 2.01× |
| 模板散布 + 共享粗网格环境 | **1147.698** | **2.55×** | **1047.900** | **2.75×** |

组合方案在正式配对区域全部更快。步长 4 单片耗时减少范围 45.96%–67.48%，步长 8 为 54.05%–70.95%；不能保证其他种子或模组仍是这一范围。

| 工作量/分配 | 步长 4 基线 | 步长 4 组合 | 步长 8 基线 | 步长 8 组合 |
| --- | ---: | ---: | ---: | ---: |
| Java 发起的精确地表点 | 85916.8 | 1107.2 | 84716.8 | 3104.0 |
| Java 回退环境的显示地表点 | 109260.8 | 1383.6 | 103123.2 | 1350.4 |
| 当前线程 Java 分配 MiB | 436.628 | 318.009 | 472.047 | 376.151 |
| 最终装饰输出盒子 | 123899.4 | 29733.0 | 71714.8 | 15737.8 |

Java 分配减少约 27.17% / 20.31%，这是累计分配量，不是保留堆、整机内存或 Rust 内存。查询计数只统计相应 Java 入口提交的点，不包含原生代理内部全部计算，也不等于完全独立的实际密度扫描。额外模板锚点平均约 3800–3900 个/片，相关成本已计入散布阶段。

剩余精确查询主要服务仍按现有路径处理的建筑及其输出提取；没有为了显示零查询而移除这部分工作。

## 现在的剩余成本

| 组合方案阶段 | 步长 4 ms | 步长 8 ms |
| --- | ---: | ---: |
| 原显示地形 | 248.450 | 77.477 |
| 建筑、未模板化装饰及其整理 | 551.450 | 648.433 |
| 固定锚点查询、散布、模板归并 | 344.858 | 320.697 |
| CPU 侧 Voxy 输入构造 | 2.941 | 1.294 |

这解释了为何还没有十几倍：回退 Feature、建筑、群系检查、固定高度锚点和模板归并仍在运行。单独继续压缩已经只有数毫秒的 CPU 输入构造，难以再显著提高总速度。

首次运行的统计规则与模板编译约 134.44–134.46 ms、Java 分配约 21.2–21.5 MiB；同一 JVM 后续模式约 24.76–50.93 ms、19.46–19.66 MiB。上述时间不含整个世界上下文建立，不能称为完整进世界冷启动时间。正式性能比较各组先完成两片预热，第一片额外的解析/原生 Feature 初始化不计入稳定吞吐结论，原始冷行仍保留。

## 正确性检查与画质代价

- 正式两轮所有模式的原地形列、区间、材质与群系摘要均与同输入基线一致。
- 反转执行顺序后，所有相同模式/区域的装饰几何、地形和代表区段映射哈希一致。
- 通过实际 `PredictionVoxySource.buildSection` 方法检查 0–4 级代表区段，使用固定 BlockState/biome 测试映射器；这没有验证 Voxy GPU 模型和最终像素。
- 静止重复、负坐标窗口重叠、步长 4/8 切换的锚点稳定检查通过。没有测试实际进入/退出内区的调度、缓存和发布转换。
- 补充步长 1、2、16 的实际运行矩阵共 12 行，与正式测试合计覆盖 1、2、4、8、16。该矩阵仅一轮小区域，不纳入正式加速比。
- 两轮每模式累计诊断一致：基线和仅模板组保留 3 次已有越界 Feature 回退；显示环境两组为 0。四模式均保留 13 次结构 `getLevel` 不支持的跳过。建筑调用未删除，但不能据此宣称所有真实建筑都已成功生成。

**尚不能直接发布为画质不变的优化。** 统计散布保留群系风格，无法复现原放置随机链；本原型还简化了原有的坡度、地面与存活条件。粗格材质按占用量选择也与当前逐块覆写不同。

以所有装饰材质合成后仍属于树干/树叶的目标体素计数，组合方案在五片区域的合计占用相对基线：步长 4 为 **1.665 倍**，步长 8 为 **1.353 倍**。这不是像素面积，也不是树木数量；它证明部分远景会偏密，不能将位置不对应的统计结果称为 95% 还原。体素交集/并集分别约 0.292 / 0.602，仅用于记录与当前预测的空间差别。

固定树根高度相对当前粗地形所在格的高度也有差别：步长 4 的有植被区域 P95 约 3–4 格、最大 34 格；步长 8 的 P95 约 3–25 格、最大 53 格。陡坡存在悬空或埋入风险。锚点在 LOD 间稳定，并不自动保证它与各级粗地形都贴合。

后续正式化应优先处理植被密度/地面条件和粗地形承托的一致性，再接入 4096 半径、近区提前晋升、独立质量/缓存身份和真实数据优先级。测试尚未证明这些生产连接点，也没有安装各种群系模组验证自动捕获覆盖。

## 证据与复现

正式汇总：`tools/performance/far-decoration/results-20261103.json`。汇总器先检查成功标记、完整行数、源码与原生库摘要、地形一致、映射校验、气候绑定和反序输出一致，再计算结果。

完整本地证据位于 `external/performance/20261103-far-decoration/`：

`build/far-decoration-20261103-a/`、`-b/` 和 smoke 目录属于预备原型，包含重复粗格输出或最后写入选材质的实现，未混入正式收益和画质结论。

python tools/performance/far-decoration/summarize.py build/far-decoration-repeat --output build/far-decoration-repeat/summary.json
