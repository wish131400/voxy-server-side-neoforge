# 通用装饰查询优化：生产实施与验证（2026-10-31）

本轮把[原型实测](generic-decoration-optimization-results-20261031.md)中的轻量记录、原生 Raw 工作区复用和单点入口落入生产代码，并修复精确预取影响显示地表的依赖，再验证精确分页与候选排除。交付覆盖 NeoForge 1.21.1 和 Forge 1.20.1，构建标识 `20261031-decoration-query`。

## 实现

- Java 与 Rust 的显示查询始终执行显示策略，不优先读取装饰预热的精确点；精确回退仍走原精确接口。显示结果不写入 Java 精确点缓存，装饰自己的显示页和精确页分别保留。
- 装饰精确 miss 按对齐 4×4 页提交，只计算共享点缓存中的缺项；复用原有 65,536 点有界缓存。任务保留自己的只读页，可跨共享缓存驱逐复用。装饰写入和回滚仍覆盖底层地形，不跨任务共享可变放置结果。
- 只要地表高度和材料时保留十字段原生记录；显示采样需要时才补群系身份和颜色缓存。并发补页不能把已补齐记录降级。原生外层群系路由复用既有 Raw 池，最多八份、合计 16 MiB；密度 Job 和完整深度回退继续各自求值。
- 树模型放置接入已有公共执行器。仅对紧挨 BiomeFilter 的已审核纯 BlockPredicateFilter 或有界 EnvironmentScan，利用已经观察且坐标吻合的群系缓存作拒绝证明。扫描所有可达终点都必须已知拒绝；任何未知项均继续原流程。不中途跳过随机数、位置变换或自定义谓词。
- 沿用公共执行器的模组修改识别与原调用回退。没有用来源区块的中心群系代替实际候选群系，没有替换 Java 群系源，也没有缓存整次有副作用 Feature 的失败结果。
- 增加装饰运行设置版本，旧装饰和成品体素缓存按需重建；原始地形缓存继续复用。无需删除整个世界缓存。

## 最终性能对照

Windows x86_64、Ryzen 7 7700、Java 21.0.6、NeoForge 21.1.234。原版主世界、种子 42，每方案两片预热、五片正式区域，每片 16×16 目标区块并包含额外一圈装饰来源，显示间距 4。计时包含地形、装饰与成品编码，排除上下文创建、哈希及日志；没有游戏渲染。

本轮对照的所有方案都已使用稳定显示语义、按需元数据及 Raw 复用。逐点控制是修正语义后的生产路径，不能把本表解释成相对旧 JAR 的完整提升，也不能与上轮 5.15% 相加。两条预热后的重复控制分别置于候选前后，按区域取控制均值配对比较；同一 JVM 固定方案顺序，一种种子的五片区域，几个百分点的差别仍有测量波动。

精确批次调用平均从 `83,908.0` 次降到 `5,369.8` 次，减少 `93.60%`；实际提交点从 `83,908.0` 增至 `85,916.8`，增加 `2.39%`。调用数减少不等于密度计算同比减少。

最终方案五片正式区域执行候选预检 `12,960` 次，提前拒绝 `11` 次。该策略只消除已有答案能证明无效的环境检查，不为寻求命中额外采样群系。总耗时比较包含公共树放置执行器的接入，不能把总收益全部归给提前排除。

35 组区域结果（含预热、五条路径）均匹配同一修正语义的逐点基线，逐片检查装饰方块坐标与完整 BlockState、装饰包围盒、最终列与群系身份哈希。完整原始数据、输入/源码摘要与 Windows DLL 摘要保存在 `build/decoration-final-runtime-20261031/`。第一轮实现对照与编译并行，只作为正确性材料，未用于本表收益。

## 回归与产物验证

- NeoForge：460 项 Java 检查通过；Forge：461 项通过。包含模块架构、列过滤、网络与状态交接，以及 52 项装饰专项检查，所有 Java 检查无忽略项。
- Rust 完整 release 回归：143 项通过、0 失败、4 项现有外部诊断忽略。新增回归覆盖 exact 缓存预热/驱逐后显示一致、负坐标精确页与反向逐点十字段一致。Java 覆盖按需补齐、取消、查询失效、写入回滚、原版随机调用与下界/末地装饰。
- 两端生产 Rust 源码与五平台库一致，Windows 实测 DLL 与发布包摘要一致。核对 JNI 42 个导出、CPU 架构、glibc 2.28 上限、macOS 11.0 下限与 ARM macOS 签名；其他平台为交叉构建和静态检查，没有宣称运行验证。
- 两个最终 JAR 均检查构建标识、标准文件名、语言资源、Java 版本、关键改动和原生库摘要，Forge 完成重映射；发布工具逐文件核对生产源码与测试快照，再更新两主项目根 `lib` 的标准 JAR 与同一标准 ZIP。

本轮没有对游戏 FPS、帧时间或整合包做前后对照；没有用原生群系替换 Java，也没有降低距离、精度、装饰数量或任务预算。最终离线对照仅覆盖 NeoForge 原版主世界；Forge 和其他维度通过专项回归，不能据此保证所有自定义世界生成模组都有同样收益。

## 复现

先用 `prepare.py <新目录> --implementation` 复制当前源码与原始输入，再用 `prepare_implementation.py <目录>` 注入只存在于实验副本的开关和计数。用 `experiment.gradle` 运行 `baseline,baseline_repeat,page4,pruned,baseline_tail`，每方案两次预热、五次正式、side=16。最后运行 `summarize.py <目录>`，并核对所有 `matchesBaseline`。实验编译输出与生产输出分开；正式计时阶段不并行构建或测试其他项目。
