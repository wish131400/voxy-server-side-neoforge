# 水平气候输入复用正式接入（2026-11-02）

构建标识：`20261102-climate-sharing`，版本号保持 0.3.7。

本轮把已经验证有效的水平气候输入复用接入 NeoForge 1.21.1、Forge 1.20.1，以及 Fabric 1.20.1、1.21.1、1.21.11、26.1、26.1.1、26.1.2、26.2、26.3，共十个构建目标。

## 实现范围

- Java 在气候根进入原有记忆化与编译流程之前，识别最大、坐标纯且不依赖 Y 的子表达式。同一 X/Z 跨高度复用它的原始结果；深度中的 Y 算术和原有运算顺序保持原样。
- Rust 为 Raw 气候水平输入增加有界共享表。Java 只批量读取原生端已经存在的值，缺失时直接计算原 Java 表达式，不触发额外原生生成。
- 绑定检查世界种子、FP32/FP64 精度、表达式树与噪声身份；未知语义或模组自有运行时节点沿用原计算。即使模组明确声明坐标纯度，也不会仅凭自定义序列化数据跨语言复用。
- 跨语言读取按 4×4 quart 点合批，工作线程复用直接缓冲区。取消、关闭、重绑和拒绝绑定时断开原生连接，退出世界清理缓存。
- Fabric 26.2 适配已迁移的 codec；26.3 使用独立的 FP32 密度接口实现，保留原版缓存去重过程和体积采样路径。既有 Vulkan、原生群系与地形/群系兼容入口保留。

## 容量与兼容边界

Java 每 worker 使用 16384 行直映射表，最多 16 个水平输入，常见六输入配置的表约 0.94 MiB；Java 缓存载荷按世界 8 MiB、Java 进程 64 MiB 预算管理。Rust 每世界最多 16384 行、六输入、64 个分片，行载荷约 1 MiB，Rust 缓存载荷在进程内另有 64 MiB 预算。两者是独立预算；额外元数据和对象开销不计入这些载荷数值。达到容量后回到原计算。

Java 缓存由各线程独占；原生缓存由世界所有并发任务共享并按分片同步。所有键均检查完整 X/Z，碰撞只影响命中率。原生端只缓存 Raw 路径，Single、Block 等求值模式保持原语义。表达式身份保留算术顺序和浮点正负零差异。

## 验证边界

- 十目标共 82 项 Java 专项检查通过，包括实际 JNI 共享命中、六根原始浮点位一致、种子拒绝与旧绑定退出、直接缓冲区边界、并发线程预算及释放；26.3 另检查新 FP32 编译与体积路径。
- NeoForge/Forge 公共原生核心新增 3 项、Fabric 核心新增 4 项水平复用差分检查通过，包含 Raw/Single/Block、跨高度、迁移、别名、根更新、取消和并发；Fabric 包含 FP32 夹具。
- Windows x86_64 执行原生回归；Linux x86_64/aarch64、macOS x86_64/aarch64 交叉编译并审查 JNI 导出。未在这些系统与 ARM 硬件实机运行或测量性能。
- 发布时检查十个标准 JAR 的构建标识、关键类/方法、五平台原生导出、源码摘要与库校验值，根目录标准包与归档摘要一致。
