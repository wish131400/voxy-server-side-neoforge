# Voxy / DH 合并方向实施与收益验收 — 2026-10-12

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

本轮实际实现并测量了多种候选。最终只保留 **工作线程 LOD 构建的延后复制**：完整真实语料累计分配减少 **18.11%**，所有源、水面、显示记录、误差与选档结果逐字一致。增强几何合并和共享存储方案均已撤回，本轮没有降低实际提交面数或常驻显存，也没有测得游戏 FPS 提升。

这是“有收益才保留”的结果；不把曾经试验过的路径计为已完成的 Voxy/DH 粗层架构。

## 保留的生产改动

只修改 `PredictionDisplayGeometry.java` 与 `PredictionScanMerge.java`，已同步 Forge 1.20.1 和 NeoForge 1.21.1。

旧实现每生成一个候选档位，先分配完整 `int[]`，再扫描合并；很多候选随后因减面比例或驻留预算不足被丢弃。新实现先在该线程已有的数组内向前紧凑记录，扫描只读取有效不透明前缀；通过原有准入条件后才复制要发布的记录。扫描产生了独立结果时直接使用该结果，不再先复制一次输入。发布记录不会引用可被下一次构建覆盖的线程工作数组。

没有更改坐标简化、材质、光照、归属、变体预算、屏幕误差、源缓存、透明排序或命令范围。`mergeDisplay` 明确区分有效前缀与数组容量，较大旧工作数组的尾部数据不能进入输出；原来的 source/water 扫描接口继续保留水面尾部。

## 试验后撤回的路径

以下面数是完整语料全部统一 tier 3，不是某个游戏帧；旧值 10,232,042 面。所有试验源码已从生产撤回，发布 JAR 不包含这些新类。

| 路径 | 统一粗档面数降幅 | GPU 编码字节变化 | 不保留原因 |
| --- | ---: | ---: | --- |
| 共享字节相同的记录，联合选择可用档位 | 5.58% | +5.09 MiB | 同档重叠面的绘制顺序变化，GPU 像素回归失败 |
| 限定为非 feature 地形记录共享 | 2.63% | +1.69 MiB | 仍有同档像素变化 |
| 只共享有序相同前后缀 | 0.38% | +0.99 MiB | 像素通过但收益小；mesh 2241 的 64 次提交命令 64→384，GPU 0.139264→0.147456 ms |
| 旧预算准入后再做 DH 式分组排序连接 | 1.02% | −2.97 MiB | 同档像素变化，未满足正确性要求 |
| 只连接连续相邻同属性矩形 | 0.54% | −1.35 MiB | 同档像素变化且 GPU 收益很小 |
| 完整有序档位逐字去重 | 0% | 0 | 这批真实语料没有可去重档位，无收益 |

这些试验中，有些局部远档组件时间下降明显，例如无序共享使 mesh 13 的 64 次提交 GPU 约 0.435→0.187ms。但它们同时存在正确性失败，不能因计时变快而进入生产。排序合并原型不是 DH 完整粗列汇总，也没有运行 Voxy 的体素下采样。
