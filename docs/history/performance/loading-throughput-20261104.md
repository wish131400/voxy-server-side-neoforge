# 预测加载吞吐改进（2026-11-04）

构建标识：`20261104-loading-throughput`。

## 修改内容

- 建筑起点的查询与提交使用短锁。不同起点可以同时生成，同一起点只生成一次；失败或取消的任务不会占据成功缓存。会修改建筑组件的放置过程仍按单个起点串行，保留组件状态与原有生成规则。
- 在预测建筑回放期间复用原版生成器返回的精确高度和地形柱。缓存区分生成器、随机状态、坐标、垂直范围和高度图类型；地形柱使用独立副本。首次查询仍执行原版生成器，实际区块生成不使用此缓存。
- 远景植被的原有五格锚点按世界坐标组成 8×8 查询页。Rust 一次接收最多 64 个原有坐标，各会话与不同 LOD 复用查询结果；原有随机种子、候选位置、植被密度与轮廓规则保持一致。非 Rust 后端复用同样的分页结果。
- 子块发布触发的已有父级刷新按原有距离与视野顺序排队，不再获得真实区块失效修复的最高优先级。刷新期间保留旧画面，同一未完成刷新继续合并；真实区块捕获更新可立即恢复优先修复。
- 生成入队明确区分已入队、当前任务暂不可用和 CPU 名额占满。全局 CPU 拒绝后保留选中的队首，下一轮优先重试，防止远处任务趁线程释放名额时插队；已入队任务也不会因为快速完成而丢失公平轮次记录。兼容渲染路径同样在成功提交后推进公平轮次，保留三个近处任务后安排一个远处任务的规则。

以上缓存随预测世界释放，分别限制为 512 个建筑起点、16,384 个高度结果、512 根地形柱和 2,048 个植被查询页。显示用植被地形不会写入精确建筑地形缓存。

## 覆盖版本

NeoForge 1.21.1、Forge 1.20.1，以及 Fabric 1.20.1、1.21.1、1.21.11、26.1、26.1.1、26.1.2、26.2、26.3。

## 验证范围

针对建筑并发与取消、精确查询隔离与可变数据副本、实际 Minecraft 方法的注入匹配、原生批量与逐点采样一致性、父级刷新与缺失地形排序执行离线回归，同时复查原有调度、表面生成与缓存流程。版本构建与测试明细保存在交付清单中。

离线验证不等同于实际整合包的加载耗时测量。此构建尚未替换当前运行游戏的 JAR；实际加载速度需在重启游戏后对比。
