# 装饰公共查询路径优化（2026-11-01）

构建 `20261101-decoration-core`，VSS 0.3.7，NeoForge 1.21.1 与 Forge 1.20.1。

## 实现与优先级

1. 精确地表的重复规则分析。原路径为每根柱及其前序邻居重新遍历世界的 SurfaceRules 树，检查是否可能改写空气/液体，以及向下石层条件需要保留的深度。世界初始化时，现在按群系、干湿检查与 Hole 条件的六种组合预先分析安全性，并整理去重的向下深度谓词。逐列只计算仍依赖坐标的数值。未知群系保留原来的完整分析，整数溢出、命名空间分派、取反条件与特殊地形仍按原规则处理。原递归深度实现仅保留在测试配置，交付流程使用预编译谓词。
2. 群系计算的数值复用。每个图工作区最多保留 256 组精确量化气候参数，缓存坐标、六个路由节点与完整七维目标；容量不超过 40 KiB，计入现有原生工作区字节预算，重定位时清空。缓存参数后仍调用同一棵 RTree，执行调用方原有的并列命中与上一叶子选择。没有跨请求缓存带顺序状态的群系答案，也没有改成 FP32 噪声。
3. 原生装饰工作区复用。原生 placed Feature 的群系过滤只使用 Raw 采样，现在从已有的有界池取得工作区，避免为每次 Feature 尝试分配完整 NoiseChunk 插值表。每次尝试独立初始化 RTree 选择状态；成功或普通失败后均返还工作区。特征顺序、随机调用和写入事务继续采用原流程。

三项均作用于公共环境查询。Java 的模组 Feature 调用同一精确地表环境时也能受益，不依赖自定义树模板。Java 自身的 BiomeSource 选择保留兼容路径，本轮没有把任意模组的群系查询强制改由原生接口回答。

## 内部耗时拆分

实际 NeoForge 装饰流程中使用独立的 profiling DLL 拆分。一个正式区域记录约 86,092 根冷列、1,451,822 次底层方块查询；仅 2 次完整重建回退。邻居几何阶段累计约 1,936 ms，中心扫描约 1,429 ms，地表规则约 430 ms；密度值约 902 ms，含水层/物质判定约 180 ms。整个装饰中的原生群系选择约 717 ms，其中气候参数计算约 450 ms。

这些计时来自带深层计时器与原子计数的诊断构建，包含嵌套调用，不能相加或直接与正式库耗时比较。它们用于选择公共规则分析、参数复用与原生工作区，而不用于计算下面的性能收益。准备阶段的逐列工作区回调在本场景中未被调用，不是这次场景的大头。

## 独立计时与完整输出

Windows x86_64，实际 NeoForge 运行时，原版主世界种子 42；目标区域 16×16 区块，加一圈装饰来源共 324 个来源区块，显示间距 4。每方案两轮预热、五个正式区域，所有 Java 流程相同；仅实验副本固定外部 shuffle 熵并添加归因计时。正式对照阶段没有并行构建或测试任务，未开启 Rust profiling。计时排除上下文创建与结果摘要，没有渲染。

先完成单独规则预分析的四组对照，再按 `baseline, plan, combined, baseline_repeat` 复核组合。下表采用组合试验的末尾原版对照均值；按区域配对的总耗时下降为 4.77%。

| --- | ---: | ---: | ---: |
| 总生成 ms/区域 | 5412.92 | 5158.12 | 4.71% |
| 装饰 ms/区域 | 5092.61 | 4838.72 | 4.99% |

本轮组合整体约节省 0.25 秒/区域，精确地表查询约节省 0.21 秒/区域。单独规则预分析两组试验的收益存在波动；第一组前后原版对照也有约 8% 差异，因此不把任何一组最好结果表述为稳定增益。组合复核中两次原版对照均值约 5.52/5.41 秒，本轮约 5.16 秒。没有获得两倍、十倍级的整体加速。

请求点数仍然一致，收益来自少做重复分析和复用数值/工作区。密度、含水层、Java 群系和大量无写入放置尝试仍然需要计算；仅以“最终没有写入”为理由跳过特征，会改变随机流或后续装饰环境，未采用这种策略。

首组 28 个区域、组合组 28 个区域均通过装饰坐标/完整方块状态、地形列/群系和最终体素包围盒摘要对照。最后另外使用五平台正式构建中的 Windows DLL，验证 7 个区域与原版控制的完整摘要一致，且测试加载的 DLL 校验值与交付 DLL 相同。最后一组只用于交付正确性验收，期间两端回归仍在运行，故不使用它的计时计算性能收益。
