# 密度查询复用与缓存更新（2026-10-31）

构建 `20261031-density-reuse`，VSS 0.3.7，覆盖 NeoForge 1.21.1 与 Forge 1.20.1。

## 实现

- 世界共享邻居高度缓存保留 65,536 项预算，满后按 FIFO 替换旧位置。重复更新不追加队列，空列答案同样参与缓存；任务内部结果独立保留，淘汰不会改变答案。
- 同一插值单元的整片空域检查同时缓存成功和失败。失败只省掉重复的整单元检查，逐列密度与含水层回退继续执行；保留有状态图、结构调整、非有限范围的原有语义。
- 允许独立求值的精确/显示批次按水平插值单元稳定分组，输出仍按请求索引返回。不重排 Feature、随机调用或可变放置结果。有状态图与结构调整保留原顺序。
- 共享单元的密集批次可使用局部 FP64 角点数组。只有空工作区可以选择表示，恢复中的缓存沿用原表示；稀疏查询沿用坐标哈希。每工作区数组预算 256 KiB，超出、邻居、非格点及垂直范围之外继续用原哈希缓存。两种表示都保留精确位值，不通过淘汰角点改变求值顺序；工作区重定位时清空内容并复用分配。
- 符号查询计划改为共享节点的紧凑 DAG，相同子节点不重复展开/分类。增加有限 Max 分支短路及常量在右侧的正比例缩放；NaN/无穷可能性保留完整叶节点回退。完整数值求值器仍存在，没有把整张噪声图改成另一套算术。

## 回归与交付

- 最终 Rust release：149 项通过，0 失败，4 项已有外部诊断保持忽略。新增检查覆盖缓存满后新区域、逐位角点与溢出缓存、负坐标/重定位、复杂图内存预算、失败证明回退、共享 DAG 与有限/非有限 Max。
- Java 必需模块检查与原生接口专项通过，详见交付 `validation.json`。联测发现两项旧测试仍要求精确预热改变显示策略，并将装饰内部十字段原始记录当作已补齐群系的发布结果；上一版 DLL 复现相同失败后，改为逐项核对显示网格在预热前后一致、精确结果未被覆盖，以及原始装饰记录能在发布前补齐并复用群系编号。没有修改生产流程或跳过失败测试。
- 两主项目 Rust 生产源码与五平台库一致，最终 JAR 检查源摘要、构建身份、JNI 导出及原生库摘要，再更新两个根 `lib` 的标准 JAR 和相同 ZIP。Linux/macOS 双架构为交叉构建及静态审计，未在对应硬件运行。
- 结果语义保持一致，沿用现有算法/缓存版本；没有清空世界缓存、改变距离、采样精度、装饰数量或并发预算。
