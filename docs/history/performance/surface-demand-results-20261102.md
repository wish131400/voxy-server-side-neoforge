# 地表与环境查询按规则需求准备：完整路径实验（2026-11-02）

可以减少无用环境计算，但本轮没有找到能把精确地表成本大幅降低的方案。在上一轮水平气候共享原型之上，安全的按需准备方案在交替对照中使完整生成耗时减少 **1.03%**；再加矿脉有效高度提前排除，合计减少 **2.30%**。精确地表子阶段分别减少 **2.88%** 和 **4.29%**。这是固定输入的小幅收益，不能推导成帧率或实际加载队列的同比提升。

本轮只修改实验工具、隔离副本和历史记录，没有向生产接入这套地表原型，也没有打包。另一个对话正在独立正式化上一轮的气候共享；本轮性能比较使用冻结源码，不要求并行工作中的生产树保持静止。

## 简化了哪些计算

原 `backend/exterior.rs::exterior_record` 已经采用边界优先策略，保留表层至少七层及规则要求的额外深度，并有高度缓存、插值和确定为空气的范围跳过。当前精确查询并非每次重新生成完整地下世界。

仍可省掉的工作集中在统一准备了规则可能根本用不到的输入：

1. 从世界实际 `surface_rule` 的 Rule/Condition 树，按群系编译 `Steep`、`Cold`、secondary depth noise 和 `Above` 的潜在依赖。不是按原版群系名硬编码白名单；`Biome` / `Not(Biome)` 能确定不进入的分支不贡献后续依赖。
2. 没有 `Cold` 依赖的群系，不对每个保留的默认方块计算温度。没有 secondary depth 依赖的群系，不为整列计算 secondary noise。`min_surface` 也仅在存在 `Above` 依赖时求值。
3. 保留原先较早邻居的高度、群系查询顺序和特殊几何安全检查；较晚邻居的高度在该列群系的规则可能使用 `Steep` 时才查询。
4. 矿脉两种原有分支的有效高度分别为铜 `[0,50]`、铁 `[-60,-8]`。在没有运行时状态依赖的密度图中，Y 位于联合范围 `[-60,50]` 之外时，可在 `vein_toggle` 前直接返回。没有改变范围内的矿脉规则、随机流或材料答案。

这是按群系潜在依赖准备上下文，尚未把每一个实际规则条件都编译成完全惰性的执行器。未知群系使用全局保守依赖；已有特殊几何和顺序敏感图回退继续保留。

## 为什么不能把邻居检查全部删掉

初版把整段邻居准备都延后到 `Steep` 真正需要时，完整路径发现第三片正式区域比基线多出四个装饰方块，最终摘要不一致，因此弃用，不计入收益结论。

原因不只是陡坡几何。原生气候参数树在距离相等时参考上次选中的叶节点；较早邻居的群系查询会影响后续查询的这一历史。删除它们会改变等距情况的选择。安全版因此保留这些群系查询及其顺序，仅延后其余高度准备。这里存在实际的顺序约束，不能作为多余防御直接移除。

侵蚀恶地、冰冻海洋等特殊表面还会影响几何；能删除方块或改变保留层需求的规则也有自己的回退。用普通陆地顶高直接替代这些语义，会改变水位、落点或方块状态。

## 完整路径和实验条件

- AMD Ryzen 7 7700，8 核 16 线程；Windows x86_64，Java 21.0.6，Minecraft 1.21.1 / NeoForge 21.1.234。
- 原版主世界，种子 42；单生成线程，显示采样间距四格。
- 五片固定正式区域，每片 16×16 个目标区块；装饰包含一圈来源边界，共 18×18 个来源区块。
- 实际 NeoForge 运行时调用显示地形、现有结构和装饰、植被整理与提取，最后构造 `PredictionVoxySource.build` 的地形列和方块包围盒。
- 计时包含完整生成、缓存访问、缺失后的原路径计算、跨语言调用和 Voxy CPU 输入整理；不含上下文准备及结果哈希。
- 没有减少候选、装饰密度或采样精度；没有替换成近似地表。
- 不含游戏渲染、GPU、磁盘缓存、网络或调度排队。没有独立测 Forge、多工作线程吞吐或安装群系模组后的完整运行时。

先运行两轮各五片正式区域、各模式两片预热的完整对照，第二轮反转候选顺序。第二轮末尾 cross 对照平均 3872.987 ms，而开头为 3436.779 ms，存在 **12.69%** 的漂移。将两轮所有首尾对照直接混合会把额外收益放大到约 5%–6%，因此不采用该混合值作为结论；原始数据全部保留。

随后追加按区域交替的对照：每个模式保留独立 Java/Rust 上下文，每片区域依次运行四个模式，奇数区域反转候选顺序，各自仍先处理两片预热区域。上下文不重建，缓存不跨模式混用，创建和清理不在计时窗口内。另一对话的重型编译和性能计时与本次正式计时错开。

## 交替对照结果

以下以同一轮、同坐标的 cross 模式为本轮优化基准，避免把上一轮气候共享的收益重复算入。

| 方案 | 完整耗时 ms/区域 | 精确地表 ms/区域 | 相对气候共享组的完整耗时减少 |
| --- | ---: | ---: | ---: |
| 冻结的原生产路径，无气候共享 | 3667.410 | 1731.300 | — |
| 上一轮水平气候缓存与跨语言共享 | 3326.171 | 1706.505 | — |
| 气候共享 + 按规则需求准备地表输入 | 3292.019 | 1657.307 | **1.03%** |
| 气候共享 + 按需准备 + 矿脉高度提前排除 | 3249.829 | 1633.310 | **2.30%** |

按需方案每片完整路径减少 34.151 ms，组合方案减少 76.341 ms；两者精确地表分别减少 49.197 ms 和 73.195 ms。子阶段收益不能再次加到完整路径上。组合相对按需方案进一步减少约 1.28%，但这里不是独立的纯矿脉对照。

按需方案五片的配对完整耗时变化为 `+2.22%、+4.94%、-4.09%、+1.66%、+0.98%`；组合为 `+4.78%、+3.53%、+3.72%、-0.83%、+0.51%`，正数表示更快。存在回退和波动，不能保证每个区域都会加速。第一轮顺序测试相应完整耗时减少 2.66% / 3.28%，方向一致但数值不同。本轮按 **约 1%–3% 的小收益** 判断，不采用受漂移影响的第二轮均值。

交替轮的精确地表仍占完整路径约一半：气候共享组 51.31%，组合组 50.26%。按需方案 Java 当前线程分配量约 492.092 MiB/区域，与气候共享组 492.054 MiB 基本相同；这项优化没有解决大量临时分配。

## 真正减少了多少工作

另用带原子入口计数的独立 DLL 完成同样五片区域的完整生成。计数版输出同样校验，耗时不参与性能结论。下表为每片均值，不是互斥时间分布。

| 实际入口 | 气候共享组 | 按需准备 | 按需准备 + 矿脉排除 |
| --- | ---: | ---: | ---: |
| `surface_top` 调用 | 410075.2 | 248152.0 | 248152.0 |
| 实际高度扫描 | 87819.4 | 86935.2 | 86935.2 |
| retained 表面列准备 | 86386.4 | 86386.4 | 86386.4 |
| retained secondary noise 求值列 | 86386.4 | 18880.8 | 18880.8 |
| retained 温度求值 | 598152.0 | 0.0 | 0.0 |
| 矿脉 toggle 求值入口 | 853278.2 | 852708.4 | 347871.2 |

邻居高度调用减少 **39.49%**，实际高度扫描只少 **1.01%**。多数删除的调用原本就在读缓存，不能把调用数减少直接当作同等比例的计算时间减少。secondary 求值列减少 **78.14%**，但单次计算成本较小；本次五片没有走 retained `Cold` 或 `Steep` 分支，不代表雪山、冻洋或自定义规则永远不需要它们。

组合方案矿脉 toggle 入口减少约 **59.23%**，仍未带来大幅完整路径收益。未被省掉的扫描继续承担真实密度、含水层、表面材质和保留层计算。计数只证明实际入口发生变化，不提供这些内部环节的互斥时间百分比。

## 一致性与适用边界

- 两轮顺序测试共 70 次正式生成、交替对照 20 次、插桩诊断 20 次，共 **110 次正式完整生成**。所有有效组最终摘要与各自基线及上一轮五个已归档 oracle 一致；预热组也与同进程基线一致。
- 交替轮逐片核对精确请求点数、调用次数、Java 群系请求数、装饰方块数及 Voxy feature box 数，候选与 cross 一致。
- 摘要覆盖装饰方块位置/BlockState、地形列群系/区间/BlockState 和 Voxy 包围盒。oracle 是现有预测路径，不证明与完整真实存档每个方块完全一致，也不是像素对比。
- 四项原生差分测试全部通过，共 **21964 组十字段列记录对照**。覆盖主世界、下界、末地、放大世界，两种种子，区块边界、反向访问、远坐标，以及显示/精确混用和重访。
- 补充规则覆盖 `Steep`、`Cold`、secondary、`Above`、`Not(Biome)`、air 替换及特殊几何回退；包含合成 `terrablender:merged` 和自定义命名空间测试。它们验证解析后的规则语义，没有替代真实安装 TerraBlender 或全部群系模组的兼容测试。
- 暴露 `cache_2d` / `flat_cache` 的密度图保留原路径，对照一致。
- B/C 和交替轮的 main Java、Rust 生产副本内容哈希及性能 DLL 一致；交替轮仅改变实验驱动的运行顺序。插桩 DLL 单独标识。

## 后续优先级

这套小优化可以作为通用清理候选，但不应再期待删几项上下文准备就显著改变加载速度。更大的未验证方向是按调用需求区分“只需高度/水位”与“需要精确材质/保留层”，让相同坐标的结果能够分阶段升级，并让同一插值单元的相邻列共享实际计算。

该方向必须从现有调用入口证明有足够多的轻量请求，并保持表面删除、水体、特殊几何、群系等距选择和缓存升级语义。之前独立先算高度的原型已经出现完整路径变慢，不能把重新拆一层接口当作必然加速，也不能把初始显示地形答案直接当作精确装饰落点。本轮没有测出这些更大改造的收益。

同日后续另测了扫描内部的[精确空气证明与含水层邻域复用](height-air-results-20261102.md)，组合完整路径耗时减少约 9.30%。该结果来自新的内部算法实验，不改变本报告对外围按需准备方案约 1%–3% 收益的结论，两者也没有测过叠加收益。
