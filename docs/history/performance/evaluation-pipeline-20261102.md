# 群系入口、工作区和地表规则隔离对照（2026-11-02）

## 决定

以已发布的 `20261102-decoration-pruning` 为基线，完成任务内 Raw 工作区复用、精确纯噪声复用、材质规则线性化及组合实验。所有候选的对应区域输出哈希一致，但没有获得可稳定复现的完整路径收益。本轮不将这些实验加入生产代码，也不把局部计时下降当作整体加载提速。

生产代码仅保留未消费 JSON 的整理：新增 `placedFeatureStatus`，生产调用经过 `applyPlacedFeature`，省去构造 JSON Value、数字字符串、序列化文本及 Java String。诊断、回归所用 `placedFeature` 保留；外部旧 ABI 6 库缺少新符号时，一次识别后走旧入口。两条入口调用相同 `World::placed`，保留完整事务、异常和随机流消费。本次没有证明这一整理能单独提高完整生成吞吐。

另一轮的跨版本候选群系筛选推广是独立改动，其收益不能计入本轮实验。最终原生构建、十目标回归和打包由该轮在双方冻结的源码上统一执行。

## 测量范围

- 运行目标：Fabric 26.3、JDK 25、CPU 路径，关闭 Vulkan。
- 固定世界种子 42；每片 16×16 区块；地表采样间距 4；区域随 round 固定变化。
- 每个正式计时进程先预热两片，再测五片；归因进程测三片；首次 smoke 不参与吞吐结论。
- 流程覆盖实际注册表解码后的地形、按原顺序执行的装饰，以及 Voxy CPU 输入构造。运行过程中没有并行执行其他构建或基准。
- 独立冻结 Java、资源和 Rust 副本；实验开关、逐点计时及临时任务 scope 均只存在于隔离副本。原发布 DLL SHA-256 为 `47f9dac9fdd8d624762264d3eea7d0a3ec9b6ca4e895019eb8458750b32d142f`。
- 只固定原生装饰代理用于外部 shuffle 的熵，不改变 Feature 的随机流；候选和基线使用相同处理。
- 不覆盖磁盘、网络、队列、绘制、连续移动和传送，不换算游戏 FPS。

带探针完整路径约 3592 毫秒。单点入口约占 6.6%；群系借还外层约占 0.5%，全部 Raw 借还内层约占 0.3%。这些比例说明存在跨语言成本，但工作区池锁不是当前主要瓶颈。实现本来已有池，不应再描述为每点新建完整 NoiseChunk。

任务 scope 原型在任务开始/结束时借还，在同线程内暂存一个 Raw Scratch，保留原有坐标、Mode 和等距选择语义。差分回归覆盖嵌套、错误顺序、其他 world、其他线程和异常退出。它的完整路径没有变快，故不进入生产。

## 二、列内和位置内纯噪声复用

实验只复用 `Condition::Noise` 的不可变噪声答案：按 noise ID 和 x/y/z 的精确位模式匹配，缓存限制为列内 16 槽。二维条件保留 y=0；三维条件保留实际 y。没有复用依赖方块、坡度、密度 Mode、矿石随机或可变写入的条件。

本组每片约 31682 次噪声条件检查，其中约 18191 次命中，命中率约 57.4%。带探针该区间由 3.56 降到 2.20 毫秒，每片只省约 1.36 毫秒；完整路径没有稳定收益。不能用较高命中率推出较大的整体收益。

大部分实际查询为平面噪声，三维噪声在这些区域很少执行。变量 y、不同 noise ID、负零、淘汰及旧/新精度路径已有精确位比较；这不能替代硫磺洞穴或大量自定义材质规则整合包的吞吐测试。此结果也不等于所有地形模组都不适合做纯噪声复用。

## 四、未消费的 JSON

审查生产调用后，确认 `RustVegetationStage.place` 忽略 `placedFeature` 的 JSON 返回值。`describe`、`schedule`、`support` 和统计返回值确实被消费；`feature` 等诊断/回归入口不机械删除。

轻量入口单独两次测得 3718.57 和 3625.96 毫秒。相邻基线约 3594～3681 毫秒，未建立独立吞吐收益。因此这项按减少不必要序列化的整理交付，不宣传提速百分比；最终包仍需执行相同事务/结果的回归。

回归夹具比较旧 JSON 与新状态码的完整 volume、写入 journal、再次执行得到的 `after` 随机值，以及失败后继续执行的结果。旧库模式另验证缺少新 JNI 符号后的回退。

## 追加实验：整数单点群系 JNI

归因后另外验证了 scalar `biomeIndex`：调用同一 `noise_biome_index`，保留坐标、活动 world 和索引校验，只绕过批量缓冲准备和复制。

- 带探针 Java 单点入口由 238.69 降至 134.08 毫秒；实际原生群系求值约 127 毫秒，没有消除计算内容。
- 第一组无探针对照：3620.11 → 3508.88 毫秒，约快 3.07%。
- 反序相邻复测：候选 3684.01，基线 3681.21 毫秒，没有复现收益。
- 七片对应输出仍一致；生产接入已撤回，原型和测试留在实验工具中。

NeoForge/Forge 的装饰群系查询走 Java context 精确路径，并无 Fabric 的相同单点→批量 JNI 开销。没有为了复用这个未通过收益验收的入口去改变旧版群系求值器或等距缓存语义。

## 正确性与复现

本轮 20 个隔离进程（含 smoke、归因和重复组）的对应区域哈希全部与原发布 DLL 一致。组合原型的 Rust release 单元回归 149 项通过、4 项既有离线探针忽略，含四项新增差分。NeoForge/Forge 共用核心原生 release 回归 179 项通过、4 项探针忽略；NeoForge 1.21.1 专项 65 项、Forge 1.20.1 专项 64 项均通过，0 失败、错误或跳过。

Fabric 26.3 初轮在重新构建的 Windows 库上完成 72 项 Java/JNI 回归，0 失败、错误或跳过，包含轻量返回契约；另在独立 JVM 使用原发布 DLL，开启旧库模式执行同一轻量返回夹具，1 项通过。这两次使用最初的 dirt/granite 夹具，不能当作后续共用夹具的通过记录。

旧核心的轻量返回夹具改用其既有规则支持的蒲公英/虞美人并铺设土层，明确要求 `placed=true` 和非空编辑记录后再比较两条路径，未修改生产生存规则。Fabric 的共用夹具与可移植工具夹具已同步采用此版本。Fabric 1.20.1、1.21.1、1.21.11、26.1 各 68 项专项回归均通过，0 失败、错误或跳过；本次记录时，Fabric 26.3 新共用夹具及其旧库回退仍待重新验证。1.20.1 的渐进细化测试仅补齐夹具中缺失的既有 `noiseBiome` 委托，生产实现没有因此改动。

其他平台只有交叉编译，不能视为在其硬件上执行或测过性能；剩余目标与统一包的最终结果以配套发布记录为准。

可移植工具保存在 NeoForge 项目的 `tools/performance/evaluation-pipeline/`，原始本机输出留在该项目忽略的 `external/performance/20261102-evaluation-pipeline/`，不提交机器路径、运行目录或大体积采样记录。每组记录实际 Java 源哈希、DLL 校验值、开关和区域结果；初始 manifest 只标识打补丁前的冻结输入，不能误当作后续候选的源码清单。

复现顺序：用 `freeze.py --build-id <基线标识> --jdk <JDK25路径> <输出目录>` 冻结对应版本的 26.3 Java/resources 和 Rust crate，保留 `baseline.dll`、原生文件哈希清单；运行一次 `prepare.py`；编译隔离 crate；用 `run.py` 逐进程指定 `--mode` 和 `--trace`；用 `analyze.py` 核对区域哈希及归因差值。`prepare_point.py` 在首矩阵之后增加标量入口实验，不能重复打补丁。`install_status.py` 是最终轻量返回片段；`install_point.py` 仅留档，不代表获准生产启用。

无探针基线的现有阶段计数还显示：每片 Java `UNSUPPORTED` 兼容装饰约 2189.46 毫秒、9004 次尝试，其中约 8449 次未写入；`TREE_MODEL` 约 652.05 毫秒、4536 次尝试，其中约 4407 次未写入。两者合计约占完整 3594.01 毫秒的 79.1%，但包含其下游精确地表等查询时间，不能与底层探针相加。这些“未写入”计数不构成跳过尝试的正确性证明。

新一轮若要继续研究，应先改进同进程、区域交替的无探针对照，减少进程间 JIT/分配波动，并在上述实际高成本消费者上取样。现有证据不支持给所有生产任务增加新的缓存和 scope。
