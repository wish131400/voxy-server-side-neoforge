# FTF 精确远景查询优化验证

本轮目标为 NeoForge 1.21.1 和 Fabric 1.21.1，构建标识 `20261103-ftf-exterior`。

## 改动

- 按水平噪声格合并精确占据查询，共用密度图与插值平面。先检查锚点；已经全部实心的区域保留提前结束，避免平地也扫描整个粗体素范围。
- 用位图保留已完成的精确柱结果，供不同细化等级、边缘重建和失败屋顶探测复用。缓存由世界采样器持有，按估算内存限制在 8 MiB 内，另有短期工作数组；1.21.1 默认噪声尺寸最多保留 2048 个噪声格。退出时清空，并发同格请求合并；取消的未完成结果不进入缓存。
- 审查已知 FTF 节点的坐标依赖。读取 C2ME 发布类保留的原始函数图来判断顺序要求，实际计算仍使用当前运行时的 NoiseChunk 与密度函数。无法证明安全的图继续按原版顺序计算并复用最终结果。
- 保留高度、液体、空腔和粗体素范围的精度。没有修改生成距离、细化等级或工作线程预算；Rust 后端未修改。

## 验证

两端各 17 项回归，共 34 项，失败、错误、跳过均为 0。覆盖原版三维度与水体、负坐标、跨噪声格、1/2/4 方块范围、不同查询高度、失败屋顶复用、未知节点与有顺序要求的缓存、并发同柱、计算取消和世界关闭后重开。

使用两个平台的 FTF 0023 发布包，在真实默认预设函数图与已初始化的过滤地形上下文上对照原版逐柱结果。每端针对原始及重建注册表分别进行了 30 次地形结果对照，并补充批量冷/热查询对照。相邻四柱的冷查询只构造一个噪声图。

离线微基准使用 32 个 4×4 范围、全深度查询；上游 FTF 地形单元已热，VSS 新占据缓存分别从空缓存和已填充状态开始。这用于隔离本次改动的查询成本，不是整个世界首次加载的基准。

| 平台 | 旧路径，两轮 | 新路径空缓存，两轮 | 新路径命中缓存，两轮 |
| --- | --- | --- | --- |
| NeoForge 1.21.1 | 65.928 / 62.931 ms | 47.892 / 39.253 ms | 0.490 / 0.185 ms |
| Fabric 1.21.1 | 59.022 / 55.479 ms | 37.815 / 31.704 ms | 0.753 / 0.291 ms |

这四次测量的冷查询耗时降低约 27%–43%。样本较小，不能据此承诺整段加载提速或帧数倍数。

## 验证边界

离线执行了 FTF 发布包的实际预设、单元过滤与函数图映射；为独立测试补入了该发布包所需的访问规则。C2ME 验证覆盖真实 SubCompiledDensityFunction 类的原始图提取，以及对有顺序要求的图继续拒绝批处理。没有在这套测试中启动完整 FTF+C2ME Mixin 游戏环境，尚未安装新包进行实机加载和画面对比。后续实机应同时核对批处理是否启用、缓存命中、细化完成速度和画面一致性。
