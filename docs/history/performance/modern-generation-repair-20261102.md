# 26.x 树木、GPU 选择与材质查询修复（2026-11-02）

本轮以完整生成路径验证修复和优化。目标是缩小 26.x 与 NeoForge 1.21.1 的差距；不能把缺少树木的旧版本结果当作完整画面的性能基准，也不能将单线程生成吞吐换算成整圈加载时间或 FPS。

## 修复

- 26.1、26.1.1、26.1.2、26.2、26.3 的树模板按新版植被支撑标签准入。湿润和陌生环境交回真实树生成；回放先检查空间，再执行一次实际地面 provider。原有树模型仍复用有限视觉变体，不能声称每棵模板树与原版完整生成逐块相同。
- 现代树修复增加独立装饰设置身份位，使旧完整装饰和成品体素缓存重建；原始地形缓存继续复用。旧版设置身份不变。
- 26.3 GPU 按真实 16×16 区域的完整成本校准和运行中复核。冷柱不足 192、部分缓存区域继续 CPU；3 次 CPU / 3 次 GPU 初始对照，GPU 运行时每 8 个合格区域插入一次 CPU 对照，近期 GPU 收益不足 20% 退回 CPU。CPU 决策后每 2048 个合格区域才重新尝试。已提交后的失败回退成本计入，取消和未执行请求不充当速度样本。
- 材质规则初始化时按已登记精确群系折叠确定分支和命名空间分发，保留动态条件、顺序、矿脉与位置随机种子；未知群系使用原树。
- 只有规则确实读取温度或次级地表噪声时才计算对应输入。外层保留深度不依赖 depth / secondary 时跳过这些计算；Hole 的三个安全摘要一致时不再重复计算 depth。
- 装饰查询的缓存命中计数按实际使用的视图统计：显示查询只统计显示缓存，精确查询只统计精确缓存。修正原先显示查询误计精确缓存命中的口径；不扩大缓存，也不把这项诊断修正当作提速成果。

## 验证方法

Ryzen 7 7700、RTX 4070 Ti SUPER、Windows x86_64。每个目标启动自己的真实服务端，使用该版本资源、标签、注册表和世界生成配置。种子 42，16×16 个目标区块、含装饰邻域 324 个源区块；地形间距 4、装饰间距 1；单生成线程，2 次预热、5 片不重叠正式区域。

计时覆盖地形、按序装饰、地表整理与 Voxy 输入构造。启动、注册表导出、哈希和显式轮间 GC 不计时，生成过程实际 GC 计时。没有覆盖磁盘缓存、游戏调度、网络、Voxy 建网格和绘制，未测游戏 FPS。

隔离基准仅固定 native stage 的外部遍历随机值，不更改 Feature 随机流。性能优化前后逐片核对完整输出哈希；修树后的完整结果作为同版本基线。

## 当前正式对照

以下为同机、单生成线程的完整生成路径中位数。每一行均保留该版本自身的装饰与资源；跨版本数值用于比较实际工作负担，不代表不同版本逐块生成相同世界。

| 目标 | 修树后基线 | 材质与噪声优化候选 | 同版本变化 |
| --- | ---: | ---: | ---: |
| NeoForge 1.21.1 参考 | 3077.5 ms | 本轮不修改生产核心 | — |
| Fabric 26.1 | 3510.9 ms | 3551.9 ms | 慢约 1.2%，未见明确收益 |
| Fabric 26.2 | 3544.4 ms | 3504.2 ms | 快约 1.1%，未见明显突破 |
| Fabric 26.3 | 3977.3 ms；重复基线 4066.5 ms | 3904.1 ms | 较两组基线减少约 1.8%–4.0% |

26.1 与 26.2 的候选各七片输出与本版本修树后基线全部一致；26.3 的七片输出也全部一致。26.1.1 与 26.1.2 使用相同现代树实现，执行对应版本回归与成品构建，不将 26.1 的吞吐直接标为它们各自的测量结果。

**这轮没有实现“26.x 完整加载追平 1.21.1”的目标。** 26.3 候选完整耗时仍比参考高约 26.9%，约需再减少 21.2% 才能达到此组参考时间。其地形阶段约 218.6 ms，已接近参考的 231.4 ms；主要差距在装饰及环境查询，分别约 3682.4 ms 与 2738.4 ms。不能继续把减少纯噪声计算当作解决剩余整体差距的主要手段。

GPU 修复后的完整路径对照中，CPU 地形阶段约 224.3 ms，GPU 在线选择约 228.2 ms；完整耗时约 3977 ms 与 4021 ms，七片输出一致。实际发生 GPU 提交与退回 CPU，说明选择器进入真实路径；本机该场景没有测得完整生成的 GPU 加速，不能把设备已启动当成提速结论。

最终 Windows 原生库再测完整耗时 **3865.6 ms**；紧接着反向运行未包含本轮材质优化的原生库，基线 **4029.3 ms**，同版本减少约 **4.1%**。两次各七片输出均与最初修树后基线一致。此为成品库复测，不替换前述全部首轮数据，也不据较快的一次运行扩大收益结论。

最终库开启 GPU 的完整路径为 3961.3 ms、地形阶段 222.8 ms；相同 CPU 库为 3865.6 ms、地形阶段 222.6 ms。七片输出一致，实际提交 11 次、最大批次 256 列，选择器记录一次在线切换并最终选择 CPU。表明本机此场景 GPU 没有提供完整生成净加速；选择器按要求保护后续路径，GPU 选项仍默认关闭。

## 回归和交付范围

- 现代树、放置器与环境查询的定向回归覆盖 26.1、26.1.1、26.1.2、26.2；26.3 另覆盖植被和 GPU 策略，共 63 项定向检查通过。
- Rust 全量 release 回归 254 项通过、4 项显式跳过；随后新增的 exact/display 缓存命中口径回归通过。规则 oracle 覆盖旧版与现代格式、命名空间、动态分支、矿脉随机流、负值范围、溢出边界及实际三种材质入口。
- RTX 4070 Ti SUPER 上运行真实 Vulkan 生产显示入口，覆盖间距 4、16、八工作线程与 96×256 列，核对结果并确认真实 GPU 提交及在线退回 CPU。
- 五平台原生库重新编译，逐个核对架构与全部 51 个 JNI 导出；Linux 依赖不高于 GLIBC 2.28，macOS 部署基线 11.0，ARM macOS 的临时签名页哈希通过。Linux/macOS 及 ARM 硬件未实际运行。
- 标准文件名、最终 JAR 源码身份、关键修复、五平台原生库与校验值在交付前统一核验。八个 Fabric 目标使用本轮共同核心；NeoForge 1.21.1 / Forge 1.20.1 保留已验证的双端 JAR，重新核对生产源码并刷新配套合包说明。

本轮不包含实际游戏内 FPS、连续移动、传送、二次进入或具体光影的画面验收。26.x 装饰缓存更新后需要重建，已有原始地形可复用。原始本机采样留在独立实验目录，不随用户包分发。

## 剩余主要工作

26.3 的 `sulfur_pool`、`rooted_sulfur_spring` 等新增装饰，会在随机高度的早期条件检查中触发完整精确 proxy 地表与材质查询；即使最终没有放置方块，这部分工作也已经发生。独立归因运行中，前者约 570 ms、其中地表约 525 ms；后者约 94 ms、其中地表约 92 ms。探针本身有开销，这些数值只用于定位，不与无探针的整片时间相加。

不能直接用单点密度或地下空气判断替代 proxy 查询：proxy 以最终表面下的材质带填充洞穴，实际空气不等于 proxy 空气；还必须保留已放置方块和结构覆盖。盲目前移群系过滤也会给原本早已拒绝的候选新增大量精确查询。

更深的优化需要候选范围的精确排除证明，或按现代浮点体积上下文复用密度输入。当前 Single、Raw、Cell 模式及现代体积形状的语义不同，旧版共享角点不能直接在新版打开。本轮保留原路径，没有省略植被、装饰或改变精度来制造提速。

缓存检查未发现仍在无条件按邻居整块重建的简单残留问题。精确 Job 和显示 Job 已各自按区块复用工作区；约 28 万次显示淘汰主要来自互不重叠冷区域的正常换入，不能直接解释为同一区域重算，也不据此扩大缓存。

## 未采用的实验

- **精确查询改成按需单柱：** 七片哈希一致，但完整耗时约 4123 ms，相对 3977 ms 基线变慢约 3.7%。保留 4×4 页合批。
- **整片群系不存在证明：** 七片哈希一致，确实跳过 2016 / 2268 次合格调用，但累计预取约 533 万 quart 点，完整耗时约 4528 ms，慢约 13.9%。未接入生产。
- **无坡度规则省略精确邻居：** 对保留列和最终颜色位置证明群系没有异名等距候选后，跳过四邻居扫描。完整输出七片一致，但总耗时约 4575 ms，检查成本超过收益。已按修改前备份撤回生产候选及辅助代码，仅保留本机实验记录。
- **Java 侧精确群系答案缓存：** 每 sampler、每线程 16384 个固定槽，完整坐标匹配，取消检查在命中前执行。七片输出一致，但命中约 6%，完整耗时约 3993 ms，比无此缓存的 3904 ms 慢约 2.3%。仅保留隔离实验工具，不进入生产代码，也不增加常驻内存。

这些结果说明减少查询次数不必然降低完整成本。材质分支数量、额外证明、查询缓存和处理顺序都必须纳入完整路径验证。
