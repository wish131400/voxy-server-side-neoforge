# 预测 LOD 渲染性能优化（2026-09-19）

> 历史记录：保留当时的实现、输入与验证结果，不能据此判断当前版本的渲染架构、配置或兼容范围。 当前说明见 [文档目录](../../README.md)，相关旧报告见 [历史索引](../README.md)。

本轮针对“加载完成后仍持续损失 1/3–2/3 FPS”的反馈。没有更改帧率熔断、后台线程数或地形精度设置，也没有用采样吞吐替代渲染性能证据。前一轮实体闪烁的 GL 状态隔离修复保留。

## 已实施

- **Iris 同帧复用绘制计划。** 不透明通道准备一次可见列表、归属遮罩、接缝和 morph 值；匹配的透明通道复用不可变列表，跳过第二次 tile 扫描、排序、归属和接缝准备。校验实际帧、Voxy 帧、viewport 身份、世界实例、网格快照、相机、投影/视图矩阵、尺寸及 GPU 修改代次。每帧清空；交错视图或资源/世界重置使缓存失效。真实深度副本也校验同一个视图，避免跨视图取错水面背景。
- **减少每个像素的重复查询。** 四边形固定的 sprite rectangle 和 average RGBA 改在顶点阶段读取，以 flat varying 传入片元阶段，取消原先每个有效材质片元的两次 SpriteTable 查询。顶点阶段相应增加这些查询和插值接口，净收益依赖几何/像素比例，不能直接推算 FPS。材质 tint 仍按每像素颜色计算；近处纹理、远处 cutout alpha、水的 alpha 及 Iris 材质 ID 保留。
- **尽早拒绝不属于当前网格的像素。** Yield 判断前移到真实深度重建、真实覆盖判断和材质处理之前；导数仍在任何 discard 之前计算。不按磁盘缓存或数据就绪状态删除预测，不改变真实深度交接规则。
- **降低 CPU/驱动提交成本。** GL uniform location 按程序缓存（包括 -1）；spacing、cellAxis、UseAverage 只在变化时提交。静止地形不再反复设置无作用的 morph；退出 morph 时仍明确清零。连续绘制 spacing/cellAxis/average 相同、morph 已结束的普通地形时，setTile + setMorph 的 uniform 调用由每网格 7 次降为 1 次（仅 offset）；这不包含纹理绑定与 draw 等其他调用。复用矩阵上传数组；Iris 材质 ID 仅在变化时上传，映射仅在材质表版本改变时重建；shader pack 的纹理单元布局按 pipeline 缓存。
- **更新小遮罩时复用存储。** 使用明确的 R8 格式，尺寸未变时 glTexSubImage2D；仅首次或尺寸变化分配。临时 native buffer 在提交后立即释放，恢复像素 unpack 对齐状态。调用方原地修改 allowed 数组仍能被检测。
- **将接缝与归属遮罩上传成本纳入升级预算。** 必须同时生效的接缝/归属遮罩仍整组完成；以本帧实测成本预留下一帧的可选网格上传预算。保持首个网格可推进。此处是软预算，不是所有上传总耗时的硬上限；不会为了满足预算留下半次交接。
- **恢复普通 GL 路径的早期深度测试。** 无限反向深度投影的窗口深度就是 `1 / clip-W`，与 `gl_FragCoord.w` 相同；普通预测片元不再显式写入相同的深度值。这样驱动可以在所有权、真实深度和材质判断之前拒绝已经被预测地形遮住的片元，保留原有深度结果和交接规则。
- **远处纯色面跳过导数计算。** 已经携带平均材质颜色的远处不透明面不需要纹理过滤导数；只有实际需要材质/裁切查询的四边形才计算 `dFdx/dFdy`，花草、水和近处材质路径保持不变。
- **不透明批次按距离桶提交。** 共享纹理页仍使用 MDI 合并，但可见地块先按近到远分成最多 32 个短桶，再在每桶内按页合并。这样不会把远处地块提前到近处遮挡物之前，驱动有机会用反向深度测试尽早拒绝片元；每桶增加的少量批次换取更少的片元过度绘制，几何、材质和归属精度不变。debug 日志会报告 `opaqueBuckets` 与 `opaquePageGroups`。

## 诊断

启用现有 debugLogging，或 JVM 参数 `-Dvss.renderTimings=true`。仅启用诊断后每 30 帧采样一次，不是默认每帧 GPU 查询。

- CPU：PREPARE（含子阶段）、COVERAGE（单个失效 tile）、SEAMS、UPLOAD（单个普通 tile）、OPAQUE/WATER（提交）、STATE（保存或恢复一次）、DEPTH_COPY（提交）。这些有包含关系、计数单位也不同，不能把显示的平均值直接相加作为一帧耗时。
- GPU：OPAQUE、WATER、DEPTH_COPY；16 组 timestamp pair，后续帧只读取 AVAILABLE 的结果。队列满跳过采样；不使用 glFinish、不阻塞等待，也不抢占光影包的 GL_TIME_ELAPSED query。
- renderer diagnostics 中增加 preparedPlans / reusedPlans 及 timings；GPU 指标附样本数。普通上传和 handoff 上传字节、耗时、下一帧预留分开显示。
- 当前计时给出采样均值，不提供 p95/p99，也不是开关预测 A/B 的自动 FPS 基准。

## 验证与边界

两个加载器运行同一组针对性测试：帧计划失效、上传交接、预测/真实接缝、材质表版本和生产 GPU 像素回归。GPU 测试使用本机 NVIDIA GeForce RTX 4070 Ti SUPER 的隐藏 OpenGL 上下文；覆盖普通/Iris 深度、洞口/岩壁、花草双面朝向、水/熔岩、真实区块交接、实际 morph 位移及实体状态隔离。另测 timestamp 与外部 query 并存、环形队列满时跳过，以及 R8 遮罩复用与尺寸变化。

这不是玩家整合包 + Eclipse 的完整实测，也未完成 AMD 验证。尚无可发布的“实际 FPS 提升百分比”。JAR 位于各仓库 lib/；替换后重启即可，不需要删除地形缓存。

## 后续需要数据决定的改动

接缝仍使用现有变化缓存并在渲染线程准备；本轮去掉同帧重复准备，尚未将其整体迁移到后台。超大单 tile 上传仍有首项放行规则。若计时确认这两处占主导，再实施带版本校验的后台接缝构建和分块上传/原子发布。

也未直接开启全局背面剔除、删除光影状态恢复、删掉真实深度副本，或合并所有 draw calls。这些涉及混合绕序、双面植物和不同光影约定，需要逐项测量并保留视觉回归。帧率熔断不是本轮优化手段。

## 2026-09-25：静止批次复用与已撤销的遮挡实验

- 不变的批次记录和间接绘制命令保留在各自的 GPU buffer 中；内容发生任何变化则重新上传。切换世界时释放这些 buffer。普通和水面批次分开缓存。
- debug/render diagnostics 的 `indirect` 报告五个水平距离桶的 `queuedQuads`：`0..256`、`256..1024`、`1024..4096`、`4096..16384`、`16384+` 方块。
- 曾测试 Hi-Z tile 预剔除，但实景只过滤约 1%–2% 的四边形，GPU 开销高于收益；已移除实现和开关。批次复用仍覆盖普通预测渲染通道；Iris 光影通道继续走独立绘制与深度交接。

## 2026-09-25：实景复核后的页合并

同一台游戏里，预测开启时每帧约 400 万至 700 万四边形、数百次间接绘制；一个 1901 tile 的视角出现 30 个距离桶、749 个页分组及 979 次绘制。45 秒 JFR 的渲染线程 1255 个 Java CPU 样本中 864 个经过 VSS；关闭预测后的 30 秒为 754 个中的 6 个。两组长度不同，不应直接把样本数解释为 FPS 百分比。

对照 Voxy 的 `MDICSectionRenderer` 与 `HierarchicalOcclusionTraverser`：Voxy 在 GPU 侧遍历并生成命令，几何缓冲集中，最终只作少量间接绘制。VSS 仍在 Java 侧选择/排序，并按纹理缓冲页和距离桶提交。因此本轮先减少页与桶的碎片化：默认几何页从 8 MiB 增至 64 MiB（`-Dvss.indirectPageMiB=8|16|32|64` 可回退），桶目标从 64 增至 128 tile、上限从 32 降至 16；桶内页查找使用复用的 identity 映射，不再线性扫描并逐帧分配 `PageGroup`。几何精度、纹理与深度规则没有变化，代价是单页闲置空间最多增加到 64 MiB，且桶内绘制顺序比以前更粗。诊断增加 arena 页数/字节，供实景确认页合并是否生效。

这些改动有望减少驱动提交，但仍没有把 VSS 改成 Voxy 的 GPU 场景遍历、全局可见性和统一命令缓冲。实景复测中页分组从约 749 降到约 52，绘制从约 979 降到约 57；同一窗口里不透明 GPU 时间约 3.6--4.4 ms。要判断是否接近 Voxy，必须继续用相同视角测 `opaquePageGroups`、`opaqueFallbacks`、`drawCallsCurrentPass`、OPAQUE CPU/GPU 时间及预测开关两组 FPS；不能把合成 GPU 测试结果外推到实际帧率。

## 2026-09-25：共享页溢出与移动路径

更大视距的实景日志显示，共享页达到默认 1 GiB 上限后，仍有约 1900 个地块回退到独立缓冲，单帧绘制约 2100 次。因此把共享页默认上限提高到 2 GiB（仍按需分配，`-Dvss.indirectArenaMiB=1024` 可回退），并报告 `opaqueFallbacks`。这些地块原本也已上传到独立 GPU 缓冲；是否减少实际显存和提交次数要用新包日志确认。

同一归属视图内移动时，场景只重新处理进入或离开预测范围的地块，复用其余地块的覆盖和接缝结果；朝向面与视锥可见性仍逐帧更新。视距、网格、玩家归属视图或真实地块边缘变化继续触发必要更新。针对步行、穿过预测范围边缘并返回的 GPU 回归覆盖了地块移除和恢复。

## 2026-09-25：移动时的细节回退

玩家走远后，预测地块不再因为曾经访问过而永久驻留。最外层地块在离开预测范围和滞回距离后可以直接释放；内部细节地块先为缺失的粗父级建立回退链，只有父级已经发布并可交接时才释放子级。渲染驻留层仍会等父级完成 GPU 上传后再移除旧细节，因此不会用尚未上传的粗块制造空洞。

`surfaceDiagnostics` 现在报告 `ready`、`fine`、`coarse`、`fallbackPending`、`retiredOutOfRange` 和 `retainedForFallback`，可用来确认行走时驻留数量是否收敛。父级准备使用合并后的 O(n) 回退扫描，不对整个驻留集合逐帧排序；半径缩小时会清空旧回退链并按新范围重新规划。

## 2026-09-26：批量接缝遮罩的并行准备

接缝遮罩只读取已经发布的地块、覆盖结果和不可变空间索引，不调用 OpenGL，也不依赖 Minecraft 客户端状态。因此，受影响地块达到 24 个时，使用两个后台工作线程分担 `PredictionBoundaryWalls` 的计算；渲染线程等待所有结果后，才按原有顺序拼接接缝并上传。少量更新继续使用串行路径，避免线程调度成本。

结果按地块逐项比对，和串行实现字节一致；后台计算不能提前发布 GPU 资源，所以不会引入旧快照与新接缝交错的空洞。测试基准在当前开发机上对 32/64/128/256/1024 个地块的遮罩中位数分别约为 0.484/0.221、1.008/0.472、2.179/1.110、4.266/1.634、18.454/6.648 ms（串行/并行）。这是接缝准备阶段的墙钟测量，不等于整帧 FPS；实际收益取决于同一帧是否有大批量地块变化。

## 2026-09-26：父子归属的安全提交削减

渲染场景现在额外保留一份“父级仍可回退、当前帧不一定提交”的归属集合。当一个普通父地块的四个直接子地块都已经上传、四个子地块的归属遮罩也完整时，父地块从当前绘制计划中暂时压掉，但仍保留在 `terrain` 和 GPU 驻留中；任一子地块缺失、遮罩不完整或回退条件变化都会在同一帧重新放回父级。视锥变化不会重新把被压掉的父级加入绘制计划。

对固定源单元的 packed 四边形，顶点阶段读取当前地块的归属遮罩；已经交给更细地块的整块 primitive 在光栅化前被裁掉。跨单元合并面、接缝、水体、植被和真实边界仍使用原片元级判断，以避免裁掉跨覆盖边界的几何。该路径只减少重复提交和无效片元，不改变高度、材质、深度交接或 LOD 选择；不支持批量 shader 时自动使用原路径。

诊断增加 `ownerTiles`、`suppressedParents`、`partialCoverageParents`、`transitionTiles`，用于实景确认父子重复提交是否下降。为减少 Java/page flush，不透明距离桶目标从 128 地块调整为 384、上限从 16 降为 8；水体仍保持背到前顺序和独立回退。这里依赖已有的 Voxy 深度副本和固定功能早期深度测试，没有重新启用实测收益为负的 Hi-Z 实验。

父子绘制归属随变更地块和其直接父级局部更新，不在一次局部上传后遍历全部常驻地块。`partialCoverageParents` 和 `transitionTiles` 也跟随绘制记录增删维护。Forge 1.20.1 同步使用保守的高度/视锥四叉树候选、候选绘制计划、批量接缝遮罩并行准备，以及与 NeoForge 相同的预测深度预填充路径；两边的接缝仍须在渲染线程统一发布，不能由后台线程碰 OpenGL。

## 2026-09-26：跨版本补齐

Forge 和 NeoForge 都在 Voxy 不透明地形绘制前计算外缘扇区遮罩。只有相应扇区内缘已有可绘制且拥有覆盖权的预测地块时，才隐藏 Voxy 的外缘面；其它区域保留 Voxy 原有网格。此规则需用对应版本的 Voxy shader 验证链接和画面，不能只凭 JAR 构建通过推断交界正确。

两边都在外部列填充中批量提交最多八列。Java 路径逐列执行原算法；支持新 JNI 的 Rust 库在相邻密度单元间复用工作区，未命中或旧库回退到逐列路径。Forge 1.20.1 专有的 WWOO、Tectonic 兼容规则未作为 NeoForge 的通用规则移植。
