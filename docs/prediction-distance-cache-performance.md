本次针对缩小预测距离后资源滞留、重进世界精细缓存恢复慢的问题。两端保持相同算法，保留 Minecraft / Forge / NeoForge API 差异。

## 修改

1. 配置布局变化不再等待固定的五 tick 规划间隔。
2. 显式缩小预测半径时，立即释放新范围外且新规划不需要的 CPU tile；清理其任务宽限及重试状态。过时 LOD 层级不能再被任务发布。保留磁盘文件供扩大距离时恢复。
3. 批量回收只做一次覆盖失效更新，避免每删除一块都扫描全部后代。
4. 半径、选择质量等布局变化保留仍适用的已上传 tile，只更新覆盖归属；维度变化仍清空。缩小距离时，被移出的 GPU tile 不再为了等待父级上传继续滞留。实际 GL 删除仍走现有有预算的逐帧退休队列。
5. 压缩缓存增加 32 KiB 的解压后输入缓冲和压缩前输出缓冲。消除逐个整数/字节跨入 zlib 的重复调用。格式、校验、失效规则和旧缓存兼容性保持不变。

释放 Java 对象引用不等于 JVM 立即把已提交堆归还操作系统；本轮也没有让所有有界生物群系/原生缓存按半径重建。FPS 仍受近景精度、像素覆盖和光影影响，不能按半径缩小倍数推算。

## 微基准

工具：`tools/prediction/CacheStreamBenchmark.java`，JDK 21；12 轮预热、31 轮交错顺序测量，验证两种实现读回相同字节/校验和。真实缓存样本解压后 348917 字节、压缩后 14087 字节。

| 阶段 | 原实现中位数 | 缓冲后中位数 | 阶段耗时减少 |
| --- | ---: | ---: | ---: |
| 解压后的整数读取 | 5.531 ms | 1.169 ms | 78.9% |
| 整数写入与压缩 | 9.060 ms | 3.572 ms | 60.6% |

该工具在内存中重放真实缓存负载，不含磁盘寻址、方块注册表解析、植被/网格重建、任务排队、GPU 上传。不能解读成整场景加速 4.7 倍。测试未改写用户缓存。

## 校验与后续边界

两端运行磁盘缓存往返/失效/损坏测试，以及驻留、上传交接、渐进加载、望远镜驻留、覆盖缓存回归测试。新增回归覆盖 65536→4096 后复用近处 GPU 数据、释放远处数据、重新扩大距离，以及无需等待未上传父级即可释放范围外 tile。

本轮未修改初始化执行路径、普通精细距离、帧率策略和逐级任务准入。还没有在游戏中对新包做同位置开关距离、重进世界的 A/B 测试。

精细缓存命中会直接恢复已保存的采样轴长度，不必从 8 重新采样到 64；但该 tile 仍须获得任务准入，并恢复植被、重建网格、上传。Voxy 使用持久化的多级体素数据，也需要网格构建；VSS 当前额外依赖可复现的地形上下文和预测调度，所以两者不是相同恢复路径。

下一步优先级：给有效精细缓存增加有界恢复通道、在保持父级覆盖和上传交接的前提下缩短逐级等待；再拆分 Java 上下文的初始化耗时，评估是否能将非首屏必需的准备延后。避免通过预读全部缓存或长期保留上一世界的原生上下文来换取表面上的启动加速。

产物放在两仓库各自 `lib/`，沿用 `vss-0.3.1-neoforge-1.21.1.jar` 和 `vss-0.3.1-forge-1.20.1.jar`，内部版本号与文件名一致。诊断和优化不另加版本后缀，只有用户要求推进版本时才修改版本号。保留工作区原有的实体渲染诊断改动，不代表实体透明问题已经修复，也没有自动替换游戏 mods。lib 中不再保留带 render-capture / cache-perf 后缀的包；重新构建后仍存在的旧后缀包已移到 build/distance-cache-20260920/superseded-names 归档。
