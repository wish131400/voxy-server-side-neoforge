# 0.3.3 后续整理：网格存储、接缝与采样

日期：2026-09-23。累计玩家更新日志见 [CHANGELOG](../CHANGELOG.md)，基线为 0.3.2 发布后的代码。两个加载器保持 0.3.3 与原 JAR 名称。

## 内存与显存

CPU 网格先采用可逆的颜色/光照字典布局，再使用可用的 Zstd 或 Java LZ4 无损压缩。GPU 直接消费字典布局；坐标、颜色、光照、面片顺序与标志保持一致。小网格、无法安全编码或不能节省足够空间时使用原布局。字典在发布/恢复工作线程生成，绘制循环不构造哈希表。

接缝摘要将相对高度紧凑打包，并按收益选择端点字典。查询支持随机读取，不需要反复整体解压。高度跨度无法编码时回退原布局；磁盘仍以规范字段写出，不要求为这项内存优化清空缓存。

2026-09-23 的运行实例：预测 4096 方块、精细 1536 方块、地表 2048 方块，约 2033 个常驻地块。已统计的常驻预测数据约 759 MiB，其中 CPU 网格约 276 MiB，接缝摘要及端点约 130 MiB。已统计 GPU 资源分配约 1.12 GiB；这是容量统计，不是操作系统按模组分摊的实际显存驻留。

按同批数据记录的压缩前长度反推，单独关闭 Zstd 时已统计预测数据约 1526 MiB，即约 1.49 GiB；当前约 0.74 GiB，差约 767 MiB。这不是关闭压缩后的实机 A/B，也不包含字典布局和接缝紧凑化的历史收益。CPU 压缩不直接缩小 GPU 分配。统计尚未完整归入 Rust 原生内存、所有辅助缓存和执行中的临时任务，不能视为 VSS 全部内存的精确归属。

## 接缝、树木与采样

山体局部检查记录实际非空气区间。较粗网格只有在整个占地范围均为空气时才挖空，避免用单点代替整个格子误删岩石；真实区块捕获保留空洞信息。网格与接缝按已记录实体区间生成露出面，避免用一整面长墙跨过洞口。

树木按真实邻接占用处理面，不再只保留最高连续层；薄层悬空屋顶的表面替换保留其空洞证明。几何硬上限仍存在，病理密集场景可能保留粗网格。详细原因与回归见 [树木与 Rust 空洞采样](trees-and-exterior-footprint.md) 和 [Java 空洞采样与薄层长墙](java-exterior-and-thin-roof.md)。

Rust 与 Java 均使用有界高度、噪声格复用、整格非空气并集和已确认高度提前停止。Java 进一步复用纯密度子树、查询上下文和固定容量高度/失败屋顶缓存。未知、有状态或依赖求值顺序的图采用相应兼容路径；不把缓存标记当作密度与 Y 无关的证明。详见 [Java 密度优化验证](java-density-optimization.md)。

## 升级与复现

成品网格版本由此前的 3 更新至 7，旧错误几何自动重建。地形与装饰缓存保留，旧采集记录兼容读取。初次升级可能等待部分网格重建，不应据此删除世界或 Voxy 数据。

带入仓库的回归样本只包含山体列的几何和空气区间；完整世界、游戏日志、JFR 与本地采样包留在忽略的 build 目录。山体生成基准需要自行提供匹配世界生成快照，普通回归不依赖这份外部快照。测试用例和显式 GPU 测试开关保留；阶段记录给出当时的测试范围，不能推断全部玩家环境均已验证。
