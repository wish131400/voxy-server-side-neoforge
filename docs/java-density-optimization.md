**Java 预测回退优化与验证记录 · 2026-09-23**

本轮把能够确认收益、且保持既有采样结果的复用优化同步到 NeoForge 1.21.1 与 Forge 1.20.1。产物版本仍为 0.3.3。以下数字衡量 Java 地表查询阶段，不代表完整世界加载或游戏 FPS。

已保留的改动：

- 密度图按依赖区分 XYZ 查询与仅依赖 XZ 的查询。已证明与 Y 无关的子树在同一列的不同高度之间复用结果。Raw 模式下的 FlatCache / Cache2D 仍按子树实际依赖判断，不把缓存标记本身当作“与 Y 无关”的证明。
- 已知纯密度图使用复用的查询上下文，子节点直接取得本线程槽位，减少逐节点 ThreadLocal 查找。上下文只持有独立身份标记，不反向持有采样器/缓存所有者，避免世界退役后延长其生命周期。
- 精确高度使用固定 4,096 槽的原始数组缓存。地表规则、相邻高度和 groundY 查询可共享结果；碰撞时重新计算，不返回别的列的高度。预览、自定义高度函数和无法证明为纯函数的图不进入这个精确缓存。
- 原版列顺序兼容路径增加“上一列”快捷复用，连续高度/材质查询不必再次锁住共享列缓存。原版列顺序与含水层计算保持原有语义。
- 洞口检测失败时，缓存精确的 X/Z/屋顶高度。相同失败候选点不再重建 NoiseChunk；换屋顶高度重新验证。只在已证明可使用局部扫描的图上启用，仍检查取消状态。
- 有状态密度节点向已知父节点传播不可缓存属性；编译图拒绝变换时保留全部原根节点，避免半套图被改写。
- 修正 Forge 正式环境的反射识别：Noise 和 ShiftedNoise 的 Y 缩放从 record 字段描述及声明顺序读取，不依赖会被 SRG 改名的 yScale 方法字符串。NoiseChunk 顺序分析也使用相同读取方法。

新增精确高度与失败屋顶缓存各约 52 KiB 数组数据/工作线程，两者均分配后合计约 104 KiB；8 个工作线程约 832 KiB，另有少量对象头及密度槽位元数据。缓存按采样器/线程隔离且容量固定，不随已探索区域增长。依赖分析在密度图构建阶段执行，分析用的映射在构建后即可回收。

**同一 JVM 对照测速**

基线保留本轮之前已有的 XYZ 密度缓存，关闭本轮新增的跨高度复用、上下文复用和高度缓存。每组 256 个点、间距 2 方块；每轮使用新的坐标区域，交替测试顺序，预热一轮后取六轮中位数。采样器/图构建耗时不在计时范围中。

| 场景 | 原 Java | 仅增加跨高度复用 | 再增加查询上下文复用 | 本轮全部保留改动 | 耗时下降 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 主世界地表 | 17.327 ms | 10.139 ms | 8.821 ms | 8.725 ms | 49.6% |
| 末地地表 | 46.171 ms | 9.740 ms | 9.053 ms | 9.328 ms | 79.8% |
| 玩家山地密度快照 | 14.820 ms | 7.149 ms | 6.134 ms | 6.109 ms | 58.8% |

相同坐标再次请求、精确高度缓存已热时，完整地表查询分别为 0.837 / 0.643 / 0.615 ms。这里不是磁盘读取或完整网格恢复的耗时。所有对照检查整个 ClientColumnSample 记录，包括高度、液体、材质和标志，结果一致。山地回放保留实际密度图；独立测试中使用原版地表规则与固定 plains 生物群系，避免依赖测试注册表中不存在的模组资源。

下界实际走内部体积查询，不能用普通地表查询基准来代表下界加载提速，因此没有把下界地表微基准列入收益表。上述收益主要在 Java 承担地表预测时生效；Rust 已接管的计算不应套用这个比例。未知/编译/依赖运行时状态的图会保守退出对应优化。构建依赖分析的新增初始化耗时未单独归因。

**试验后没有加入生产路径的两项改动**

1. Java 地表改为 8×8 空间批次：1,156 点测得逐行 38.985 ms、空间批次 43.522 ms，约慢 11.6%；另一轮同样更慢。因此保留原调用顺序，没有把“批量循环”当作性能收益。
2. 仅占据性扫描省略矿脉材质：一轮从 57.361 ms 变为 61.083 ms，另一轮从 40.434 ms 变为 38.247 ms，未显示稳定收益。实验留在测试里，正式路径继续使用原版设置与材质判断。

本轮没有用降低采样精度来获得这些结果。Java 已有的生物群系缓存、地表规则 Worker 和装饰任务缓存继续复用，不再叠加重复的一整套缓存；未知模组装饰仍由原实现处理。

**两处真实问题山体回放**

使用种子 5052304137288917019 的只读世界生成快照，验证 -4588/-1531 与 1605/-1456 两片区域。每片使用 66×66 网格，分别检查 1/2/4 方块间距；与完整原版列扫描比较全部样本、实体区间和标志。保存的 52 列、1,634 个空气位置在 Java 与 Rust 下均仍为空。

1605/-1456 这片山完成细化后，重复 enrich 的实测耗时：step 1 为 0.055–0.072 ms，step 2 为 0.067–0.193 ms，step 4 为 0.057 ms 左右。失败屋顶的复用不会产生新的实体区间，也不会把旧失败应用到不同高度的屋顶。

本轮密度查询基准不包含前一轮“完整列扫描改为局部 NoiseChunk 扫描”的收益，避免重复计算优化幅度。
