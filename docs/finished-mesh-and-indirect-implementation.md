# 成品网格缓存与按场景启用的批量提交

> 阶段记录：正文中的实验范围、未提交状态和测试数字对应当时的工作节点。0.3.2 之后截至本次提交的最终功能与升级说明见 [更新日志](../CHANGELOG.md)。

2026-09-22，0.3.3 工作区。NeoForge 1.21.1 与 Forge 1.20.1 同步；版本号和 JAR 名称不变，无 GitHub 提交。

## 实际接入范围

`PredictionTileManager` 在得到当前采样、颜色、精确植被与简单植被输入后，先查成品网格记录，命中则跳过 `PredictionMeshBuilder`、紧凑化、接缝构建和 packed payload 生成。仍然保留前面的输入恢复、颜色检查和植被组合流程；本次并不是直接从磁盘跳到 GPU，更不是首次地形计算加速。

成品记录使用现有 `.vpr` 区域索引中的 kind=2，zlib level 1。kind=0 地形失效会同时失效 kind=2；更新中的 lease、后台保存与退出重进都沿用已有 owner/失效机制。新身份包含格式版本、实际列数据/体积、颜色、植被体素/方块/外壳与简单植被形式；世界、维度、种子、生成器与算法使用原有缓存目录身份。

资源身份在每次图集重载后由一个低优先级后台线程计算，覆盖模型、blockstate、纹理资源及方块注册顺序。资源内容最多读取 512 MiB，超过上限或读取失败时绕过成品缓存；已有预测仍正常工作。指纹未就绪时不等待。运行时动态模型若在资源不变时改变几何仍需要显式失效，尚未用所有模型模组验证。

材质以名称、模型 UV/阴影属性、静态火类型及代表方块保存，读取时映射到当前 sprite 行；接缝颜色中的材质行也重新映射。缓存不保存动态覆盖遮罩和父地块 morph，恢复后按当前场景生成。读入长度、区间、材质、接缝与 zlib 校验失败均走重建回退。

保存时编码为独立 byte[]；后台队列容量为 2，队列/处理中字节上限 32 MiB，单记录上限 16 MiB，超额跳过保存。编码仍在网格工作线程进行，压缩与区域写入在后台；不会把整个地块/植被对象图挂到 IO 队列。

## 渲染路径

OpenGL 4.6 支持时采用 8 MiB 共享几何页，最多 16 页（128 MiB 容量上限）。更大的地块、页满或不支持时用原独立缓冲池。该页容量替代对应载荷的独立缓冲，并非在其外再复制一套完整几何；页内碎片和每 cell 4 字节覆盖值仍有额外成本，不能宣称显存下降。

覆盖变化仍更新原 R8 纹理，并同步共享页中的覆盖值；后者供批量片元路径读取。更新使用新切片，旧切片设置 fence；回收采用零等待检查，每次最多处理 16 个，遇到最早尚未完成的 fence 就结束，空页释放。逐地块路径也从共享页加偏移读取，避免频繁切换纹理范围导致驱动开销。

普通渲染只有在至少 64 个实际绘制地块、全部可批量提交、平均可见区间至少 1.25 时启用 MDI。单区间场景保留原着色器和提交；编译不支持时回退。每批最多 512 地块，遇到页切换/回退按原顺序 flush，不跨页重排透明地块。当前每次提交仍组装/上传参数和命令，没有宣称完成命令的跨帧增量缓存。

Iris 实际光影包继续使用原逐地块提交路径（共享几何页与偏移读取已生效）。本轮不默认开启光影批量提交；测试桩通过不等于真实光影兼容。SSBO binding 7 的 buffer/range 和 indirect buffer 在批量结束时恢复。

排查时 JVM 参数 `-Dvss.disableIndirect=true` 可同时禁用新 arena 和批量能力；不是帧率限流，不改变 LOD 精度。

## 正式路径复测

机器 Ryzen 7 7700 / RTX 4070 Ti SUPER，JDK 21。缓存每场景预热 8 轮、交错 31 次取中位数。样例为合成水体/悬崖，包含生产签名计算、区域读取、校验、恢复；已解码采样输入为基线起点。资源指纹初次计算、实际纹理行恢复、植被组合及 GPU 上传不在此计时，操作系统文件缓存为热状态。

| 网格 | 重建 | 区域恢复 + 输入身份 | 耗时减少 | 临时 Java 分配 |
| --- | ---: | ---: | ---: | ---: |
| axis 16 / 834 四边形 | 1.7988 ms | 0.6604 ms | 63.3% | 1.378 → 0.255 MB |
| axis 64 / 17,271 四边形 | 8.5580 ms | 3.0694 ms | 64.1% | 27.367 → 4.086 MB |

证据：`build/production-mesh-cache-final/benchmark.csv`。这里的分配是当前线程的临时分配，不是常驻内存。之前实验的 78%–85% 不应用来描述正式流程。

生产共享页/批量路径测试，128 地块、171,776 总四边形，预热 30 轮、交错 31 次。关闭栅格化隔离顶点和提交，不能换算游戏帧率：

| 可见面组 | 原 CPU → 批量 CPU | 原 GPU → 批量 GPU |
| --- | ---: | ---: |
| 全部面组、合并为单区间 | 0.0393 → 0.0634 ms | 0.121856 → 0.118784 ms |
| 两个不连续面组 | 0.2149 → 0.0505 ms | 0.059392 → 0.070656 ms |

单区间 CPU 回退是收紧启用条件的原因。多区间 CPU 省约 0.164 ms，但 GPU 增加约 0.011 ms；不是普遍 GPU 加速。两行实际选中的几何数量不同，只比较同行前后。证据：`build/production-batch-perf3.log`。

## 验证与交付

- 缓存几何/接缝恢复、父 morph 不复用、资源/颜色/间距身份失效、区域重开、地形失效连带删除和排队写入不能复活旧记录。
- 材质行顺序变化后的模型 UV、阴影属性和光影代表方块恢复；缺失资源拒绝。
- 正式 arena + MDI 与原着色器逐像素颜色/深度对照，覆盖不透明/水体、多区间、遮罩、交错逐地块回退及 SSBO range/indirect 绑定恢复。
- 原有 GPU 回归包括水体、洞口、Voxy 深度交接、Iris MRT、纹理/采样器/混合状态恢复、PBO 隔离、覆盖和场景复用。
- 两仓库完整单元回归及原名称 JAR 构建，具体运行结果见 `build/mesh-batch-final-build.log`。真实游戏 FPS、实际资源包缓存命中率与 AMD 驱动仍需要游戏验证。

最终完整回归：NeoForge 共 958 项，919 通过、39 跳过；Forge 共 960 项，925 通过、35 跳过，均无失败。之后两边单独运行 `PredictionProductionBatchGpuTest` 均通过。最终 GPU 复测多区间 CPU：NeoForge 0.2256 → 0.0618 ms，Forge 0.2091 → 0.0585 ms；GPU 分别增加 0.010240 / 0.011264 ms，与启用条件的取舍一致。日志为各仓库 `build/production-batch-final-gpu.log`。

同步脚本：`tools/prediction/sync-finished-mesh.ps1`。JAR 位于各仓库 `lib/vss-0.3.3-<loader>-<minecraft>.jar`。旧 `.vpr` 地形/植被结果仍可读取；安装后会逐步补齐成品记录，第一次使用新包不能期望全部地块立即命中成品缓存。
