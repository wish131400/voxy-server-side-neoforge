**实现范围与接入路径**

本次迁移 Voxy 的二维切片扫描合并策略：先形成属性相同的横向连续段，再把连续行中相同长度、相同属性的段延伸为矩形。算法独立实现，没有复制或打包 Voxy 源码。实际安装的 NeoForge 0.2.15-beta 和 Forge 0.2.14 扫描器作为外部行为参照；五组规则/混合切片的输出面数与参照一致。

- 新增 `PredictionScanMesher2D`，用可复用的行工作区完成扫描，支持非方形输入、长宽限制、重入和异常后的清理。
- 新增 `PredictionScanMerge`，把整片瓦片中符合条件的轴对齐矩形按方向、平面、完整材质标志、均匀四角颜色/天空光、绕序和归属规则分组，在稀疏 32×32 页面上扫描。每个输出矩形最多 16×16 格，世界跨度最多 256 方块。
- `VssLodGreedyMesher` 的地表/水面采样格合并改用新扫描器，继续遵守调用方原有的覆盖面积限制。所有 Java int 材质键均有效，零和负数不会被错误当成空白。
- 最终 `PredictionPackedMesh` 增加静态 feature 的精确合并。树冠、建筑外墙/屋顶等规则面可跨原来的最近 64 面查找窗口；四角颜色、光照、坐标及面的绕序保持原语义。可 morph 的基础地面不进入这条精确 feature 合并路径。
- `PredictionDisplayGeometry` 的显示变体合并改用整片扫描。原有的世界格点、颜色简化、边缘保护、误差、近处和望远镜回退继续参与选择。
- 显示变体受额外驻留预算限制。更深的档位没有自己的分配时，现在复用已经生成的较细表示及其误差和绘制前缀，避免远处退回完整密集网格；复用只增加选择元数据。

生成时的 `PredictionQuadMerger` 继续承担输出顶点预算前的局部预合并。最终静态 feature 平面合并和显示变体合并已接入新扫描器。完整三维体素降采样、粗体素外壳重建以及 Voxy 代理模型捕获仍属于后续工作。

本次没有降低近处植被的数量，也没有改变上一轮植被 shader。草花的斜向十字面、模型 UV、流体、临时预览和真实地形边界等特殊面不进入最终平面合并。精确合并会保留孔洞、重叠原面和属性不同的边界；无法减少面数的组继续使用原记录，避免将已有大矩形拆碎后反而增面。

**归属、缓存和内存处理**

跨单元合并继续遵守 Voxy 接管语义。固定归属面只有在采样 spacing 已知、所有切向坐标确实位于原单元内时，才可转成逐像素归属；伸出单元的树冠保持固定归属。侧面继续保留垂直方向的归属列，顶面可按 X/Z 像素归属。覆盖撤销/恢复、混合覆盖、直接绘制和 MDI 均已做 GPU 回归。

网格打包、保留 feature 的精化、普通磁盘缓存和城市基础网格缓存读取均接入相同合并路径。缓存读取从 tile manager 取得实际 spacing，先验证原存储记录再合并，已有缓存无需清空即可取得收益。磁盘格式版本没有变化。

合并后的 canonical 数据重新生成地形面组、水面起点、sprite 计数、归属范围和遮挡 bounds。水面尾部记录保持原内容与顺序；磁盘只保存 canonical 数据，不保存追加的显示变体。已有压缩存储、上传后释放原数组和冷恢复路径经过回归。

合并在已有工作线程准备路径执行。每个网格的光栅/扫描预算为 1,048,576 单元，单组页面上限为 2,048；超预算保留原组。精确路径固定格点上限，避免同一缓存重复恢复时不断扩大格点。相机移动只选择已生成的表示，不因移动重新扫描整片网格。

**GPU 验证与合成收益**

显卡为 NVIDIA GeForce RTX 4070 Ti SUPER，驱动 572.70。扫描合并测试使用实际生产 shader，在 X/Y/Z 平面、重复图集 UV、三线性 mipmap、不透明和 alpha 裁剪材质、完整/混合/撤销/恢复归属、直接绘制/MDI 下对照。

不透明覆盖和 alpha 与基线一致，RGB 的最大实测差异为 1/255。合并改变三角形划分，会产生浮点插值微差：256×256 图像中，alpha 裁剪面最多有 52 个边缘像素改变显隐，约 0.079%，差异限制在一像素边缘；没有内部覆盖差异。测试设置 RGB 误差上限 2/255、alpha 边缘上限 0.1%。这不是逐像素完全无差异的渲染保证。尝试过的 UV 稳定化没有进入最终生产 shader，上一轮植被 shader 对照继续通过。

规则叠层合成场景将 65,536 个相邻小面合并为 256 个面，GPU 编码为 1,310,736 → 5,136 字节。每轮绘制四次，预热八轮、交替十五轮后取 GPU 时间查询中位数：

| 合成测试 | NeoForge 旧 → 新 | Forge 旧 → 新 |
| --- | ---: | ---: |
| 关闭光栅，仅测顶点提交 | 0.048128 → 0.003072 ms | 0.048128 → 0.003072 ms |
| 开启光栅 | 0.583680 → 0.035840 ms | 0.582656 → 0.033792 ms |

此表说明规则细碎面能够减少 GPU 工作；合成场景连续属性特别多，不能将这些倍数外推为真实森林、整合包 FPS 或全帧收益。其它已有 GPU 回归的 benchmark 也不属于本次合并的独立收益。

**复现与后续同场景对照**

PowerShell 构建使用仓库根目录，NeoForge 设置 `JAVA_HOME` 为 JDK 21，Forge 设置为 JDK 17：

```powershell
./gradlew.bat --no-daemon --project-cache-dir .gradle-voxy-scan-20261011 `
  -I tools/prediction/feature-handoff-tests.gradle `
  -I tools/prediction/voxy-scan-tests.gradle voxyScanTest jar

# Forge 的 jar 已 finalizedBy reobfJar。
# GPU 对照必须提供实际 Voxy JAR 和上一轮植被包的绝对路径。
./gradlew.bat --no-daemon --project-cache-dir .gradle-voxy-scan-20261011 `
  -I tools/prediction/feature-handoff-tests.gradle `
  -I tools/prediction/voxy-scan-tests.gradle voxyScanGpuTest `
  '-PvssVoxyJar=<对应平台已安装 Voxy JAR>' `
  '-PvssVegetationReferenceJar=<上一轮 vegetation-render-20261011 VSS JAR>'

python tools/prediction/replay-voxy-scan.py `
  --capture C:/Users/Administrator/.codex/tmp/vss-distance-render-20261010/geometry `
  --output C:/Users/Administrator/.codex/tmp/vss-voxy-scan-20261011
```

默认启用新扫描器。诊断 JVM 参数 `-Dvss.disableVoxyScanMerge=true` 可对新生成/读取的数据使用旧地表格合并、旧显示局部 join，并关闭最终 feature 扫描。这个开关不会拆开已经保存为合并矩形的磁盘记录；严格 A/B 需使用同一份合并前缓存的两份副本，或相同的原始捕获语料。

用户可自行换包进入相同世界、位置和视角，等待驻留数据稳定后比较实际提交面数、预测不透明 GPU 时间和 FPS，再移动检查 Voxy 交界、树冠和建筑边缘。当前证据已确认减面和合成 GPU 收益；还没有本轮新包的现场 FPS 数值。

机器可读结果：本报告同名 `.json`，另附 `prediction-voxy-scan-replay-20261011.json` 的逐网格数据。原先调查中的 115 个取样网格、15.80% 合并机会仅是前期估算，本报告采用最终实现的完整回放结果。
