# LOD 弱网发送与重试

入服的世界生成档案仍由 `WorldgenProfileTransfer` 分片后优先发送，不进入普通列的限速队列。
本次改动针对 LOD 列同步的重复请求、重复接收和下游发送积压。
Minecraft 使用 TCP；这里减少的是 VSS 应用层的误超时和整列重试，不能消除 TCP 自身的丢包重传。

## 发送预算

- `totalBandwidthBytesPerSecond`：全服共享的 LOD 列发送字节预算。单个不可继续拆分的分片可暂时透支，后续发送等待预算补足。
- `sendPacketsPerTick`：全服每 tick 实际发送的列数据包数，默认 64，范围 1–4096。世界生成档案初始化不受此项限制。
- 各距离的 `*SyncRateLimitPerTick` 控制请求接纳速率，不等于列数据出站包数。
- 每名玩家最多提前安排 8 个包、512 KiB 的 Netty 编码工作。单个更大的不可拆分包可独占空窗口，避免永久卡住。
- Netty 通道不可写或 BO 已有会话正在等待流式 epoch 确认时，暂缓从该玩家的列队列取包，其他玩家继续轮转发送。
- BO 检查只读取已存在的会话，缺少对应接口时退回通用 Netty 检查。VSS 不创建 BO 会话或改变它的压缩方式。

编码窗口完成标记表示编码工作已通过相应事件循环，不表示客户端已收齐数据。
已交给底层传输的数据不能通过 VSS 取消包撤回。

## 避免整列重复发送

- 相同分片重复到达时保留已收数据，不重复计入接收内存；内容冲突仍拒绝该传输。
- 相同或更旧版本的脏列通知不再次取消请求，也不再次清空部分接收数据或预测网格。
- 服务端最多每 5 秒发送一次批量排队状态。新客户端收到后更新等待期限和部分列的接收期限，不另起生成任务。
- 排队状态只通过可选能力位协商，不向旧客户端发送未知响应。旧客户端维持原有队列过期策略。
- 支持排队状态的客户端等待已有队列继续发送；队列数量、字节上限、移动后的相关性检查、取消和溢出淘汰仍有效。
- 连续真实超时增加重试间隔，成功收齐后恢复快速请求。
- 取消请求立即删除服务端队列内尚未发送的分片；异步读取或生成结果回到发送阶段时还会检查请求是否有效。

## Xaero 保存修复与验证

Xaero 的 tile chunk 可能在可写之前已被创建。每次成功写入、需要保存时都设置地形标记，
让所属 region 能进入 Xaero 自己的保存流程。

`XaeroMapCompatStubContractTest` 覆盖延后首次写入；`XaeroActualJarContractTest` 直接检查发布 JAR
的反射成员和 region 保存标记调用。可使用 `-PvssXaeroJars=绝对路径1|绝对路径2` 指定外部 JAR。
已核对 1.40.16、1.45.0 及 NeoForge/Forge 的 1.46.0。这是接口和保存流程验证，实际整合包仍需入服验证地图写入。
