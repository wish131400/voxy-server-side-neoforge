## 缺口机制和修复范围

上一轮区域交接在稳定 PRESENT 列内直接丢弃预测片元，且整张瓦片被索引覆盖时会退出生成与驻留。现有 Voxy 本地索引把 LOD0 的 32×32 section 映射为 2×2 Minecraft 区块；索引存在及 2 秒等待，都不等同于该边界已有完整可见的 Voxy 地面。这一语义能造成“索引已接管、实际画面尚有缺口”的回退失效。截图形态与此一致，但本轮没有在截图位置重启修复包验证，不能声称已证明截图每一处缺口都出于同一个原因。

现在索引纹理区分三种状态：

- `0`：未知或未稳定，保留预测。
- `128`：已稳定但相邻 3×3 区块存在未知/未稳定项，作为一圈 16 方块宽的边界回退；使用本帧真实深度交接。
- `255`：稳定内部区域，继续按区域直接让位给 Voxy，包括地形和流体。

分类由后台快照完成，不在片元着色器中增加九次邻域读取。`hasRealColumn` 继续把边界视作已知数据，使实际可见的附近地面仍可优先；硬裁剪仅接受内部值。纹理边界保守地保留回退。

CPU 整瓦片退休也要求瓦片外一圈区块全部稳定，避免 GPU 想保留回退、CPU 却已经删除网格。原有三维距离检查、2 秒等待和稳定快照机制继续生效。

这个修复保护索引的外围和洞口边缘，并没有把原本的二维存储索引升级成逐体素/逐高度完整性证明。已知区域内部的存储误报或长期缺失 Voxy mesh 仍需另外诊断；边界层也不等同于对任意高度差自动生成连接面。

## 已修复的 CPU 热点

1. 覆盖查询缓存的空间键由 16×16 Minecraft 区块规范化为最小 64×64 预测瓦片。同一 footprint 内的 16 个区块共享结果；使用向下取整，负坐标边界不串区。局部版本失效和望远镜细节键继续有效。
2. 不含望远镜专用瓦片的快照直接查找当前最细普通所有者，找到满足条件的层级即可结束，避免每次遍历所有 LOD。
3. 普通驻留瓦片的覆盖解析按最小预测瓦片合并，跳过重复的逐区块视距、平方根、LOD 与焦点计算。64×64 精细瓦片的覆盖查询次数从 16 次降为 1 次；大于最小 footprint 的采样仍保留原有粒度。非驻留/望远镜路径保留按视角判断。
4. `fullyAuthoritative` 在没有编辑例外时复用稀疏页位图矩形查询，减少逐区块哈希查询和同步。

没有修改用户的细节距离、线程档位或画质设置。上述计数改善只证明重复工作减少，不等于整体游戏 FPS 提升 16 倍。混合瓦片的片元裁剪仍然需要提交其几何；本轮没有加入容易造成跨区大四边形缺口的逐顶点所有权裁剪。

## 验证与复现

新增 CPU 回归先在修改前代码上运行：9 项中 3 项如预期失败，分别是边缘瓦片提前退休、纹理没有区分内部/边缘、同 footprint 没有共享查询。修复后定向 CPU 套件 54 项全部通过；包含负坐标、跨页、缺失/未稳定邻居、局部发布失效、望远镜驻留及按单元参考算法比较覆盖掩码。

GPU 回归由生产索引快照构建半区覆盖，连续 120 帧切换空白/远处深度与地形、水、熔岩、冰：边界应保留回退，内部应持续裁掉预测。额外验证边界出现附近真实地面时，即使预测更高也正常让位。普通与 Iris，以及普通索引绘制和实验实例绘制均执行了检查。其余 GPU 套件覆盖真实批处理、深度播种、原始 GL 状态、Voxy 边界以及实际 Voxy JAR 的 shader。

最终结果：定向 CPU 54 项通过；独立 GPU 6 项通过、无跳过；全量构建 1,370 项中 1,296 通过、74 跳过、0 失败、0 错误。全量中的跳过项包括另行启用并执行过的 GPU 套件，以及性能实验和需要额外输入的可选测试，跳过不算通过。
