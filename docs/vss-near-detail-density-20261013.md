## 结论与验证边界

客户端实际使用了 `predictionVegetationDensity=medium`，并非只改了配置文件但运行时仍处于高档。草株筛选正常；树冠连成片时，旧逻辑会把多棵独立树干的树木合成一组，造成一片树林共同保留或共同删除。

截图中近处大平台、长灰墙的直接原因是细化需求的入队判断与执行判断不一致：中等覆盖需要升级，但执行中的过期任务检查漏掉这项需求，反复取消任务，阻塞随后依赖它的近处细化。

修复已通过实际预测管理器与工作线程回归，以及同一批真实植被缓存的筛选对照。当前运行中的游戏仍加载旧包；没有替换实例 JAR、重启游戏、修改世界或采到安装修复包后的 FPS。本文的植被数量是缓存方块记录和树干组，不能直接当成 GPU 四边形数量或帧率收益。

## 近处地形为什么一直很粗

六次快照间隔约 3 秒，总窗口 15.002 秒，六次均未暂停。

| 指标 | 开始 | 结束 | 增量 |
| --- | ---: | ---: | ---: |
| 就绪瓦片 | 4172 | 4172 | 0 |
| 已构建 | 8419 | 8419 | 0 |
| 被判为过期并取消的构建 | 36661 | 37501 | 840 |
| 线程池完成任务 | 44352 | 45192 | 840 |
| 在途构建 | 0 | 0 | 0 |

此时 CPU 预算的 8 个槽位均可用，预测核算内存约 933 MiB，空闲堆约 7.7 GiB，没有触发网格内存限制。任务在运行，但没有产生有效细化。

四块近处 LOD3 中等覆盖前沿瓦片位于 `(-1,-1)`、`(-1,0)`、`(0,-1)`、`(0,0)`。它们每块跨度 512 方块，当前网格轴长仅 8，即采样间距约 64 方块；请求目标为 32。执行阶段却返回 `buildDemandCurrent(key,32,false,false)=false`。

原因是此前新增的过期任务取消逻辑只考虑普通地形目标与交接目标，没有包含中等覆盖前沿的启动升级。调度器把任务送入线程池，工作线程又把它取消。附近 108 个可见细瓦片还在等待中等覆盖依赖，因而长期只显示粗级回退。已有成品缓存的远处瓦片可以恢复，形成“远处有细节、近处反而粗”的现象。

修复集中在 `PredictionTileManager`：

1. 入队与工作线程的需求检查统一使用 `targetCellAxis`，包含中等覆盖前沿、普通细化和交接目标。
2. 普通地形目标读取已发布的不可变 `terrainTargets`，避免计划刷新时暂时清空可变叶集合而误取消未改变的任务。
3. `mediumAxis` 同样以不可变目标表判断已发布的叶目标。

最低粗覆盖、脏列修复、Voxy 归属、视野外可选任务停止和缩小后的过期高细节取消仍沿用原有规则。相对于本轮修改前的源码备份，两套管理器都只有上述三处改动。

新增测试先在旧代码上失败，随后在修复上通过：

- `mediumFrontierUpgradeCompletesAndUnlocksLocalRefinement`：实际工作线程完成中等轴长 `8→16→32`，再完成近处叶 `32→64`，没有错误的过期取消，任务和预算租约释放。
- `mediumDemandAlsoSurvivesAnUnchangedLeafSetPublication`：可变叶集合临时清空时，未改变的已发布目标仍有效。

原有转头、缩小后的可选工作取消测试继续通过。

## 植被密度有没有真正按配置工作

低、中、高分别按固定世界位置选择约 25%、50%、100% 的预测草株和树干组。三个档位是稳定的嵌套子集，切换或转头不会随机换一批树。完整原始放置数据仍保留，密度控制的是 VSS 预测显示网格。

这个设置只作用于 VSS 预测植被。原版近处植被，以及 Voxy 已记录的真实区块植被，保持世界原密度。中档的“50%”是大量位置或树干组上的选择率；大小不同的树、局部样本和为避免破坏建筑而保留的木质结构，都会使局部方块数偏离 50%。

### 草株抽样

最先读取的 128 份源区域缓存包含 22,300 条植被方块记录，中档保留 11,134 条，约 49.93%。另有 208 条非植被记录全部保留。

这批样本没有树木，不能用它单独证明森林筛选正常。因此补做了树木样本检查。

### 树冠相连造成的缺陷

旧实现按 26 邻接收集木质和树叶连通块，再使用整个连通块最低树根的坐标决定保留。这会把树冠相接、树干并不相连的多棵树合成一片：一棵树的选择结果控制整个树丛。

补充探针扫描了 512 份源区域缓存、117,912 条方块记录，其中 134 份有木质植被。对照限定为其中 64 份含木质植被的完整源放置图，共 17,942 条木质记录、141 个树冠连通块、246 个独立树干组。其中 55 个连通块包含多个独立树干组。

在同一批不可变源放置图上，对旧运行时筛选和修复后的独立计算助手进行比较：

| 指标 | 旧中档 | 修复中档 |
| --- | ---: | ---: |
| 与各树干根部坐标选择不一致的组数 | 55 | 0 |
| 保留树干组 | 157 | 142 |
| 保留木质方块记录 | 11,916 | 10,948 |

本样本少保留 968 条木质记录，较旧中档减少约 8.12%。这些是源图内的组和方块记录，不是去重后的全世界树木数，也不是 GPU 面数。部分原先被整片删除的树现在会恢复；修复的是每棵树的选择独立性，不是保证每个局部森林都单调变稀。

修复后保留木质记录约为原始记录的 61.02%，并非恰好 50%。这个有限样本中，固定坐标选择保留了 142/246 个树干组，且各组大小不同；不能把配置百分比理解成每一片树林严格删除一半方块。

### 修复方式与缓存兼容

- 先完成源图树冠收集，再按相连树干分组；大树宽树干、斜向枝干继续作为同一组。
- 树冠相接但树干独立时，各树干根坐标独立决定保留。
- 多组共用树冠用确定的多源遍历分配，等距离按根坐标排序，保证输出不依赖源图遍历顺序或密度档位。
- 保留下来的树冠连接到保留的树干；完整草株使用同一个 X/Z 选择结果。
- 没有树干的树冠、没有树冠的木材、与建筑部件相连的木质组继续保留，避免误删建筑。
- 低、中档的成品显示网格缓存身份增加筛选版本位，旧网格不会被当成新结果恢复；高档身份与原始放置缓存身份保持兼容。因此无需手工删除预测缓存。
- 更新设置帮助及中英文提示，说明 VSS 预测范围、独立树干组和局部数量差异。

确定性密林测试构造 64 棵树冠相接的树，结果为低档 13/64、中档 31/64、高档 64/64 个树干组；对应 143、341、704 条方块记录。另覆盖宽树干、枝干、共享树冠、跨显示瓦片边界、子集关系和缓存版本兼容。

比较助手只在独立类中执行计算，没有替换运行中的生产类、修改源放置图或改变实际画面。
