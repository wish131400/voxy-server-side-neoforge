# 静态火焰、植被缓存与精细地形恢复

## 问题与依据

预测火焰此前走通用植物交叉面：兜底色为 `0xFF65934A`，颜色取上表面、贴图取侧面。材质缺失时会留下绿色实心面，两个面的平均颜色不同也会造成错误归一化。旧实现没有预留火焰材质行。当前主世界运行快照只有 145 行，不能据此断言用户下界截图一定由 254 行容量耗尽触发。

对照本地 Voxy 源码 `ModelTextureBakery.bakeBlockModel`、`ModelFactory`：Voxy 将模型及纹理外观烘焙后复用；没有找到专门为每团火持续模拟的分支。本次借用静态外观复用思路，保留 VSS 的轻量交叉面。

本次主世界运行时累计诊断：地表装饰磁盘命中 10,110 次、内存命中 3,774 次，新生成装饰区块 8 个；地形磁盘命中 2,470 次。45 秒 JFR 中预测工作线程的执行样本同时涉及地形采样、网格压缩与打包。运行时累计计时还包含采样、颜色、网格阶段，不能把全部重进等待归因于重新放树，也不能把累计计时当作该 45 秒窗口的独占耗时。

## 实现

- 优先登记普通火和灵魂火，从资源包的 `fire_0` / `soul_fire_0` 原始图片截取第一个图像帧，采样为共享 16×16 静态外观。保留 alpha 轮廓、分别使用橙色和蓝色兜底，不乘树叶色。资源重载时清理重建。
- 静态像素放入现有材质表，复用纹理单元；每类火只保留一份，不增加每团火的动画任务。普通渲染使用自发光效果，Iris 接口提交满亮光照坐标。远处平均颜色模式仍读取静态轮廓。最多增加约 128 KiB 材质表显存，CPU 像素副本共 2 KiB，另有容器开销。
- 主线程只提交当前规划的缓存键。后台每批最多探测 128 个压缩文件头，验证身份及采样轴长度，批次自动衔接，并让写入/失效操作穿插执行。提示索引最多 32,768 项，不扫描整个存档目录。
- 命中且比驻留地形更精细的缓存走独立恢复准入，最多两个任务；任务完成后自动补位。绕过父级/中等覆盖/普通精细化的生成等待，仍使用现有内存预约、失效 epoch、网格上限及 GPU 上传预算。
- 缓存头只是提示，正式读取仍校验完整载荷、身份及压缩校验和。读取失败、过期、损坏时，恢复任务退出且清除正向提示，绝不在这个通道中回退到昂贵的地形生成。普通生成流程随后补缺。
- 已规范化的地表缓存使用 schema 4 标记，直接复用竹子和树叶状态；schema 3 装饰缓存仍可读取，修整一次后升级。旧地形 schema 1/2/3 继续可用，不清空世界缓存。
- 植被缓存显示查询按所需坐标窗口直接查哈希表；大范围稀疏查询若遍历现有区块更省，则遍历驻留项。两种方式选择预计访问项较少者。
- 修正下界装饰设置位 `96` 未纳入区块编辑磁盘失效的问题，避免新恢复路径读回过期下界装饰。

## 为什么仍不承诺整个世界秒加载

VSS 缓存的是采样结果、颜色与装饰方块，不是可直接显示的 GPU 网格。哈希定位可以减少寻找和调度等待，但解压、状态解析、网格构建/压缩、打包、GPU 上传仍有成本。Voxy 也需要构网，但其持久化多级体素和渲染调度与 VSS 不同。

本次直接恢复的是当前规划需要、且磁盘确实保存过的采样精度。只有粗数据的缓存不会凭空变精细；世界生成身份、配置身份不匹配或被编辑失效的缓存必须重新生成。植被的完整发布仍遵循地表任务流程，本次减少其缓存整理成本，并未持久化 GPU 网格或绕过所有地表任务准入。

## 验证

- 磁盘往返、旧版兼容、损坏、截断、身份不符、脏区块、旧会话写入失效；新增连续多批探测与下界装饰失效测试。
- 实际管理器测试：精细缓存无父级直接生成可上传网格，地形采样调用为零；损坏文件退出恢复通道，采样仍为零。
- 恢复并发测试：最多两个待处理恢复任务；不调用规划 tick，也能自动补位完成八个精细缓存。
- GPU 回归使用生产着色器，验证普通/Iris 两路径、近处贴图/远处平均颜色模式下普通火与灵魂火的颜色和透明像素，另覆盖已有渲染交接和 GL 状态回归。
- 固定植被读回基准：32 区块、3,643 方块；2 轮预热、7 轮交错顺序，取中位数，验证两种处理结果一致。最终完整回归中 NeoForge 为 6.476 ms → 4.901 ms（耗时减少 24.3%），Forge 为 5.972 ms → 4.398 ms（减少 26.4%）。此前运行有约 19%–34% 的改善，说明存在运行环境波动。这是读回/整理阶段的微基准，包含缓存数据读取和结果比较，不含整个世界初始化、组网及 GPU 上传，不能当作整体 FPS 或加载时间增益。

保持 Java 与 Rust 后端共同可用；本次不修改 native ABI。两端产物继续放 `lib/vss-0.3.1-neoforge-1.21.1.jar` 与 `lib/vss-0.3.1-forge-1.20.1.jar`。需要重启加载新包后，才能验证用户原下界位置和整包重进耗时；当前运行游戏没有被替换或重启。
