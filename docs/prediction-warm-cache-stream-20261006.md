# 预测 LOD 缓存恢复与远景首屏加载

日期：2026-10-06。同步目标：NeoForge 1.21.1、Forge 1.20.1。

## 问题与目标

已有地形缓存不等于成品网格可以直接显示。原来的 cacheOnly 任务与预测生成共用执行器、CPU 准入和生成工作槽；成品网格不匹配时，还会继续执行采样、植被处理和网格生成，长期占用缓存恢复名额。GPU 上传另有每帧两个瓦片的数量限制，即便粗网格很小，也无法利用剩余上传时间批量恢复。

参考本地 Voxy 源码中优先处理较粗层级、从已有层级区段恢复可绘制覆盖的机制，本轮目标是让有效缓存优先铺出远景轮廓，再补细节。没有将所有 GPU 上传集中到一帧。

## 实现

1. `PredictionTileManager` 新增独立缓存执行器：最多两个后台线程，最多四个缓存任务在途，空闲线程 15 秒后退出。缓存恢复不占生成 CPU 配额和生成工作槽，仍申请共享内存预算，每个活动恢复预留 128 MiB，发布时转成常驻数据计账。
2. 缓存专用任务只尝试恢复通过现有校验的成品网格。成品未命中时退出，将该键的恢复尝试退避五秒，后续由正常规划与生成路径补齐；不会在缓存执行器内执行完整世界生成。新增 `cacheFastMisses` 和 `cacheWorkers` 诊断。
3. 缓存候选先处理尚无常驻瓦片的区域，然后按较粗 LOD、距离排序。GPU 上传也先处理尚无 GPU 瓦片的区域，并优先较粗层级，再考虑原有工作优先级与距离。
4. 每帧上传数量上限从 2 调整到 16。保持原有 4 MiB、2 ms 软预算和必需交接成本预留；小网格可以同帧恢复多个，大网格仍受字节/时间限制。首个超大瓦片的保底前进规则保持有效，时间预算不是严格抢占式上限。
5. 暂停时取消缓存队列中未启动任务、打断活动任务；退出存档时同时关闭生成与缓存执行器，后台释放器等待二者结束后再释放采样器和原生资源。保留版本、捕获代次和磁盘租约检查，过期恢复不能发布。

未降低城市、材质或资源签名校验，也未更改网格缓存签名版本；本轮本身不要求清空缓存或全量重建。现有 GPU 驻留预算和移动保护逻辑继续参与上传准入。

## 验证

使用独立 Gradle 初始化脚本 `C:/Users/Administrator/.codex/tmp/vss-warm-stream-20261006/tests.gradle`，执行 `warmStreamTest assemble`。Forge 使用 JDK 21。

- NeoForge：48 项通过，失败、错误、跳过均为 0。
- Forge：50 项通过，失败、错误、跳过均为 0。
- 验证生成执行器、CPU 槽和生成内存工作槽被占用时，缓存仍可恢复完整地形与植被，输出与冷生成一致，新增采样和植被放置均为 0。
- 验证不兼容成品缓存不会在缓存线程中重放植被，重复尝试会退避，普通生成仍可修复该记录。
- 验证暂停拒绝过期发布；释放采样器必须等待缓存线程退出。
- 验证同帧可以上传 16 个足够小的瓦片，耗时或字节预算用完仍停止；实际渲染帧事件会补充下一帧预算；父级覆盖持续到子级实际上传完成。
- 兼容现有 GPU 驻留、CPU 配额和内存生命周期测试。

验证期间还修正了两个测试适配问题：暖缓存测试签名补入已有植被密度设置，旧网格记录测试明确使用格式 8。望远镜范围缓存测试的原有失败已通过独立编译修改前源码复现；前者是测试遗漏配置字段，并非本轮修改了游戏签名规则。

## 边界与后续验证

尚未替换正在运行的客户端 JAR，也未测量新包在当前存档的实际首屏时间。因此不能把数量上限提高八倍解读为加载速度提升八倍。

有效成品缓存走加速恢复；缺失、不兼容或被真实世界更新失效的部分仍需生成。城市签名不匹配、资源身份初始化、成品恢复后的 GPU 重新打包仍可能影响速度，本轮没有宣称这些原因全部解决。相同设置、同一区域重进时，应分别比较粗覆盖出现时间、细节完成时间、`finishedMeshRestores`、`cacheFastMisses`、`cacheWorkers` 和上传耗时；缓存目录无需删除。
