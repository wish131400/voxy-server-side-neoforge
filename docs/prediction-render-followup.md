# 预测渲染后续优化：消除入口排序与重复接缝检查

日期：2026-09-20。根据 00:06:06–00:07:06 新包实机 JFR 和 GPU 计时定位问题。本次仍不改变帧率熔断、采样精度、工作线程数或近远加载顺序。

## 已确认的问题

光影不透明/透明回调入口使用 readyTiles(...).isEmpty() 判空，而 readyTiles 每次复制全部 ready 数据、按 LOD 排序、再生成不可变列表。它发生在上一轮 FramePlan 复用之前；JFR 反复捕捉到了它的复制与排序。

生产渲染的归属遮罩在发布后不再原地修改，但 GPU 缓存之前每帧仍与防御性副本执行 Arrays.equals。接缝处理同样会为未变化的输入重新创建 Surface、活动集合和 Draw 列表；可见集只有少量变化时，所有存量接缝仍逐边查询邻居。

## 实施

1. 新增 hasReadyTiles 存在性查询。直接查询并发 ready 集合，无需持有 manager 的 synchronized 锁，不构建、排序或复制网格列表。Iris 两个回调都使用它；真正需要完整列表的其他调用保留原语义。
2. GPU 新增仅供渲染器使用的 updatePublishedCoverage 路径。以不可变发布数组的身份识别同一遮罩，命中时跳过数组比较和上传。通用 updateCoverage 仍做防御性比较，继续支持调用方原地修改；通用调用、网格替换或资源清理使快速路径失效。重新求值但内容相同的 TileCoverage 会复用之前的发布数组。
3. 缓存当前接缝选择集合。只有 tile 或遮罩身份、成员发生变化才创建新输入并运行预测接缝更新；镜头改变排序而成员未变化时直接复用。真实区块边界使用 PredictionVanillaMask 已有的不可变边列表身份作为独立失效条件。
4. 接缝绘制批次按 Patch 列表身份复用。稳定帧跳过活动集合分配、ensureSeams/updateCoverage 及接缝 Draw 重建；移除、重新出现和资源清理会正确重建/退休 GPU 资源。
5. 对少量变化使用保守区域判断：只要改变的旧/新 tile 覆盖范围可能影响某块的邻居查询，就继续完整检查该块；其余直接复用缓存接缝。包含负坐标、接触边界和父子重叠。旧/新变化区域多于 64 项时使用原来的完整检查，避免新增判断退化。
6. RenderSnapshot 按各 LOD 的实际 tile 数量预分配索引容量，减少构建时的扩容和重排。快照仍在数据/归属确实失效时重建，没有延迟或放宽交接一致性。

诊断中的 wallIndex 新增 localReuses，记录局部变化中跳过逐边邻居检查的次数。保留上一轮的 CPU/GPU 计时。

## 验证

NeoForge 1.21.1 与 Forge 1.20.1 均构建成功，各通过 8 个测试套件、38 个针对性用例，失败、错误和跳过均为 0。最终 JAR 已核对新代码标记，并逐字校验包内 5 个平台的原生库与资源源文件一致；结果记录在各仓库 build/render-second-verification.json。

针对性检查包括：存在性查询的空/发布/关闭生命周期；同帧视图/资源失效；未变化接缝排序复用、归属更新、移除和世界重置；局部接缝与从零完整重算的逐字数组对照；大范围转视角；望远镜与普通 LOD 归属；上传父子交接；生产 OpenGL 普通/Iris 像素回归。

GPU 回归额外验证发布遮罩新旧身份、通用调用的原地修改、资源重置后重新上传，以及接缝批次的复用/删除/重新出现。验证运行在本机 NVIDIA 隐藏 OpenGL 上下文，不代表玩家光影包和 AMD 验收。

局部对照证明省掉了无关边界查询且输出一致；现有 warm/cold 接缝计时包含此前已有缓存收益，不能用来宣称本轮相对上一版的 FPS 增幅。本轮尚未在重启后的游戏里做新旧包同场景 A/B。

## 产物与安装

两个仓库的 lib/vss-0.3-*.jar 更新，保留 Forge 1.20.1 的事件/Oculus 适配。替换对应 JAR 后重启，不需要清理预测或 Voxy 缓存。运行中的游戏不会自动切换到新的类。

接缝仍在渲染线程执行发生变化的部分，本轮没有迁移至后台，也没有改变几何绕序/开启全局背面剔除。
