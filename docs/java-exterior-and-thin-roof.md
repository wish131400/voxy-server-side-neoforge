# Java 外侧空洞批量采样与薄层屋顶长墙修复

保持 0.3.3 和原 jar 文件名，输出在各仓库 `lib`。本次没有修改原生库。

## Java 路径

此前 `ClientTerrainSampler.exteriorFootprint` 对占地内每根柱调用 Minecraft 完整 `getBaseColumn`。现在新增 `PredictionJavaExterior`，采用与 Rust 相同的有界高度查询、噪声格内复用、整格非空气并集和已确认高度提前停止策略。继续使用 Minecraft 的 NoiseChunk、插值、实际 FluidPicker、含水层和材质判定，不用近似密度代替原结果。

`PredictionDensityOrder` 只分析图，不改写图。普通原版图按需要访问垂直格；Cache2D 包裹垂直依赖、未知或编译后的模组节点保留原求值顺序，但到所需下界就停止，且不创建完整 NoiseColumn。这与 Rust 对有状态密度图保留顺序的原则一致。新工作区限于一次查询，不增加全世界柱缓存；图分析与反射句柄不在每个采样点重复创建。

Java 仍使用 Minecraft 的完整非空气状态判定，未像 Rust 一样单独移除矿石分类。本次不承诺 Java 与 Rust 相同的绝对速度，也不是整个地形生成器的替换。

## 同负载 A/B

使用游戏只读导出的 worldgen.json，seed=5052304137288917019。固定原密度图，用测试注册表的平原生物群系替代动态生物群系来源，移除测试环境没有注册的装饰状态定义；测量目标为外侧空洞补采样，不包含装饰生成与实时游戏渲染。每个坐标/步长为 66×66 网格，先建立相同原始样本，然后交替运行旧 Java 完整柱与新 Java 路径三轮。表内为耗时中位数；不同步长覆盖面积不同，只应横向比较。

缓存样本再次 enrich 时，新路径旧山体约 0.08–0.11 ms，新山体步长 1 约 0.07 ms，步长 2/4 分别约 38.29/17.26 ms。后两项仍会重试未通过锚点屋顶校验的候选，不能表述为“所有缓存命中都零计算”。测试时游戏继续运行，数值为本机离线回放，非整世界加载或 FPS 比例。

## 本次截图长柱

用户提供坐标 1605,156,-1456。只读捕获到附近已发布网格：1610,-1460 的样本记录实体段 `[-64,63),[71,98),[160,161)`，但 GPU 数据中存在 Y=97..160 的泥土色长墙；1602,-1456 同样是一格厚屋顶，上下实体之间是大片空气。安装包里的相关网格类与当前源码编译结果一致。

`addEditedGround` 允许地表替换将高度降到最上方实体段的底部。此时顶层已全部被切掉，后续 capture 因新锚点落在空气中而拒绝记录区间，临时样本退回实心高度场，产生长墙。旧保护只处理“低于底部”，遗漏了“等于底部”。现在完整保留这种悬空屋顶的地形占用，不允许这类表面切割抹掉其空洞证明。

回归用现场 `98..160` 空气区间和 `160..161` 一格屋顶构造地表替换。旧代码稳定失败，报告 `wall inside air: 98.0..160.0`；修正后 1/2/4 方块步长均通过，并检查打包后的四边形不穿过空气。此前下层积雪不能切掉上方山体的测试仍通过。

此修复仅改变网格阶段的边界判断，不新增密度查询。成品网格缓存版本从 6 到 7，使错误长墙自动重建；已有地形、空洞区间和装饰缓存保留。没有替换运行中的游戏 jar，最终截图位置视觉效果仍需使用新包后确认。
