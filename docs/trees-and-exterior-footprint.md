# 树木分层缺面与山体补采样优化（2026-09-23）

用户提供的两张图显示金合欢、云杉树冠/树干被水平切断；同时上一轮山体空洞修复后整体细化显著变慢。本次保持 0.3.3 版本与现有 jar 文件名。

## 原因与修改

`PredictionVegetation.Tile.withExteriorEnvelope` 只保留同一 XZ 上最上方连续实体段，并用邻列最高点遮掉它以下的侧面。该假设对分层树冠、树冠下方的树干不成立。现使用真实相邻方块占用判断与连续面合并，保留原方块位置、材质和空气间隔，不增加植被世界生成。原草本稀疏策略与网格硬上限保留。64 棵分层测试树、12,416 个方块生成 144,768 个顶点；密集连续树冠的 36,864 个方块经面合并生成 31,104 个顶点。

对于 16,384 个完全孤立方块的病理测试，完整几何确实无法落入现有硬上限。现在触发原有几何限制并保留粗网格，而不会为通过预算暗中删除下层。该内存测试已改为验证正确拒绝和原方块保留，不能解释成“任何密度的森林都能保留全部精细几何”。

`PredictionExteriorColumns.enrich` 原先针对待检查位置逐列通过 JNI 请求完整世界高度、完整材质的 base column。2×2/4×4 粗格为避免误挖岩石，需要覆盖整个占地范围，导致重复分配密度工作区并计算很多已经无关的高度。

新增 `exteriorFootprint`：一次 JNI 完成一个 1/2/4 方块格的严格非空气并集；只读取所需高度范围，同一噪声格复用工作区，一个高度已被证实存在实体便不再检查后续列的该高度。固体矿石分类不影响非空气判定，因此安全路径跳过矿石材质运算，液体/含水层仍精确求值。它不是单点代替整格，也不减少空洞采样的空间精度。

依赖完整求值顺序的密度图使用原完整柱路径；默认材质为空气的特殊世界回退到原状态 ID 查询；旧 ABI 6 库没有新增函数时也回退。Java 后端保留 Minecraft 原柱算法，本次不能承诺同等速度提升。工作区仅在单次有界调用内存活，不新增长期全世界柱缓存。

网格缓存版本从 5 调整到 6，防止继续显示缺层树木。地形、装饰、已有空洞摘要缓存有效；仅旧成品网格需重建。

## Meridian 0.1.5 源码对照

查看本地 `meridian/audit-0.1.5/.../client/lod/mesh/LodMeshBuilder.java` 的 `resolveSpans`、`wall`、`seams`、`exposed`、`subtract`、`rows` 和 `LodColumnSpans.java`。

它用已有高度、上段底部、下段顶部/底部组成最多两个实体区间，扣除邻列实体区间后生成露出侧面，处理形变差形成的局部接缝，并由 WallRuns 合并。网格阶段这些函数不重新查询密度。此次借鉴的是消费已有区间、按需要计算、复用局部结果的思路；保留 VSS 已修好的多段空洞，未限制为 Meridian 的两个区间。这里审查的是可见 Java 源码，不能由此断言其原生采样免费，也不是两模组整体速度横评。

## 同负载 A/B

`PredictionMountainReplayTest` 使用原问题山体 seed=5052304137288917019 和同一导出的世界生成图。66×66 采样网格，步长 1/2/4；每个步长覆盖的世界面积不同，所以只比较同一行。旧 Rust 通过旧 columns JNI，全新 Rust 通过新 footprint JNI，同一测试进程交替顺序运行三轮，以下是冷补采样时间中位数。

| 步长 | 旧 Rust | 新 Rust | 加速 | 耗时减少 |
| --- | ---: | ---: | ---: | ---: |
| 1 方块 | 731.70 ms | 158.62 ms | 4.61× | 78.3% |
| 2 方块 | 1238.17 ms | 102.80 ms | 12.04× | 91.7% |
| 4 方块 | 1984.10 ms | 73.10 ms | 27.14× | 96.3% |

逐样本断言旧 Rust、新 Rust、Java 的高度、材质元数据、全部实体区间和标记一致。52 根历史山体柱中的 1,634 个空洞位置通过校验。三个步长的多段柱数分别为 1,154 / 488 / 174，地形网格顶点数分别为 84,042 / 81,672 / 76,902，前后相同。缓存后的再检查低于 1 ms。

这是空洞补采样阶段的耗时，未包含完整植被生成、磁盘读取、网格打包、上传与渲染，不能等同于整世界或 FPS 提升。原生单元测试还覆盖四种维度、负坐标噪声格跨界、薄层、含水层及有状态求值回退。
