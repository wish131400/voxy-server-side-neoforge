# 望远镜黑屏、移动卡顿修复与多帧生成评估

日期：2026-09-20。

## 录像与现场证据

录像 `2026-09-20 00-20-12.mkv` 为 14.67 秒、60 FPS 录制。约 7.42–8.07、8.67–9.30、9.95–10.60、11.25–11.68 秒出现黑色覆盖，小地图、准星和快捷栏仍可见。此前望远镜边框先缩小再异常放大。原会话归档日志显示 00:19:09 已关闭 Iris 光影，00:20:19 和 00:20:24 的帧间隔分别为 523.3 和 468.3 毫秒。

Minecraft Gui 的望远镜动画使用 `lerp(0.5 * deltaTicks, scopeScale, 1.125)`，没有限制插值系数。当单帧超过 100 毫秒时会越过目标；持续超过 200 毫秒时可能交替发散。缩放为负后，外围黑色矩形可以覆盖全部世界视图。该机制与录像形态一致，慢帧序列测试能复现原公式产生负值；尚不能仅凭录像排除其他场景中的独立黑屏原因。

用户在本轮调查期间重启游戏，已核实安装的是上一轮的 `b800f5e8...` 包。新进程 43088 的 JFR 覆盖 00:34:13–00:35:28。4013 个渲染线程执行/原生采样中，2223 个包含 `RenderSnapshot` 构造，1943 个直接落在构造方法；这约 55.4% 的包含率是采样热点比例，不是整段精确 CPU 时间比例，也不是用户确认的前后台 A/B。

热点在望远镜归属族判定：每个 scopeOnly tile 都遍历全部 tile。保留的望远镜缓存越多，CPU 发布快照和 GPU 驻留快照重建越贵。原有 PREPARE 计时不包含所有入口快照工作，因此不能只凭该计时较低就排除主线程准备瓶颈。新采样也有 GC 长停顿，最大约 148 毫秒；此次没有把所有掉帧归到单一原因。

证据文件保存在 NeoForge `build/blackflash-20260920/`：联系表、逐帧亮度记录、录像时段日志、JFR 和采样分析。

## 修复

- 仅限制望远镜动画插值系数在 0–1 内，正常帧原值保留，慢帧直接收敛。NeoForge 修补 `Gui.renderCameraOverlays`；Forge 同时覆盖原版 Gui 与实际使用的 ForgeGui 独立望远镜层。没有新增遮罩、帧率熔断或 OpenGL 状态查询。
- 归属族索引改为四叉树祖先集合与祖先查找，复杂度由 `scopeTiles * allTiles` 降为 `LOD层数 * (scopeTiles + allTiles)`。负坐标继续使用算术右移，并保留维度隔离、相同 tile、父子双方的归属关系。
- 保持快照失效、GPU 上传完成后交接、普通细化单调性和望远镜缓存复用规则。没有为了加速而清掉精细缓存或延迟更新归属。

同一测试进程内对照旧生产扫描与新算法：8192 个 tile、1638 个 scopeOnly tile，原扫描 13,418,496 对。预热后 6 轮的中位耗时如下，输出集合逐项相同：

| 版本 | 旧归属族扫描 | 新归属族索引 |
| --- | ---: | ---: |
| NeoForge 1.21.1 | 103.512 ms | 1.559 ms |
| Forge 1.20.1 | 107.606 ms | 1.922 ms |

该结果只衡量归属族构建步骤，不代表全快照耗时、整帧耗时或实际 FPS 倍率。该测试运行时游戏和另一个版本构建也在运行，绝对值可能波动。

两个版本均构建成功，各通过 7 个测试套件、23 个用例，无失败、错误或跳过。检查覆盖慢帧插值、直接核对游戏字节码中的注入调用与 scopeScale 写入、混合维度/负坐标/父子/移除的旧新算法对照，以及普通与 Iris 的已有像素回归。Forge 成品的 refmap 已确认包含原版 Gui 和 ForgeGui 两个路径的 lerp 映射；每包的 5 个平台原生库也已核对。测试结果与包校验分别在各仓库 build/blackflash-results 和 build/blackflash-verification.json。

## mfg-unlock 能否直接接入

结论：不能直接接入当前 VSS；完整帧生成可以作为独立渲染桥接项目研究，本轮不加入运行时。

核对的源码与官方文档：

- [mfg-unlock README](https://github.com/matiasLombo/mfg-unlock/blob/d718fe89d1f37a466dfd57225ea2b5d976d5ec29/README.md)
- [代理 DLL 与补丁入口](https://github.com/matiasLombo/mfg-unlock/blob/d718fe89d1f37a466dfd57225ea2b5d976d5ec29/src/proxy.cpp)
- [slInit 拦截](https://github.com/matiasLombo/mfg-unlock/blob/d718fe89d1f37a466dfd57225ea2b5d976d5ec29/src/slinit.h)
- [NVIDIA Streamline DLSS-G 接入指南](https://github.com/NVIDIA-RTX/Streamline/blob/2122257e0fce486f91b385aa63b9a09b0a34b363/docs/ProgrammingGuideDLSS_G.md)

该项目修改已经加载的 DLSS-G/Streamline 模块，解除作者报告的 Ada 倍率限制并调整出帧节奏。README 的 RTX 4070 Ti 测试结论属于作者的游戏/驱动环境；本次没有在 Minecraft 验证其解锁，也没有运行或安装代理 DLL。项目不是一个从 OpenGL 画面直接生成完整插帧的独立实现。

| 接入条件 | 当前 VSS |
| --- | --- |
| D3D12/Vulkan 设备及可由 Streamline 管理的呈现链 | Minecraft/Voxy/Iris 使用 OpenGL；VSS 只是参与其中的 LOD pass |
| 全场景深度和稠密运动向量 | 有预测深度与部分共享真实深度；没有覆盖实体、手持物、粒子、植被动画的统一运动向量 |
| 最终场景颜色、HUD 分离、每帧矩阵和历史 | 需要在整个游戏最终合成阶段接入，不能只给预测地形单独插帧 |
| 呈现时序、资源同步、Reflex、尺寸/窗口切换处理 | 需要新建原生桥接与生命周期管理 |
| 跨显卡 | 该解锁项目针对 NVIDIA DLSS-G；不能给 AMD 提供相同功能 |

如果研究原生接入，第一阶段应只验证 OpenGL 与 D3D12/Vulkan 共享完整场景资源、同步和呈现的成本；随后补齐运动向量/HUD/历史资源，再验证基础帧生成与 Iris/Voxy 兼容，最后才有讨论 MFG 倍率的前提。这不是单独替换 VSS 地形着色器能完成的功能。

帧生成能够提高基础帧率稳定时的显示流畅度，但不会加快区块采样、快照计算或游戏逻辑；生成帧不等于新的输入响应。它会增加 GPU 工作、显存和同步成本，源帧黑屏或长停顿也不能可靠靠插帧消除。现阶段优先修复已测到的约百毫秒 CPU 扫描和望远镜动画异常，再讨论完整画面帧生成。

新包仍输出到两个仓库的 `lib/`。本轮不替换运行中游戏的 JAR；需退出、替换、重启验证，不需要清缓存。
