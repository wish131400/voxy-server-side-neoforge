# 预测远景发布卡顿修复

适用于 VSS 0.3.6 的 NeoForge 1.21.1 与 Forge 1.20.1，构建标识 `stutter-repair-20261028`。

本次处理移动期间偶发的长帧。此前发布预测数据时，在共享锁内反复判断大量区段与邻面的覆盖关系；画面线程更新需求窗口时等待同一把锁，还会连带阻塞数据发布和缓存完成回调。一次游玩采样中，这类等待最高约 522 毫秒，对应约 539 毫秒的长帧。

- 发布分成捕获局部输入、后台计算变化、短暂提交三个步骤。昂贵的覆盖判断在锁外完成，提交只核对本区域的证据是否仍然有效；其他区域发布数据不会使本区域反复重算。
- 区段与六个邻面的缓存位置共用空间索引，只查询变化区域及其光照影响范围。缓存淘汰、失效、映射器重载和退出维度同步清理索引。
- 同一原生等级和水平位置的覆盖判断由各个高度与邻面复用。按覆盖瓦片的大小建立局部索引，减少密集植被和混合精度区域的重复扫描。
- 需求窗口更新与细化请求在后台交接，画面线程负责接收结果和任务准入。暂时忙碌、移动和退出时分别处理未消费的需求，避免靠丢弃请求绕开等待。
- 体素摘要仍使用相同的 SHA-256 内容与字节顺序，改为批量读取，并复用工作线程缓冲。真实内容比较、邻面比较和重复通知抑制继续生效。

自动回归覆盖混合精度与负坐标的归属判断、缓存引用计数、发布准备期间新建的缓存、并发局部发布、需求交接、冷暖缓存加载及 Voxy 入口。离线密集区域测试中，28,672 次查询复用 256 份水平判断，访问 2,048 次局部覆盖瓦片；它验证重复工作已减少，不能换算为游戏帧率。

本次保留已有预测距离、采样精度、完整植被、Rust / Java 计算与 Voxy 统一渲染。实际跑图长帧与加载速度需要替换此构建并重新进入游戏后测量，当前验证不代表所有整合包和光影下都已消除卡顿。
