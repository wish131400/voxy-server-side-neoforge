# Streams Reflowing 2.16.2 and VSS virtual feature placement

The 2026-11-06 client log contains the same failure for `minecraft:trees_plains` and dozens of unrelated placed features: `UnsupportedOperationException: VSS feature stamp level does not support getLevel` at `StreamsWorldgen.engine`. Reusable tree models fail before placing any logs/leaves (`built=4, fallback=4, placed=0`), so the old OTTYG-only height fix does not address this log. The far decoration path is uninitialized in that scene. Mangrove logs/leaves/roots prove some existing/other decoration geometry reaches the renderer; they do not prove the tree model build succeeds.

VSS normally calls `ConfiguredFeature.place` in exact placement, reusable tree model capture, and distant template capture. Streams Reflowing 2.16.2 attaches a pre-placement callback to that wrapper and requires a real `ServerLevel` before the normal feature runs. VSS intentionally does not expose a live server from its isolated `FeatureStampLevel`; supplying one would risk real-world reads, mutating server state and deadlocks on the client worker.

Only when Streams Reflowing is installed and the world is a VSS-owned `FeatureStampLevel`, `PredictionConfiguredFeaturePlacement` uses the underlying `Feature.place` with the same level, generator, random, position and configuration context. Existing placement modifiers and biome filtering still run through VSS's placement stage; real chunk generation and ordinary worlds keep the original configured wrapper. If another mod's own feature requires live server state, VSS still rejects that individual feature. The fix does not predict Streams Reflowing's river/stream modifications in remote terrain; missing those server-side changes can still cause local differences in riverside vegetation.

The `1 << 19` runtime settings bit is conditional on Streams Reflowing and invalidates old empty decoration/final voxel cache entries for its users only. No raw terrain data or serialized cache format is changed. Source includes focused tests for direct vanilla tree placement equivalence, real-world rejection and configured-wrapper bypass. A live mixed-mod game session and the screenshot comparison remain necessary to confirm rendering.
