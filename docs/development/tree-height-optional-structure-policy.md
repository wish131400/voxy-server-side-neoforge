# OTTYG 5.3.5 高度检查与 Structurify 可选结构策略

## 背景

用户的最新日志显示 Rust 已启用、预测任务仍在运行，但 30 个装饰特征报 `World generation profile ... getLevel`，树木模型为零。`farDecoration=uninitialized`，所以之前针对远距离平地模板的修改没有走到这次的故障路径。实际安装的是 OTTYG 5.3.5；该版本的两个 NBT 树木特征都在 `testHeightLimit` 中执行 `WorldGenLevel.getLevel().getChunkSource().getGenerator()`。VSS 的虚拟装饰世界故意不暴露实时 `ServerLevel`，这条读取因此失败。

## 修改

混入只将两个树木特征限高辅助函数中的三级查询转发到预测快照的 `ChunkGenerator`，保留树木库自身的高度策略和方块裁剪；普通世界继续调用原有服务端方法。混入使用 `require=0`，旧版树木库没有辅助函数时不强制注入。增加装饰缓存设置位以重新生成旧的空树木结果，并记录出错特征和首个调用位置，便于发现其他问题。

服务端仅在 `ModList.get().isLoaded("structurify")` 为真时读取 Structurify 的运行时配置，并给世界生成快照增加 `vss_structure_policy`。未安装时返回 null，不添加字段；客户端保留原有结构预测流程。已安装时，Structurify 的防重叠、距离、平坦度等附加检查尚未完整重演，特别是防重叠依赖实时结构占位，故目前暂停未经验证的**预测结构起点**，避免预测出错位结构。真实已生成结构依旧通过正常世界/区块传输显示。配置快照的 SHA-256 排除每次序列化都会变化的 `config_datetime` 字段。

这是防止错误预测的保守策略，**不是 Structurify 的完整结构预测兼容**。不要描述为已经能够精确预测它调整后的结构位置。服务端须使用本版才能发送标记；单人模式替换一个模组，联机需双方更新。配置改变后重新进入世界，不能声称热重载立即切换策略。

## 验证边界

回归测试涵盖未安装模组时无策略字段、配置指纹稳定及树木库 5.3.5 的两个高度函数调用链。完整整合包、Mixin 实际注入和 GPU 画面仍需游戏内验证。未动原生 Rust 库；旧版加载期间出现的短暂缝隙没有足够证据要求整体回滚。
