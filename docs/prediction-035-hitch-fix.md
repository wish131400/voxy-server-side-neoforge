## 实现

`StrictVoxyNodeIndex.coversBox` 从最大 Voxy 祖先向下验证相交体积。一个已上传节点可以证明其整个覆盖范围；只有未上传的祖先需要继续检查子节点。明确的空几何也算完成上传，缺失节点与未知几何保持预测。矩形窗口判断仍要求最远角位于原有保守圆形窗口内。

矩形查询使用固定容量的区域缓存。区域版本同时包含细节点/列变化与粗祖先变化；哈希碰撞只增加复查，不能保留过时的成功结果。待摄入列有独立的层级计数；网格工作按相交的打包节点查询一次并持有一次锁。旧上传完成不会确认更新一代的任务。原有单列接口与共享单列缓存继续用于细单元和其他调用方。

`PredictionCoverageOwners` 使用固定数组和四路 clock 替换。不可变快照共享的分页直接跳过，变化页仅提取新增、删除或替换的瓦片，对对应所有权区域写入单调版本。查询在快照变化后惰性校验局部版本，同一快照直接复用；普通驻留所有权跨 desired LOD 共用答案，望远镜专属所有权保留按细节级别区分。普通 Map 构造的快照会复制为不可变 Map，避免发布后的原 Map 修改污染旧帧。

预测所有权与 Voxy 抑制分开缓存。预测所有权变化立即处理；可延后的 Voxy 抑制验证通过 FIFO 队列跨帧继续，每个真实渲染帧共用最多 4,096 组和约 2 ms 的预算，每 32 组检查一次时间。时间预算不是硬实时上限，单次节点查询和最后一个批次可能越界，也不包含必须即时完成的所有权更新、GPU 上传和接缝处理。

等待完整 Voxy 证明时显示独立的预测所有权掩码。受影响节点撤回、新摄入/网格工作、窗口边缘变化会丢弃部分证明，立即恢复该掩码；被子预测瓦片占有的父单元仍保持隐藏，缺失子瓦片对应的父回退仍显示。队列存在时继续场景准备，静止相机也能完成验证。窗口更新先于准备帧缓存查询，距离变化能在当前帧使旧掩码失效。

## 验证与性能口径

回归包含矩形与逐区块/逐节参考结果对照、负坐标与打包 Y 周期、明确空几何、节点撤回、重复摄入、旧上传序号、圆形窗口边角、局部缓存失效、望远镜所有权、容量替换、预算与 FIFO、缺失子瓦片回退，以及静止相机下继续验证。

在完整上传祖先、全部拥有的 LOD 7 工况中，64×64 单元、128-block 采样间距对应 512×512 chunks：

| 项目 | 原检查量 | 本轮检查量 |
| --- | ---: | ---: |
| 冷查询 | 262,144 次单列查询 | 4,096 次矩形证明、4,096 次节点查找 |
| 同一工况热查询 | 仍需遍历列并访问共享缓存 | 4,096 次区域缓存命中、0 次节点查找 |
| 100 次无关快照发布后的 409,600 次所有权查询 | 每次发布清空缓存后重建 | 409,571 次命中、29 次保守哈希复查 |

这些数字是确定工况下的工作量回归，不能换算成整机 FPS 倍数。实际查询量仍取决于驻留所有权、窗口、缺失节点和提早失败。预算允许预测临时继续显示，因此 Voxy 接管会分帧完成。

两端完整测试、构建日志、打包审计、测试统计、源码备份和本轮差异保存在各仓库 `build/coverage-hitches-fix-20261005/`。最终测试统计和 JAR SHA-256 以该目录的 `package-audit.json` 与 `test-summary.json` 为准。构建使用游戏实例中的实际 Voxy JAR 进行契约检查；有条件的 GPU/外部组件用例仍由其测试前提决定是否运行。

新 JAR 保持 0.3.5 与原文件名。需要重启客户端加载本轮 JAR 后再复测长帧/P99；本次构建不会替换正在运行的游戏实例模组。
