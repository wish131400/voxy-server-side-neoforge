# 预测 LOD 城市成品缓存恢复修复（2026-10-06）

本次修复城市索引未到齐造成的成品缓存失效、临时网格覆盖完整缓存，以及恢复时重复空间排序。已同步 Forge 1.20.1 与 NeoForge 1.21.1；没有清空用户缓存，没有安装到正在运行的客户端。

## 原因与证据

`LostCityHints.chunk()` 原来把未收到区域和已确认空区域都表示为 EMPTY，`snapshot()` 在没有已知建筑时返回 null。重进存档期间，保存时包含城市摘要的 base signature 因此与恢复时的空/部分摘要不同，成品缓存落入重建路径。部分索引构建出的网格还可能覆盖之前的完整网格。城市索引是会话内数据，重新获取每 200ms 请求一个区域，不能把到达先后视为地形变化。

这是源码路径和确定性测试证实的问题，不代表此前所有 meshMisses 都由它造成。资源变更、设置变更、新区域、捕获编辑等仍会合法失效。

## 修改

- 显式区分未知、已确认空、已确认有城市，并包含一圈接缝 gutter 的完整性。
- 城市信息完整时，成品网格附带原始地形身份与城市摘要（记录格式 10）；旧格式 8/9 继续读取。几何签名 VERSION 保持 10，不全量作废原缓存。
- 恢复首先核对地形、颜色、资源与设置；当前已收到的任何城市区域若与保存内容冲突，拒绝恢复。未知区域允许先显示上次已校验的缓存，并继续请求服务器索引。
- 保存的每种方块状态同时记录名称/属性，恢复检查编号对应关系。编号变化时安全回退，避免把旧编号当成当前材质。
- 恢复后的地表样本和高度使用同一份城市摘要，保持建筑基座、地形和接缝一致。水下通道等 overlay 数据无损保存。
- 收到相同索引不重建；真实变化以及首次回复确认建筑已消失会正常失效。上传后只保留每个相关区域的 32 字节校验摘要，不另留一份完整城市模型。
- 索引不完整时仍可显示临时预测地形，但不写回成品网格，保护完整缓存。旧城市缓存成功校验后自动补写新格式，不必重新采样/重跑植被。
- 已排序网格仍重新计算材质分类和排序键；键已单调时跳过排序及整组四边形复制。材质重映射改变顺序时照常排序。

## 验证范围

执行 `cityWarmCacheTest assemble`，测试选择和完整日志保存在 `C:/Users/Administrator/.codex/tmp/vss-city-warm-cache-20261006/`。打包哈希、测试数量和 native 文件检查见同目录 `package-verification.json`。

验证包含：完整城市网格冷写入→无服务器索引的会话恢复，逐字比较四边形、地表样本和高度；该恢复的采样调用、植被放置调用均为 0。相同索引不会弄脏已完成网格；首次空回复及后续建筑删除都触发更新；缺失索引生成的临时网格不会覆盖旧磁盘数据；旧记录成功恢复后自动迁移，下次无索引也可恢复。

另覆盖负坐标、边缘 gutter、已知区域冲突、状态名称变化、截断记录、共享城市数据和水下结构，以及现有网格写入顺序、接缝、后台缓存工作线程退出和空间排序回归。

## 使用与边界

Forge 构建位于 `lib/city-warm-cache-20261006/vss-0.3.5-forge-1.20.1.jar`；NeoForge 构建位于对应仓库同名子目录。

旧城市缓存首次运行仍可能需要等索引校验或必要的重建，迁移后后续重进才能获得完整收益。不需要删缓存。城市摘要过大超过有界记录容量会放弃该次成品保存；地形缓存仍可用。服务器始终不给完整索引的区域不会被当作已确认空城市写入新的成品缓存。

本轮没有在实际客户端做替换后进档 A/B 测量，因此不提供加载秒数、FPS 或 I/O 降幅。GPU 调色板/分 pass 打包和 CPU 压缩仍保留，未声称全部消除恢复开销。服务器确认前显示的是上次有效缓存，服务器后续真实变更会纠正它。
