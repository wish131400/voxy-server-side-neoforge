# 预测渲染 CPU 与望远镜调度优化（2026-09-21）

适用 NeoForge 1.21.1 和 Forge 1.20.1，版本及产物名保持 0.3.1。

## 问题与依据

上一轮正在运行游戏的 JFR 显示，预测任务基本完成后，渲染主线程仍在接缝处理、边界包围盒计算、驻留网格遍历/排序和覆盖关系查询上花费大量 CPU。此前一个非严格对照窗口里 PREPARE 平均约 9.647 ms，其中包含 SEAMS 约 5.180 ms，不能相加。GPU 使用率不足以单独判定瓶颈，本轮针对已采到的主线程工作进行减量。

望远镜原本强制准星周围半径 1,024 方块进入完整精细地表候选，相关任务绕过普通细化的部分准入限制，瞄准小幅变化还会改变覆盖选择。扩大全部工作线程并不能解决主线程等待 CPU 的问题。

## 最终行为

- 将望远镜额外完整地表/植被范围限制在准星周围最多 256 方块；最多 1,024 方块的地形范围仍享有望远镜优先级。准星中心可达到方块级，测试覆盖 8,192、32,768、65,530 方块目标。玩家附近正常地表配置继续生效，范围外已有细节也不会因本规则被主动删除。
- 半径从 1,024 收到 256，理想圆形候选面积约为原来的 1/16；实际候选还受网格边缘、玩家附近范围、缓存和场景影响，不能据此声称加载耗时减少 93.75%。
- 望远镜待执行和正在执行的生成任务合计最多 `max(1, min(3, workers / 2))` 个；8 个工作线程时为 3 个。昂贵的完整地形与地表任务共享相同并发上限。非望远镜预览及缓存恢复仍有独立准入，因此这不是整个模组所有后台线程的总上限。
- 规划阶段保存按现有优先级、距离排序的候选；工作完成后自动补位。准入失败不会连锁补位，避免拒绝任务反复启动。下一轮规划会更新候选，并在补位时检查最新目标及生命周期。关闭望远镜恢复普通细化并发规则。
- 精细缓存恢复通道继续最多两项、完成自动补位，不要求先重新计算父级或中等地形。
- 小于 8 方块的目标移动，以及小幅半径/投影变化，可复用原焦点；显著移动或关闭望远镜立即更换焦点。没有增加延时保留旧几何的稳定窗口。
- 接缝网格与其包围盒一起缓存，真实区块边界接缝也复用这一数据。脏区域通过分层坐标索引查询，移除“变化超过 64 项就让所有接缝进入重算路径”的分支。邻接、父子重叠、负坐标仍保守失效。
- 所有视距内驻留地形继续参与接缝选择，之后才进行视锥裁剪，只对实际提交的地形/接缝排序。保留不透明近到远、水面远到近的顺序，避免通过提前删除视野外邻居造成转头裂缝。
- 边界替换着色器 uniform 只在值变化时提交，减少重复 OpenGL 调用。

本轮没有新增帧率熔断条件，不修改地形密度算法、Java/Rust 后端接口或缓存格式。前一轮静态火焰与精细缓存恢复改动仍包含在产物中，见 `prediction-static-fire-cache-restore.md`。

## 验证与性能边界

- 实际管理器并发测试：阻塞采样时确认望远镜待处理数受限，解除阻塞后不再调用规划 tick 也能完成八个目标。
- 规划测试：准星中央完整地表、较大范围地形优先级、附近地形保留、远端目标及细长山体射线命中；另验证焦点轻微抖动、明显移动和关闭。
- 接缝测试：80 个远处网格一起更新，原有未受影响的 Patch、遮挡掩码保持同一对象，并与全量重建得到一致的接缝数据；分层脏区域查询覆盖混合精度边界、负坐标及父子重叠。
- 窄视角微基准：4,900 个驻留网格、约 155 个提交项，预热 30 次、采样 30 次并交错新旧执行顺序。NeoForge 裁剪/排序中位数 0.704 → 0.106 ms；Forge 0.540 → 0.107 ms。测试验证排序结果一致、全部驻留项仍供接缝使用。这不包含完整渲染准备、采样或 GPU 绘制，不能换算成整体 FPS 增益。
- 生产着色器 GPU 回归覆盖普通/Iris 路径、深度、透明层、状态恢复、边界和静态火焰。独立 JVM 执行规划测试时发现其此前依赖其他测试初始化 Minecraft，已补上本测试自己的初始化。

运行中的游戏需重启加载新 jar 后，才能完成同位置、同视角、同光影的望远镜前后对比。不能仅凭单元测试保证任意整合包都不掉帧，尤其新目标仍可能需要首次密度采样和装饰放置。设计上优先让中央目标可用，完整装饰集中在小范围，避免一次开镜抢占过多 CPU。

产物：`lib/vss-0.3.1-neoforge-1.21.1.jar`、另一仓库的 `lib/vss-0.3.1-forge-1.20.1.jar`。
