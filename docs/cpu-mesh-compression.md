相同 61 块网格，真实 PredictionPackedMesh/PredictionMeshRestore 路径。含每块现有元数据估算，清空暂存后恢复，不含真实 GL 上传时间：

## 实现约束

- 发布工作线程上压缩，最多两个压缩工作区；满额时保留原数组，不排队阻塞其他生成线程。
- 64 KiB 以下、16 MiB 以上以及节省不足 25% 的网格不压缩。
- 首次上传暂存原数组，全局 32 MiB 上限；上传后释放暂存。容量不足允许淘汰最旧暂存，不丢失压缩数据。
- GPU 网格、面数、绘制范围、接缝摘要和 morph 保留。普通已上传绘制不解压。
- 只有上传需要且暂存缺失时，单个后台线程恢复；排队解压的原始字节总量最多 32 MiB，任务数量也有上限。
- 渲染循环每次最多遇到四个冷恢复请求，避免大范围恢复申请反复淘汰即将上传的数据。
- 只有 ensureMesh 实际完成上传才交接覆盖；旧网格在恢复等待中保留。
- 世界/资源重置清空暂存并推进代号，旧恢复任务无法回填。队列中旧任务正常释放计数，不产生泄漏。
- 网格磁盘编码只获取一次恢复数组；不在逐四边形循环中反复解压。磁盘格式、采样和画面精度不变。
- 内存预算按压缩后的常驻对象计算，暂存及解压队列在 meshRestore 诊断中单独报告。
- 配置 predictionCompressMeshes 默认 true；设为 false 并重进世界可做对照。

按上一轮约 1.45–1.48 GiB 的打包网格数组粗略外推，若大部分满足压缩条件，可能减少约 0.87–1.19 GiB，再扣除最多 32 MiB 常驻暂存及恢复临时空间。此数为语料比例外推；并发跳过压缩、大小阈值及新区域分布会影响收益，不是已测得的游戏进程降幅。不会减少 GPU 几何量或显存占用。

## 验证和复现

- PredictionMeshCompressionTest：精确恢复、压缩阈值、随机输入、损坏输入、暂存与任务字节上限、重置拒绝旧任务、压缩网格磁盘往返。
- PredictionCompressedUploadGpuTest：实际 OpenGL 共享页与独立缓冲路径均逐字读回验证；阻塞解码线程时旧网格仍有效，恢复后才能更换。
- tools/prediction/ExportPredictionMeshes.java：有总量上限的只读网格导出工具。
- tools/prediction/MeshCompressionBenchmark.java：同语料的三种编码器对照。
- tools/prediction/mesh-compression-benchmark.gradle：生产存储/恢复回放，可显式传入 Zstd JAR 测两种分支。
