# VSS 0.3.5 玩家更新说明

适用：Minecraft 1.20.1 / Forge 与 Minecraft 1.21.1 / NeoForge。整理日期：2026-10-06，内容覆盖自 0.3.4 以来已完成的更新。

这次更新主要改善远景交接、闪烁和水面显示，减少进存档、跑图时的重复计算，并加入中文帮助和指定区域预生成。预测远景会先补上尚未收到的地形，真实 Voxy 远景到位后再接管画面。

## 升级前先看这三点

- 客户端和服务端一起更新，使用对应游戏版本、加载器和同一次构建的 VSS JAR。此前同名的 0.3.5 测试包也可能不兼容；Forge 和 NeoForge 的文件不能互换。
- 通常无需删除存档或整个 Voxy 缓存。能够确认兼容的预测缓存继续复用，不兼容的旧记录按需重建；首次升级时，部分区域可能重新加载。
- 下文介绍功能和已核对的模组版本。实际帧率、生成速度和显存收益取决于场景与整合包，没有统一的提升比例。

## 玩家能看到哪些变化

1. **两套远景的交接更自然。** 改善 Voxy 真实远景与 VSS 预测地形重叠、边界不清的问题。真实画面尚未准备好，或精细地形还缺一部分时，继续保留必要的粗地形补位；高空、低处和移动时也检查实际覆盖范围，减少错误消失和地平线空洞。

2. **修复多处闪烁和水面异常。** 修复一批会让远景反复闪烁、读错地块或透明阶段异常的问题，改善高空海面黑带、交界处暗线、前后遮挡错位，以及水面与地形叠加的顺序。渲染结束后正确恢复状态，减少对后续画面的干扰。

3. **减少每帧重复处理的远景。** 已经被前景挡住的预测地形，可以在绘制前跳过。开阔场景下会根据实测成本选择绘制方式；不变的绘制数据直接复用，轻微移动不再触发整份列表重排。水面仍保留透明显示需要的远近顺序。

4. **减少重复水体数据，改善显存使用。** 水面使用独立存储，不再在不透明地形中重复上传一份。显存有压力时，优先释放长期不需要、且已有粗地形补位的细节；近处、接缝和必要的回退覆盖受到保护。回到视野后逐步恢复，减少集中上传造成的冲击。

5. **改善进存档与跑图时的间歇卡顿。** CPU 使用率查询移到后台，避免系统查询持锁卡住渲染主线程。没有计算额度的任务延后再试，减少反复启动后立即退出；缓存恢复使用独立队列。移动时优先补齐缺少远景的方向，普通自动预生成仍会照顾游戏帧率和服务器负载。

6. **地形和植被生成少做重复工作。** 复用气候、生物群系、地表和植被查询结果，优化 Java 与 Rust 的生成路径，并适配 FreeTerraForged / ReTerraForged 的新旧接口。遇到无法安全处理的生成逻辑时，保留适用的 Java 兼容路径；具体模组版本见后面的适配表。

7. **植被更好调，草和树的显示更可靠。** 提供低、中、高三档预测植被数量，约保留 25%、50%、100%，默认中档。水草按整株调整远处显示，避免只剩半截；修复已识别的 BOP 高草变成实体柱、材质表满后树林变灰等问题。望远镜是否额外加载远处细节，也能单独开关。

8. **重进世界更容易复用已有远景。** 缓存按世界或服务器、维度和种子稳定保存，减少切换生成后端或采样设置后重复建立缓存。兼容的成品网格可直接恢复，减少重新采样和构建；合并重复写盘和失效处理，修复旧资源编号、城市状态及 Windows 文件占用相关问题。

9. **安装 Lost Cities 时，城市远景更完整。** 改善楼层、屋顶、道路、公园、喷泉和门前部件的预测，补充城外桥梁、高速路、支柱、桥下底面和水下玻璃铁路。适配多代城市模板、调色板和缓存接口，并修复旧版缓存并发崩溃路径。没有安装 Lost Cities 时，其他更新照常适用。

10. **远景同步、地图和指令更好用。** 改善重复网络分片、弱网等待和发送拥堵，修复超高维度列数据及 Xaero 地图保存问题。补齐中文提示、主题帮助和自动补全；新增速度优先的 `/vss chunky`，已完成的列可以在整个任务结束前逐步交付客户端。

## 用指令生成指定区域

VSS 自带这项功能，无需另外安装 Chunky 模组。它生成真实 Minecraft 区块，并保存能同步给 Voxy 的远景数据。服务端命令需要 OP 2 权限。

| 想做什么 | 指令示例 |
| --- | --- |
| 查看总帮助 | `/vss help` 或 `/vss 帮助` |
| 查看区域预生成帮助 | `/vss help chunky` |
| 以当前所在位置为中心 | `/vss chunky here 512` |
| 指定中心坐标 | `/vss chunky 0 0 1024` |
| 指定矩形两个角 | `/vss chunky rect -256 -256 255 255` |
| 查看进度 | `/vss chunky status` |
| 暂停、继续、取消 | `/vss chunky pause`、`/vss chunky resume`、`/vss chunky cancel` |
| 中文入口示例 | `/vss 预生成 当前位置 512` |
| 查看客户端详细状态 | `/vssclient stats details`，不需要 OP |

坐标和半径单位都是**方块**。中心加半径生成的是**正方形**，不是圆形；例如 `0 0 1024` 是以 `(0, 0)` 为中心、向四周各延伸 1024 方块的区域，边界会取整到完整区块。任务在执行命令的维度运行。

显式 chunky 不按 VSS 的普通生成并发、在途窗口、每 tick 数量、CPU/FPS/TPS 或日常打包、磁盘队列配额主动限速，目标是优先完成生成。实际吞吐由 Minecraft、整合包、硬件和磁盘决定。普通自动预生成继续保留自己的性能保护。

进度每 **60 秒**报告一次，完成时立即报告；也可随时查询状态。玩家移动或离线不会取消任务，暂停停止新增工作，取消保留已经生成和保存的数据。范围仍需在世界边界内：半径 0～8192 方块、矩形最多 4,194,304 列，全服同时一个任务。

已经保存的列会逐批通知同维度、同步距离内的客户端，不必等全部区域结束。完成计数表示服务端数据已可读取，画面还需要经过下载和 Voxy 导入；范围外的数据等玩家进入同步范围后再接收。

完整用法见 [指令与 chunky 说明](vss-commands-and-chunky-20261006.md)。

## 常见问题

**真实远景到了，为什么还会看到一些预测？** 收到数据不代表 Voxy 已经能在当前位置画出完整地形。边缘、缺失区域、不同高度和正在交接的部分仍可能需要预测补位；真实画面可靠接管后才隐藏对应预测。

**更新后要清缓存吗？** 通常不用。记录会自动校验、迁移或重建。改过世界生成配置并希望整片区域重新预测时，退出世界后清理对应的 VSS 预测缓存即可；这与删除存档或全部 Voxy 数据不同。

**预测能完整还原城市、模组地形和玩家建筑吗？** 预测依据世界生成信息，仍是近似结果。部分生成后处理、随机损坏和玩家改动不能保证复现，服务端发送的真实列始终是最终依据。
