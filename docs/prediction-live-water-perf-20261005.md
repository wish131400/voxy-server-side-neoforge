# 2026-10-05 实机水面接缝与预测渲染性能复核

## 本次采样结论

客户端使用上一轮水底 / 拉丝修复的 NeoForge 包，已核对 JAR SHA256 和运行中 shader；本次问题不是未更新客户端。证据保存在 `build/live-water-perf-20261005/`。诊断 agent 按帧读取计数、颜色 / 深度、HiZ 和网格快照，不修改世界数据。CPU 网格解码分析在后台执行。

两方向原地采样各 20 秒，统计排除首 2 秒的异步 GPU 旧结果。位置相同，但俯仰角不同：预测侧 20.19389°，Voxy 侧 8.643892°；因此这是两个实际视角的对照，不是相同几何画面的渲染器 A/B。

GPU 通道时间来自异步时间戳抽样（不透明阶段分别 39 / 64 个有效样本），不是所有帧的逐帧平均，也不能与 CPU 时间直接相加。JFR 显示的 Java 方法计数是样本数，不是耗时百分比。预测窗口 GC 暂停总量约 10 ms / 22 秒，不足以解释持续的帧率差异。

`analysis.json` 包含两方向计数与 JFR 统计；`prediction-window`、`voxy-window` 保存原始样本。

## 接缝为什么露出天空

完整画面：`seam-full/minecraft-after_level-after.png`。本次抓的是白天亮带，没有抓到太阳本身。

1. 亮带在 Voxy 完成、预测不透明地形尚未开始时已经存在。
2. 对应像素的主深度并不为空，约为 0.99985–0.99989；上一轮仅在主深度 clear 时保留预测海底的修复，不能覆盖此情形。
3. Voxy 合成用的 `colourSSAOTex` 中，这些水层存在小于 1 的 alpha。256×256 取样内有 4,988 个 alpha 约 0.706 的像素，以及 35,806 个约 0.914 的像素。后者与叠加多层水相符，不能把它们当作不透明海底。
4. Voxy Normal 管线先画不透明地形，再画半透明水，最后把颜色和水深度一起写回 Minecraft。水下尚无完整不透明背景时，水与天空合成；随后预测海底又被已经存在的水深度挡住。

`colourTex` 的 alpha 是编码数据，不能把它当透明度。本次判断使用最终 `colourSSAOTex`、分阶段画面和实际安装的 Voxy shader / 管线源码。

新 Normal 顺序：**Voxy 不透明颜色与深度 → 预测不透明地形 → Voxy 水层合成 → 原版透明物体 → 预测水**。

通过 `NormalRenderPipeline.postOpaquePreTranslucent` 的 RETURN 注入，先调用该管线自身的 `finish` 合成不透明内容，再执行一次预测不透明通道。原 AFTER_CUTOUT_BLOCKS 回调识别当前帧已经绘制，不再重复提交预测地形。原 Voxy 水绘制和最终合成随后继续执行。

最终合成增加预测反向深度测试，保护原版远平面之外的近处预测前景。另保留一份绘制前的深度，只有预测确实写入的新像素才能阻止这次合成，避免把量化后的原版深度误认成预测前景。

额外成本：一次不透明合成和一份 32 位深度快照；在 3840×2066 下快照约 30.3 MiB。该成本需要实机测量，不能归入已证实的性能收益。未知 shader 合约或不兼容 API 回退普通渲染路径；Iris 仍使用原有单独回调。

## 为什么 HiZ 没有效果，以及此次性能改动

当前帧 HiZ 有大量有效深度，并非全空。但旧命令使用整个 tile 的包围盒，真实采样中最大范围约 8196×354×8196 方块。对捕获的 2,614 条命令使用最终 HiZ 重投影：2,539 条因包围矩形采到天空而保留，60 条与深度重叠，14 条穿过裁剪平面，1 条包含相机，无可剔除命令。

提高 HiZ 采样精度本身只能挽回有限数量，因此本次改为：

- 不透明间接命令按最多 256 个连续四边形分段，使用各段实际顶点包围盒；网格发布 / 读取时构建，帧循环不解压网格。
- 每条 GPU 命令使用独立包围盒，tile 的 shader 元数据仍然共享；保留 morph 高度扩展和 2 方块余量。
- 父 tile 可见时，整段仍可以在屏幕外被剔除；遮挡检测读取全部覆盖的 HiZ texel，天空、空洞、近裁剪交叉和相机所在范围仍保守保留。
- 固定源 cell 的四个顶点在整面已被其他预测细节替代时提前返回，避免继续读取 morph、材质和执行顶点扩展。跨 cell 的合并面仍逐片元检查归属。
- 水的提交顺序不分段重排。

只读真实网格快照离线评估：约 323,409 个四边形可通过深度检测判为隐藏，225,526 个位于屏幕外。该评估使用**旧管线最终 HiZ**，包含旧水深度，并且没有加入正在 morph 的扩展；它不是新顺序下的实际执行统计，更不是 FPS 提升测量。当前帧早期桶也尚未拥有最终桶的全部深度。

这项优化改善了剔除粒度，但不能据此声称约一倍的帧率差距已经消除。新命令数量和新增水合成成本也需要重新采样。

## 同步与验证

改动同步到 NeoForge 1.21.1 和 Forge 1.20.1 仓库。保留了 Forge 原有事件 API、Java 17 兼容写法以及移动上传节流逻辑。未创建提交或回滚用户原有未提交改动。

验证包含：

- 两端完整 build / 默认回归。
- 两端 7 个 GPU 测试类：遮挡命令、生产批绘制、目标深度、Voxy 深度约定、播种、外部 GL 状态和边界。
- 已安装 Voxy 最终合成 shader：两种声明投影 × 两种实际 clip 模式 × 540 / 1080 / 4096 距离，验证水使用海底颜色、近处预测前景受保护、未改变的播种深度不会冒充预测前景。
- 生产批绘制的颜色与深度逐像素一致性；天空单像素孔洞保留，屏幕外小段剔除，转向后当帧恢复。
- 独立 CPU 测试覆盖 fine / coarse / fluid 坐标、负高度、分段边界与空网格。

Forge GPU 验证使用同一份 NeoForge 客户端 Voxy shader fixture，**不等于 Forge 实机整合包兼容验收**。最终构建日志、包哈希和测试摘要见证据目录 `verification.json`。

本轮新包尚未完成游戏内加载与相同视角 A/B。需要换包重启后确认新回调执行、接缝最终外观、实际隐藏命令数和不透明 GPU 时间；不能把离线回归替代这一步。
