本轮是采样和方案评估，没有修改生产代码、部署 JAR 或永久修改游戏设置。当前 Forge 1.20.1 客户端 PID 69400，Java 21；实际安装包 SHA-256 `1a57d85078afb5799c9373d4f5b9f8d4cde5f988939f0c7316ce047a279988e2`。GPU 为 RTX 4070 Ti SUPER，驱动 572.70，渲染目标 3840×2066。

原始证据：`C:/Users/Administrator/.codex/tmp/vss-gpu-profile-20261006/`。诊断使用已有异步 OpenGL timestamp query，临时启用 `vss.renderTimings`，不使用 glFinish。所有临时属性已恢复，JFR 已结束。

## 窗口与方法

第一段 `window1/` 发生约 54 格移动，并有 362 次构建、96 次网格上传，因此只作探索，不作为固定视角收益结论。`current.jfr` 与该移动窗口附近重叠；CPU 栈不可直接当作后续静止窗口的 CPU 占比。

用户再次确认固定视角后，`contrast/` 自动执行正常剔除、关闭剔除、恢复正常三个各约 25 秒窗口。每段舍弃头 3 秒，使用累计 GPU 纳秒和样本数的首尾差分，避免混入上一阶段异步查询结果。三段有效窗口约 22.2 秒。逐秒快照的 x/z、yaw/pitch 均一致：x=-6187.90203087701、z=-4111.569970747766、yaw=535.3725、pitch=9.807835；paused 全为 false。仍有少量后台更新，但候选几何量保持 6,943,044，恢复段的剔除量仅变化 18 个四边形。

GPU 数据是每 30 帧抽样的区间均值，不是所有帧的 GPU p99；FPS 取实际渲染帧计数/墙钟时间。时间戳区间可能包含依赖等待和 GPU 空闲，不是硬件 shader cycle 分解。

**固定视角中，当前完整遮挡路径负收益约 1.1 ms GPU 区间，关闭后实测约 +7.8 FPS（10%）。** 恢复后回到原值，使这一结论比单次开关可靠。关闭开关同时取消 compute 筛选和依赖 culling 的细分 meshlet 命令，不能把差异全部算作 Hi-Z compute 本身。也不能据此全局永久关闭遮挡：地面建筑后方的遮挡收益可能不同。

每帧约 52 次筛选/多重间接绘制，细粒度 `GPU_FILTER` 和 `INDIRECT_SUBMIT` 各仅有 16 个 query 槽，发生大量 dropped。它们只记录前部分批次，不能用单批均值乘总批次数推算整帧成本，也不能将嵌套区间与 OPAQUE 相加。OPAQUE/WATER/DEPTH_COPY/AA 的有效计数完整匹配各自抽样窗口，因此使用这些顶层通道作结论。后续需要每通道聚合或轮换抽样细批次。

## 剔除后仍有大量几何

正常 A 的 GPU 统计：29,799 个候选命令、4,735 个隐藏命令；6,943,044 个候选四边形、1,100,758 个隐藏四边形。隐藏量约 15.85%，仍留下约 **5,842,286 个四边形**供绘制。

该候选数是在 CPU 可见面组/提交范围筛选之后、GPU Hi-Z 筛选之前；留下的面还会接受深度测试和 shader 归属拒绝，因此不能当作最终可见面数量。关闭 B 后这些统计会保留旧值，不能解读为关闭时仍执行了剔除。

在 A/B/A′结束后，一次性读取不透明 PreparedPass 的 989 项已选范围。主线程仅复制范围和引用，后台低优先级逐网格解压统计，避免污染对照；原始结果在 `geometry/geometry.txt`，运行时 shader 常量也保存在此目录。统计总量恰好为 6,943,044。

## 优化方向与优先级

1. **先消除负收益剔除路径。** 合并每页/每桶的 compute 工作与 barrier，减少 filter/draw 交替；把 256-quad 的全场平铺测试升级成粗层先拒绝、细层只处理候选的层级结构。以实际剔除收益和稳定迟滞选择保守直绘或细分剔除，不能同步读回 GPU 等待结果。当前实测给出约 8 FPS 的收益参照，但不是跨场景保证。
2. **远处植被与建筑显示 LOD 是更大的潜在空间。** 按屏幕投影误差与距离合并树冠/叶簇、保留轮廓的植被代理、稀疏草簇；建筑优先保留屋顶/外墙轮廓，减少远处内部和小构件。现有水生植物抽稀不能替代陆地植被 LOD。保持近景、望远镜、过渡滞回和归属边界，避免简单随机删面引起闪烁。当前树叶/草数量支持优先研究此项，收益需实现后测量。
3. **收紧 meshlet 的空间和朝向范围。** 当前 256 个连续面、Morton 主要按 X/Z 排序。高树、建筑、多高度实体可形成较高包围盒，影响隐藏率。尝试 XYZ 聚类、不同类别/距离的粒度和单面法线锥；双面叶片不能用实体墙的背面规则。不要一律改成 64 面，因为当前已接近 3 万命令，更细可能加重开销。
4. **shader 分路径属于后续实验。** 已读取运行 shader：普通路径已不写 gl_FragDepth，因此“移除 gl_FragDepth 恢复 early-Z”已经实施，不能作为新优化重复推荐。远处不透明平均色可进一步使用专用简化路径，近处归属/水/cutout 保留原语义。当前没有分辨率 A/B 或硬件 pipeline statistics，不能断言像素 shader、顶点展开或显存读取各占多少；在重写 shader 前应先补实验。

## 硬件与限制

探索硬件窗口 GPU 利用率平均约 64.8%，范围 24–76%，显存约 5.9 GiB / 16 GiB，图形频率 2805 MHz。该窗口有移动，不能当作固定 A/B 的硬件对照；未见显存容量耗尽或低频迹象，但 GPU 利用率低于 100% 不等于 GPU 通道没有优化价值。

当前静止窗口正常状态场景准备只约 0.16–0.27 ms，多数计划可复用，与此前加载/移动时的接缝 CPU 热点不同。前一轮预算锁在这次探索 JFR 的 monitor 事件里未再次成为热点。不能将探索时的 HashMap/场景准备样本百分比套用到固定窗口。

没有测量 Voxy 和原版的完整 GPU 通道，也没有硬件级顶点/片元统计，所以预测 OPAQUE 7.5 ms 只能确定它是大头之一，不能声称其余约 5.3 ms 全来自某一个模组。CPU 与 GPU 通道时间重叠，不能直接相加或相减预测最终 FPS。

本轮可验证的提升约为 10%；要争取更大收益，重点是减少远处实际处理的几何与改造剔除命令结构。不能据此承诺翻倍帧率。所有对照设置已恢复，无需重启。
