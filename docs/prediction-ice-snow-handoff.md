# 冰面交接与预测树冠覆雪（0.3.2 后续修复）

## 现场依据

2026-09-21，Minecraft 1.21.1、Voxy 0.2.15-beta、Glimmer v1.5.2。
视频中关闭预测后留下的长条阴影是树影，不作为缺陷判断依据。

开启预测后的湖面单帧采样（128×128，屏幕坐标 0.65/0.30）显示：

- 预测透明阶段将材质写为 Glimmer 的 `1002`（冰）；水的编号是 `1001`。
- Voxy 透明绘制后仍是 `1002`，但颜色再次变化。
- 3,623/16,384 个像素的深度改变 1～2 个浮点刻度。

这直接证实该采样片区存在同一冰面的透明重复绘制，不能据此宣称 Voxy 把冰方块映射成水。
其他位置是否存在真正的水/冰数据差异，仍需单独采样。

## 修改

旧 Iris 注入在 `setupAndBindTranslucent` 返回时绘制预测；Voxy 随后才提交真实透明几何。
新注入仅在此记录管线和视口，等 MDIC 真实透明提交后、状态清理前再画预测。
这条路径同时覆盖立即透明绘制和延迟透明绘制。

预测透明阶段读取刚完成的透明深度，匹配处只保留一次表面。没有实际覆盖的像素继续补预测。
复用原深度复制纹理和不透明阶段准备的网格列表，不用磁盘缓存命中来代表已绘制。
Iris 透明比较直接使用窗口深度，加两个 24 位深度刻度与垂直于表面的 0.02 方块容差。
这避免高空逆投影相消误差；精度仍受光影的近裁面、深度格式及正反 Z 设置限制。
极端高空前向深度下，数米内的两层表面可能已不足以稳定区分，不能承诺无限精度。

原版 `SnowAndFreezeFeature` 通过 `Biome` 查询 `LightLayer.BLOCK`，旧预测环境只实现了
`getRawBrightness`，最终访问不存在的光照引擎并将该 feature 判为不支持。
现在提供生成阶段的块发光/天空亮度查询，无需建立或传播真实区块光照。

地表缓存版本 5 标记覆雪检查完成，旧版本 3/4 继续可读。
旧缓存保留树木、建筑和地表修改，只补跑已配置的原版 `FREEZE_TOP_LAYER`，升级后直接读取。
不清空地形缓存，不重新生成树木，不重放其他自定义装饰。

## 性能与验证范围

- 光影交接每帧增加一次 GPU 内部深度复制，复用既有纹理，不新增全屏常驻纹理。
  3840×2066、4 字节深度约 30.3 MiB/次；这是复制数据量，不是新增堆内存。
  未在重启后的新包上测量实际 GPU 帧时增量。
- 新生成区块执行原本应有的原版覆雪步骤；旧地表缓存一次性补检查，最多基础 16×16 列。
  覆雪后真实增加的雪层几何也有相应网格成本，不能称为零开销。
- CPU 测试覆盖原版冷生物群系树冠覆雪、天空/块光区分、旧 canonical 缓存修补与二次读取。
- 安装包字节码契约测试检查透明注入确实命中 Voxy 的实际 draw call。
- GPU 测试覆盖水、熔岩、冰、同面深度误差、近处 1/8 方块浅层、远处独立河床、
  普通/望远镜视角以及正反 Z、两种 clip 范围。

代码测试不能代替同一存档、同一光影下换包后的画面复验。
