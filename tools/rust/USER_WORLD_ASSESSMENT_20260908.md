## 旧库输出的关键限制

使用工作区内附带的 ABI 10 DLL，直接读保存的 seed 和 native-input.json 创建新句柄，先正序、再新句柄倒序调用 4 种间距。32 次完整 grid 重放全部与采集二进制一致，说明数据可以稳定重放。

但是 4 个采样原点中有 3 个原点在改变间距时输出不同。例如 `(36, 12)` 的 grid 首记录高度，在间距 1/16/256/4096 下分别为 93/108/63/76；单列查询为 93。重新创建句柄和反转调用顺序未消除差异。按缩放原点、格中心、向下对齐原点解释也不能统一匹配全部记录，因此不能在未确认旧库内部语义前把差异简单归因于 Java 参数顺序或坐标平移。

| 间距（格） | 64 条 grid 记录与对应单列的完整 32 字节一致数 | 与原版 OCEAN_FLOOR_WG 基础高度平均绝对差 | 最大绝对差 |
| --- | --- | --- | --- |
| 1 | 64/64 | 0 | 0 |
| 16 | 21/64 | 6.046875 | 56 |
| 256 | 21/64 | 4.109375 | 30 |
| 4096 | 15/64 | 13.109375 | 52 |

全部柱的平均绝对高度差为 5.81640625，最大 56。间距 1 的样本表现正确；粗间距是独立的旧库行为基线，不能将其高度/材质/biome 当作同坐标精确原版输出。此项尚未证明旧库内部是主动近似还是缺陷。本轮没有据此更改游戏地形算法或清除预测缓存。

这也要求新协议明确区分“精确位置的地形柱”和“粗 LOD 聚合/近似结果”。后者若需要聚合，应记录取样或聚合规则，不能隐含在 spacing 中。新库的精确批量查询要与同坐标单列一致；粗 LOD 的质量与接缝另外验收。

## 迁移顺序与缺失样本

1. 先做新 ABI 的句柄、缓冲区、返回单位和取消/释放契约；用这套可重放数据接通旧新后端对照。旧 `sampleColumn` 返回字节数，`sampleGrid` 返回记录数。
2. 迁移随机和噪声，然后密度图、插值、基础柱/含水层；优先用原版噪声/密度/完整基础柱做数值标准，旧库粗 LOD 仅用于行为比较。
3. 迁移地表规则和 biome/颜色查询。实际跑动 JFR 显示 Java `resolveColumn → ClientSurfaceResolver`、`noiseBiome` 是生成线程热点，这比仅迁移简单网格数学更值得优先处理。
4. 再迁移原版 feature 调度、放置修饰器和树干/叶/草/花/竹子。当前植被在 VSS 虚拟地面执行，必须补真实完整 chunk 的地形和装饰阶段、邻区读写、跨界树冠与最终方块集合。
5. 为未知 modded feature 保留 Java 兼容入口，逐项宣告 Rust 能力；Java 继续负责注册表/资源包与渲染对象，避免逐方块 JNI。

验收集合至少再补：多种子、负坐标与大坐标、下界/末地、多噪声交界、含水层/熔岩、恶地/冰雪/沼泽，樱花/桦树/红树林/大型树、花/竹子，结构与植被邻区影响、完整真实 chunk，资源包和 biome 混色，以及不同世界生成快照。已有固定 biome 离线夹具可继续复用，但必须与实际世界样本分别标注。
