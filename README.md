# Voxy Server Side NeoForge

Voxy Server Side（VSS）让服务端负责读取、生成、缓存并发送 Voxy 远景 LOD。客户端只请求缺失或过期的列数据，再交给 Voxy 渲染，适合多人服务器、大型整合包和高速移动场景。

## 支持版本

| 项目 | 版本 |
| --- | --- |
| Minecraft | `1.21.1` |
| Loader | NeoForge `21.1.x` |
| VSS | `0.3-neoforge-1.21.1` |

- Forge 1.20.1 版本：[voxy-server-side-forge](https://github.com/wish131400/voxy-server-side-forge)
- 下载：[CurseForge](https://www.curseforge.com/minecraft/mc-mods/voxy-server-side-forge-neoforge)

VSS 主版本号统一固定为 `0.3`，保留加载器与 Minecraft 版本标识，完整版本号为 `0.3-neoforge-1.21.1`，输出文件为 `vss-0.3-neoforge-1.21.1.jar`。后续构建也沿用此版本号；不同构建可通过构建时间与 JAR 的 SHA-256 区分。配置结构和网络协议使用独立的内部版本标记。

客户端和服务端必须安装协议一致的 VSS；更新时请使用同一次构建的 JAR，不要仅凭固定版本号判断两端兼容。

## 安装

服务端需要：

- NeoForge `21.1.x`
- VSS
- 可选但推荐(带宽压缩模组)：[ZstdNet](https://www.curseforge.com/minecraft/mc-mods/zstdnet)

客户端需要：

- NeoForge `21.1.x`
- VSS
- Voxy，或仅安装 Xaero's World Map 作为远景地图消费者
- Sodium 兼容渲染环境
- 可选但推荐(带宽压缩模组)：[ZstdNet](https://www.curseforge.com/minecraft/mc-mods/zstdnet)


## 工作方式

1. 客户端完成握手，取得服务端距离、速率、生成和带宽限制。
2. 客户端以玩家位置为中心扫描 Voxy LOD，并上报本地已有列，避免重复下载。
3. 服务端依次尝试内存缓存、持久化缓存、已加载区块、区块 NBT；允许时再提交区块生成。
4. 完整列进入该玩家的发送队列；服务端按距离和优先级选择数据，再通过全服共享带宽池公平轮询发送。
5. 客户端组装、解压并解码列数据，再交给 Voxy 或注册的 VSS API 消费者。

方块发生变化时，服务端会广播脏列版本，客户端只刷新受影响的 LOD。

## VSS 远处预测

VSS 在握手后发送压缩的 `worldgen_profile`，包含世界种子、维度生成配置、噪声/生物群系/feature 注册表，以及地表结构使用的拼装池、处理器和建筑模板。快照按世界生成生命周期缓存；客户端和服务端应一起更新到当前 `0.3-neoforge-1.21.1` 构建以使用建筑模板同步。客户端以 66×66 采样网格（64×64 地形单元）建立独立预测网格，默认预测半径为 8192 方块，配置范围为 1024–65536 方块。

普通地形按预测总半径的水平距离分三档：内侧 0–60% 使用完整的 64×64 地形网格，60–90% 使用 32×32 中等密度网格，90–100% 使用 8×8 轻量大块粗模。三档保留实际采样的地形材质与颜色，每个单元覆盖多少方块仍由 LOD 层级决定；近处和望远镜目标可以达到单格精度。分区按瓦片中心归属，边界增加中间层级过渡，不是硬裁切圆环。各区域先出现轻量覆盖，再按 8→16→32→64 逐步达到本档目标；近处优先执行，分区骨架规划不要求远景先全部生成。望远镜目标覆盖普通三档限制，已经加载的更精细网格继续优先显示，不因走远或收镜立即降级。植被仍沿用下述默认 768 方块扩展范围，不随 60% 精细地形范围扩大。径向分区骨架最多 640 个叶节点，其额外细分单独计数，不占用原有普通/望远镜细化名额；最后最多再增加 512 个相邻过渡叶节点。实际构建并发和驻留数据仍受内存预算约束。

加载按区域逐级推进：该区域的基础地形 → 更精细地形 → 地表内容。每个子网格只等待自身父网格就绪，不等待整个远景范围的基础根网格完成；远处任务失败或重试不会卡住其他区域。按 128 方块距离带分配工作：已完成精细地形的近处网格优先升级植被和建筑，不等待附近整圈地形全部完成，队列入队和执行使用相同优先级及到网格边界的距离。512 个待处理名额用满时，近处高优先级任务可替换尚未开始的远处任务；已运行任务、真实列采集和脏列优先级保持受保护。默认地形屏幕误差目标从每格 6 像素改为 2 像素，远处也逐步获得更细的高度和实际方块材质。普通视角每次规划最多选择 1024 个叶节点，望远镜模式最多 2048 个，给扩大后的细化区域保留名额；实际构建速度按 JVM 可用堆空间调整，不会把整个地平线一次生成成一格精度。

地表内容默认在已知近处地形外再细化 768 方块：根据原版视距和实际已收到的真实列估计覆盖边界，再向外延伸，避免整个植被范围都藏在 Voxy 里面。已有完整真实列的网格不再为预测植被强制细分；普通视角的朝向不影响这个范围。望远镜可以细化到整个预测距离内的目标，不再因目标太远停在较粗层级。目标周围半径 1024 方块（64 区块）的区域规划到 spacing=1，超出总预测距离的部分不加载；优先级排在最近 256 方块之后、普通远景任务之前。转动或放下望远镜也会重新排序尚未开始的任务。远处只在该目标区域内生成精细地表内容；生成结果保留缓存，放下望远镜不会立即销毁。预测范围内的已加载细节不会仅因闲置 30 秒而回收；离开预测范围或出现内存压力时可释放，由本地缓存恢复。后台线程总量为逻辑线程数减 2（至少 1），同时遵守实际堆余量的构建并发限制；有粗模待处理时只保留 1 个工作线程供粗模推进，其余线程可参与精细地形和地表生成。地表升级复用已生成的地形样本。真正的堆空间不足且没有工作线程运行时，会先回收闲置细节；需要为近处地形或植被升级腾空间时，可把更远的低优先级细网格交回已有父网格覆盖。debug 模式下每 5 秒的渲染统计包含植被候选、地形就绪、生成及入网格方块数，正常模式不输出这些诊断。

最终 GPU 数据打包和面分组排序在后台完成，渲染线程只上传已准备的数据。每帧最多接纳 2 个网格，并采用 4 MiB、2 ms 的上传软预算；单个较大网格允许独占一帧的上传额度，避免永久饥饿，因此并非严格的 2 ms 帧时间保证。覆盖判断只使用已上传的网格，旧粗模或同位置的旧地表会保留到新网格上传完成；CPU 回收细节时，也等待可用父网格的 GPU 覆盖。Iris 的不透明和透明阶段共享同一份上传后的网格快照。

植被及建筑的方块状态结果已写入本地压缩缓存，命中时跳过原版 feature/structure 生成；空结果也缓存，脏列仍使相关缓存失效。相邻缓存文件复用有界的方块状态编解码表，避免每个区块重复运行 JSON/BlockState codec。缓存不包含与当前材质图集绑定的 GPU 网格，因此重访仍需要后台构网和上传。debug 统计增加 `surfaceMemoryHits`、`surfaceDiskHits`、`stageTotalMs` 和每帧上传数量/字节/耗时；阶段耗时是后台任务的累计经过时间，不能直接视为单帧 CPU 占用。

预测内存由 JVM 当前余量驱动：取消原先根据 CPU 线程数计算的固定 MiB 配额、堆大小四分之一的上限，以及 2048 个驻留网格的数量上限。可用堆空间包括 JVM 尚未提交但可在启动器最大内存范围内扩展的部分；留出最大堆的 10%（最低 128 MiB、最高 1 GiB）作为游戏与 GC 的周转空间，并预留每个已接纳任务的 128 MiB 工作空间。余量充足时最多使用逻辑线程数减 2 个工作线程，余量减少时降低同时运行的构建数量，余量恢复后自动继续。缓存仍保留在堆中，因此模组必须释放不再需要的引用；释放后等待 JVM 自行 GC，不调用强制 GC，也不会把尚未回收的内存当成已经空闲。debug 统计显示 `memory={mode=adaptive,...}`、堆上限、实际空闲量、工作空间预留和可接纳线程数。游戏能用的总内存仍由启动器的最大内存设置决定。

预测层与 Voxy 的数据写入严格分开：预测高度只存在于 VSS 的 tile/mesh 缓存中，不会伪装成方块列写入 Voxy；真实列到达或收到脏列通知后，对应 cell 会立即失效并恢复 exact 请求。近处范围、脏列和失败重试永远不会被预测层延迟。

地形采样优先使用本项目源码构建的 `vss_native_core`（世界生成 JNI ABI 2）。噪声、密度、高度、液体柱、原版地表规则、生物群系颜色与支持的植被计算在 Rust 中执行；Java 提供注册表、资源包、结构与自定义 feature 兼容上下文。当前随包原生目标为 Windows x86_64、Linux x86_64/ARM64、macOS Intel/Apple Silicon；Linux 要求 glibc 2.28+，macOS 要求 11.0+。未知系统或不支持的生成配置使用 Java 回退。兼容检查只检查地形依赖，自定义矿石/装饰 codec 不会连带关闭兼容的 Rust 地形。原生调用使用有界批次、缓存和句柄租约，取消与关闭不会提前释放在途调用的数据。

Java 地形路径通过 `NoiseBasedChunkGenerator`、`RandomState` 和 `NoiseRouter` 重建生成上下文，以两阶段高度估计、8 格扫描和边界二分求地表。近远地形及植被列查询统一使用地表专用采样，不再为不显示的地下分层扫描密度或计算旧树木/结构提示；未采样地下占据关系的列保留原高度，不参与要求完整分层信息的异常高度平滑。原版地表规则与草、叶、水色、植被查询共享有界的线程局部生物群系缓存，完整匹配 quart X/Y/Z，不降低采样坐标精度。预测 mesh 保留 biome tint、雪/冰标记及海水/熔岩面。方块顶面和连接侧面保持采样高度，移除会把相邻面拉开成透明细缝的独立高度 morph；四叉树通过覆盖掩码交接，在子 tile 完整就绪前保留父 tile 覆盖。GPU 不再保存高度差缓冲，父 tile 更新也不再触发子网格重复上传。绘制列表与覆盖判断共享不可变的网格/覆盖版本快照，避免后台子网格或同位置地表升级在本帧中途发布时提前隐藏旧网格；Iris 的 opaque/translucent 阶段共享同一帧快照。新网格引用的贴图表条目在绘制前上传，取消旧的半秒更新延迟。跨度达到 65536 方块及以上的网格使用带缩放的水平坐标编码，保留准确外边缘，避免 16 位坐标截短造成相邻网格间的缝隙。

启用 `debugLogging` 后，世界快照安装时会记录 `rust=<维度数>`、`javaOrCustom=<维度数>`；Java 回退原因会指出触发判断的字段及 codec，批量调用失败诊断每个采样器最多输出一次。旧的 `exact` 数量只表示可重建生成上下文，不能用它判断 Rust 是否启用。当前 Rust 负责密度图、地表高度、材质索引和批量柱采样；原版 surface rule、PlacedFeature/Structure 方块放置、贴图表、网格裁剪与 OpenGL 上传仍在 Java，因为这些步骤需要 Minecraft 客户端对象和资源包状态，不能安全地移到现有 JNI 接口。

Rust 核心源码位于 `tools/rust/vss-native-core`，通过 `tools/rust/build-vss-native.ps1 -Package` 构建 Windows 本机库，或通过 `tools/rust/build-cross-platform.ps1 -Package` 交叉构建并同步五个目标。生产接口和原版对照测试已接通；独立 ABI 1 噪声探针仅用于验证。模块说明、构建方法与验收边界见 `tools/rust/README.md`。

## 图形与系统兼容性

普通预测渲染使用 OpenGL 3.2 的纹理缓冲、3D 遮罩和顶点数组；Iris/Voxy 路径沿用 Voxy 的 OpenGL 4.6、计算着色器和间接绘制要求。运行时会检查 API 和纹理单元，不满足时只停用预测层并保留 Voxy/原版渲染。Voxy 的系统检查还要求计算着色器和间接参数扩展，部分 AMD 驱动的深度采样缺陷会被它停用。Windows/NVIDIA RTX 4070 Ti SUPER 已通过本项目的普通和 Iris GPU 回归；Linux、AMD、Intel 只完成接口与离线着色器检查，未宣称硬件实测结果。macOS 可加载 Rust 采样库，但 Voxy 的 OpenGL 4.6 路径通常不可用，因此不能把 macOS 视为完整的 Voxy 兼容平台。

植被通过受限的虚拟 `WorldGenLevel` 调用原版 `PlacedFeature.placeWithBiomeCheck`，保留世界种子、区块坐标、全局 feature 顺序、生物群系与地面条件。运行时只给 spacing 1/2 的近处或望远镜目标网格生成树木、草、花、农作物等地表块；密集区域仍会按网格预算简化。竹子读取游戏烘焙的 multipart 模型，保留年龄、叶片状态、细竹竿、随机位移、各面 UV 和实际方块着色规则；叶片不再额外乘通用树叶颜色。密集竹林按模型面数计入预算，必要时稀疏保留整根竹竿，不放大成粗柱。原生采样器中的树木提示不会自行变成树冠盒子。失败的 feature 会撤销本次写入；不会用随机模板补树。

地表结构使用同步的 `StructureSet`、原版候选/频率/排斥条件、加权选择和 `Structure.generate`，再按真实结构片段及 NBT 模板放置方块。主世界仍排除地下结构，下界另外允许 `UNDERGROUND_DECORATION` 阶段的要塞及化石；混合要塞/堡垒结构集合不因阶段不同而整组丢弃。结构按自身阶段及该阶段内的注册索引设置随机种子。原版楼梯、半砖、栅栏使用方块状态形状和对应贴图，细小水平坐标以 1/16 格精度打包。末地城模板跳过需要真实世界的潜影贝和鞘翅展示框实体标记，保留建筑与箱子。模板缺失或虚拟世界不支持的结构会跳过，不生成范围框。模板同步总量上限 5 MiB、单模板上限 512 KiB；超出上限的模板不发送。

地表生成按原版阶段补充裸地生成、湖泊、局部修饰、地表 feature、沙盘及顶层修饰；支持的 feature 继续调用 Rust，其余通过有界原版兼容路径运行，普通地下矿脉不加入地表任务。岩浆湖复用原版几何算法，省略真实区块的后处理标记；采样液体不再依赖维度是否设置海平面。末地柱体、铁栏笼和基岩底座有独立方块适配，末影水晶实体及光束尚未实现。下界仍有单层高度场取到顶层基岩、不能表达下方洞室的限制，放行结构阶段不代表完整下界支持。地表缓存 schema 为 3，旧的植被专用或空结果会重新生成，地形缓存可继续复用。粗树冠按原始方块数量选择代表材质，树叶不同 distance 状态合并计数，树干不再无条件覆盖整格树叶。

预测水面保留当前资源包 water_still 的实际 alpha（原版为 180/255），熔岩不再受到水面透明度上限限制。真实河床在水面后方时不再因地形交界偏好而删掉预测水面；水下地形和植物按上方水深估计天空光衰减，并传给原版 lightmap 或 Iris 光影片段接口。此光照估计不等同于完整世界的光照传播。

预测只保留地表及外露侧面，不补地下洞穴或建筑下表面。真实区块仍提取 16×16 地表样本，包含真实空列、液体与材质；收到真实列后优先刷新精细预测网格，捕获到的空气不会重新长出预测植被。

渲染使用独立的 32 位反向深度附件，按像素比较 Minecraft/Voxy 主深度：前方预测地形可以挡住后方 Voxy 剖面，前方或同深度的真实地形优先；深度回写使用固定 0.02 格偏置；颜色覆盖另对相邻地表采用由采样间距决定、上限 16 格的真实表面优先范围，避免粗预测面压住真实地形，同时不把远处剖面当作前景。顶面、侧面和植被通过 packed quad 缓冲采样客户端实际方块贴图，并使用对应面的颜色和 biome tint。诊断详情受 `debugLogging` 控制。

预测仍不是完整服务端世界生成：虚拟区域不执行完整雕刻、结构地形融合（beardifier）、全部装饰阶段及相邻区块的装饰历史，依赖这些状态的模组 feature 可能被跳过或与最终地形不同。需要完全准确的建筑、洞穴、树木和玩家改动时，以 Voxy 收到的真实区块为准。预测 mesh 不会写入 Voxy 的真实列缓存。

普通设置变化（包括“允许生成 LOD”）不再重新编码世界生成快照，重复快照也不会清空客户端预测网格。数据包同步/世界重载才使快照失效。真实列到达后保留按距离选择的精细预测表面，避免退回粗父网格。关闭服务端生成会取消尚在排队/等待票据的 VSS 生成请求，并阻止迟到的存储回调重新提交；原版已调度的区块任务仍由原版收尾。关闭客户端预测会停止排队与旧版本提交；原生采样分成至多 8×8 批次以检查取消。样本缓存采用缓冲 I/O，加载、写盘和等待采样器释放放到后台；GPU 网格每帧分批回收。线程预算为逻辑线程数减 2（至少 1）。

Iris 适配以本项目使用的 NeoForge Voxy 0.2.11 分支为接口基准：复用当前 Voxy 光影补丁的 `voxy_emitFragment`、材质 ID、TAA uniforms、opaque/translucent 目标与混合设置，预测深度在相同光影目标内参与合成；保留 `excludeLodsFromVanillaDepth` 的原意。透明预测接入 Voxy 的透明阶段，支持它延迟执行该阶段的路径。没有可用 Voxy 光影接口时，不把原版颜色写进光影缓冲；接口错误只停用该光影管线中的预测。已做 GLSL 接口及 GPU 像素/状态检查，尚未进行 Complementary、Photon、BSL、Solas 各整包的实际存档验证，不能据此声明全部效果相同。依赖 Voxy 私有 modelId/模型缓冲的自定义光影仍需额外适配。

地形适配按当前维度实际引用的生成依赖选择。Tectonic 的运行配置先转换为有效密度图，并同步其 `NoisesMixin` 对噪声随机种子名称的改写规则，已实现的 Lithostitched 算子与 FastNoise 配置由 Rust 计算；不再仅因安装模组强制选择 Java。未知 codec 仍要求相应客户端运行时并使用兼容路径，装饰 codec 与地形 codec 分别处理。TerraBlender 的 positional region/地表规则上下文尚不能完整序列化，相关多噪声维度暂停种子预测；TFC 等无专用后端的生成器、缺失 codec、无快照的维度同样停用预测，不再补一片自造地形。BOP/BWG 等相关组合继续使用 Voxy 真实方块 LOD。BetterEnd New Dawn 保留现有 PAULEVS 地表适配，其植被与结构不作完整一致性承诺。建议客户端、服务端一起升级到本版本以使用新增的生成能力标记。

预测本地缓存默认启用（`rememberTerrain=true`），单人世界位于 `<存档目录>/.vss/prediction/surface-v1/`，联机世界位于 `<游戏目录>/.vss/servers/<服务器身份哈希>/prediction/surface-v1/`。联机优先采用 VSS 下发的稳定服务器身份（独立节点另行区分），没有时按服务器地址隔离；单人缓存随存档一起移动，不再绑定存档绝对路径。维度、种子、生成器数据、注册表指纹、采样后端及缓存格式进一步决定子目录；树木和结构开关另行区分。地形按 LOD 网格保存 66×66 列，树草和地表建筑按生成源区块保存，使用方块名称/状态调色板和 zlib 压缩，不保存贴图或 GPU 网格。启动不扫描或加载整个预测磁盘缓存，工作线程按需要读取；缺失或损坏的条目重新计算，写入通过临时文件和原子替换提交。队列仅保留临时文件路径，不堆积完整地形或建筑对象。

缓存命中会跳过该网格的 Java/Rust 地形采样或该区块的原版地表放置；显示网格仍按当前资源包、颜色与遮挡重新建立。首次生成后即保存，不必等待退出游戏。地图探索范围增大时磁盘文件会随之增多，森林和建筑的体积高于仅地形；不承诺固定压缩比例或零重建开销。旧 `<游戏目录>/vss/prediction/surface-v1/` 中与当前世界和生成配置匹配的缓存，会在后台初始化时迁移；同盘直接移动目录，跨盘完成临时目录复制后再发布，跨盘原文件保留。新目录一旦存在便以新目录为准，不再合并旧目录，避免脏列删除的数据复活。更早版本的独立 `.smp` 预测样本仍不迁移。

真实列到达或脏列通知都会清理该区块全部 256 列样本，失效所有相关 LOD 网格文件（包括未载入的父层与边缘采样）以及读域覆盖此区块的相邻地表生成源。旧任务在失效后不能回写过期磁盘结果，采集中收到更新时只提交最新完整列。现有真实列仍优先遮挡预测植被。资源包更新会重建外观，世界生成身份或缓存格式变化则使用新的缓存。debug 的 `surface` 统计包含 `disk={hits,misses,writes,errors}`；正常模式不定时刷缓存日志。

## Xaero 世界地图加载

客户端安装 [Xaero's World Map](https://modrinth.com/mod/xaeros-world-map) 后，VSS 会把服务端发送的远景列写入世界地图，使地图覆盖范围不再受原版渲染距离限制。桥接完全在客户端完成，不修改协议，也不要求安装 Voxy；原版已经加载的近处区块仍由 Xaero 自己绘制。

该功能默认开启，可在 VSS 的 Embeddium/Sodium 设置页控制，需要临时关闭地图写入时执行 `/vssclient xaero disable`，恢复时执行 `/vssclient xaero enable`。执行 `/vssclient xaero reload` 会清除当前服务器所有维度的客户端列存在性记录并自动重新请求已有 LOD 缓存。

Xaero `1.40.x`、`1.41.x`、`1.42.x`、`1.43.x`、`1.44.x` 和 `1.45.0` 已适配；低于 `1.40.0` 的版本不受支持，高于 `1.45.0` 的版本尚未验证。反射接口不兼容时，Xaero 桥接会自动停用，不影响 VSS/Voxy 的 LOD 功能。

## 远处玩家与兼容模组

VSS 可在原版实体跟踪范围外显示简化的玩家和载具，并同步原版装备、皮肤部件、披风开关以及部分模组附加数据。
远处玩家的位置和视角使用低频更新以节省带宽，因此不会像近处原版实体一样逐 tick 平滑同步。

## 配置

- 服务端：`config/vss-server-config.json`
- 客户端：`config/vss-client-config.json`
- 本地服务器可通过 Voxy/Sodium 设置页调整；专用服务器可编辑 JSON 或使用 `/vss` 命令。

### 服务端默认值

| 配置 | 默认值 | 允许上限 |
| --- | ---: | ---: |
| LOD 距离 | `128` 区块 | `8192` |
| 全服总带宽 | `8 Mbps` | `100 Mbps` |
| 发送队列数量 | `1024` 列 | `8192` |
| 发送队列内存 | `16 MiB` | `128 MiB` |
| 磁盘读取线程 | `4` | `16` |
| 近/中/远/超远请求 | `0 / 8 / 4 / 2` 每 tick | 手动值各 `256` |
| 单玩家生成并发 | `4` | `128` |
| 全服生成并发 | `32` | `1024` |
| 脏列广播间隔 | `10` tick | `600` tick |

近距离请求的 `0` 是特殊值，表示不限速并可使用单个协议批次的 `1024` 请求容量。手动填写时四档最高均为 `256/tick`；中、远、超远三档的 `0` 表示关闭该档请求。

全服总带宽由所有玩家共享。发送器逐玩家轮询；没有待发数据、被距离分档限制或设置了较低个人下载上限的玩家不会占用额度，剩余带宽会自动供其他玩家使用。单人游戏可独占完整的 `8 Mbps`。

### 客户端默认值

| 配置 | 默认值 | 含义 |
| --- | ---: | --- |
| `receiveServerLods` | `true` | 接收服务端 LOD |
| `lodDistanceChunks` | `0` | 自动跟随 Voxy 距离 |
| `desiredBandwidthKbps` | `0` | 不设个人下载上限，仍受全服总带宽限制 |
| `offThreadSectionProcessing` | `true` | 在线程外解码和处理收到的列 |
| `enableXaeroMapBridge` | `true` | 将服务端远景写入 Xaero 世界地图 |
| `enablePrediction` | `true` | 使用 VSS 自己的种子驱动远处预测 |
| `predictionDistanceBlocks` | `8192` | 独立预测远景范围，单位方块，独立于 VSS |
| `predictionSurfaceDistanceBlocks` | `768` | 实际近处地形外的地表细化宽度，范围 128–2048 方块 |
| `predictionTrees` | `true` | 近处及望远镜目标的树木、草等植被 |
| `predictionStructures` | `true` | 近处及望远镜目标的地表建筑 |
| `rememberTerrain` | `true` | 本地压缩保存预测地形与地表内容，允许释放闲置细节 |

进入世界后可
执行 `/vssclient stats`，其中 `profile` 表示世界生成快照是否解码完成，
`tiles`/`pending`/`failed` 表示预测 tile 队列状态，`rendered` 表示最近的
渲染阶段实际提交了多少预测网格单元；`render=...` 是累计的渲染诊断，
其中 `packedQuads` 是 greedy 顶面/水面四边形数量，`triangleVertices` 是
墙体与 feature 补充通道的顶点数量，`depthBoundCulled`/`occlusionCulled`
表示被远景边界和四帧遮挡迟滞过滤的 tile。

`surface` 诊断包含地表候选/完成网格数、基础远景与近处地形是否就绪、实际生成块数、进入网格的块数，以及跳过的 feature/结构数。自动日志受 `debugLogging` 控制；也可通过 `/vssclient stats` 主动查询。Voxy/Sodium 设置页提供植被开关、地表建筑开关与地表内容范围。

服务端的 `enablePredictionSync` 控制是否发送 `worldgen_profile`。客户端可用 `/vssclient stats` 查看 `profile`、`tiles`、`pending` 和当前 exact/预测会话状态。

### FreeTerraForged 预测适配

已接入 [ETcodehome/FreeTerraForged](https://github.com/ETcodehome/FreeTerraForged) 发布版 `0.0.6005-neoforge-1.21.1` 的 Java 生成路径。两端需使用同次构建的 VSS，并安装对应 FreeTerraForged。服务器同步实际预设与噪声注册表，客户端按维度设置其初始化上下文。采样间距至少 32 方块的粗模使用模组自己的点估算；更细地形读取逐方块侵蚀缓存，继续沿用近处/望远镜优先调度。河流、湖泊与湿地水面使用模组的水文高度函数；预测专用地形缓存会在工作线程结束后释放。

FreeTerraForged 的侵蚀、平滑、坡度、海滩检测和海滩修正已由预测专用挂钩批量交给 Rust，普通服务器生成器不注册该挂钩。Perlin/Perlin2、Simplex/Simplex2、白噪声、基础组合噪声、密度量化和线性样条也已有原生实现。大陆、河网、气候、部分噪声及其地表/装饰扩展仍使用 Java，完整 FreeTerraForged 生成器尚未全部迁入 Rust。已用发布 JAR 验证数值，整合包中的 Mixin 转换及最终画面仍需实机验证。瀑布流动、河岸补块等区块后处理不保证逐方块复现；已有真实列仍由 Voxy 覆盖。此适配不代表原始 RTF 的所有分支、任意地形模组叠加或 TerraBlender 扩展都已兼容。迁移边界见 `tools/rust/MOD_MIGRATION_2026-09-09.md`。

### 地形模组版本与史诗地形

本项目 JAR 的游戏版本仍为 **Minecraft 1.21.1 / NeoForge**。上游地形模组提供其他 Minecraft 版本的下载，不表示本 JAR 可以跨游戏版本使用。当前验证目标：

| 地形模组 | 1.21.1 验证版本 | 预测路径与边界 |
| --- | --- | --- |
| Tectonic | `3.0.26-neoforge-21.1`，配合 Lithostitched `1.8.0+beta6-neoforge-21.1` | 按实际运行图及自定义注册表重建；未验证所有旧版，不能声称整个 3.x 系列均支持 |
| FreeTerraForged | `0.0.6005-neoforge-1.21.1` | Java 生成上下文加 Rust 瓦片过滤；基础噪声和密度算子部分原生化。`0.0.6001`、`0.0.6002`、`0.0.6003R2`、`0.0.6004R1` 缺少当前适配必需的 `RTFWorldGenContext` 接口，不在当前支持范围 |
| [ETN 史诗地形](https://www.mcmod.cn/class/15808.html) / Epic Terrain | 发布名 `v0.1.4b-Beta-1.20.5~1.21.1`，文件 `epicterrain-0.1.4.jar` | Rust 重建密度缓存访问顺序、基础柱与扩展高度；已与发布数据包的 Minecraft NoiseChunk 结果对照 |
| Epic Terrain Compatible | `1.0.3+mod`，文件 `epic-terrain_compatible-1.0.3.jar` | 三维 `cache_2d`、插值切片和单元格批量填充已在 Rust 实现，并验证基础柱液体结果。此处不包含仅标注 Forge 的 `1.0.3b-1.21.1` |

Rust 样条现在保留数据包内重复/未排序控制点，并按 Minecraft `CubicSpline` 的二分查找求值；不会擅自排序或合并。对于随高度变化的 `cache_2d`，原生图构建返回明确的不支持原因，客户端保留已经解码的 Minecraft Java 采样器。诊断仍受 debug 模式控制。

这些是各自生成配置的适配结果，不代表 Tectonic、FreeTerraForged 与史诗地形可以同时叠加生成；它们之间的数据包覆盖、TerraBlender 扩展和特定整合包的光影仍需分别验证。复现命令和采样验证见 `tools/prediction/EPIC_TERRAIN_2026-09-09.md`。

## 缓存与排错

持久化缓存位于：

```text
<世界>/data/vss-column-cache/<维度>/<regionX>_<regionZ>/
```

`.vcl` 保存列数据，`index.vci` 保存 Region 索引。Biome 快照修复会自动提高缓存 schema，升级后旧格式列会被视为无效并重新读取或生成；不需要手动清理。需要手动清空缓存时先关闭服务器，再删除 `vss-column-cache`。

排错建议：

- 先执行 `/vss stats`、`/vss generation stats` 查看请求、队列和生成状态。
- 确认两端 VSS 版本与协议一致，并确认客户端已加载 Voxy。
- LOD 到达很慢时检查全服总带宽、在线玩家数量和客户端个人下载上限；默认 `8 Mbps` 约等于 `1 MB/s`，由活跃玩家动态共享。
- 待发送数量持续增长时检查发送队列、客户端期望带宽和网络拥塞。
- 生成排队但吞吐低时检查每 tick 启动限制，而不只是提高全服并发。
